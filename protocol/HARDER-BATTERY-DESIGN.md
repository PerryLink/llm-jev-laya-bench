# 更难的电池设计（目标项 2）——用于消除 LLM 上限效应

> 作者：主控 · 状态：**设计稿**（未实现）
> 起因：LLM 已**两次触顶**——P19（n=1100 全对，四档 effort 亦全对）与 P21。
> **触顶意味着该语料无法测量任何关于 LLM 的差异**，而互补性分析需要 LLM **会犯错**。**换条目无用，必须换任务类型。**

---

## 1. 为什么现有语料必然触顶（诊断）

现有条目全部属于**「模板匹配 + 单跳核验」**：

| 特征 | 现有语料 | 后果 |
|---|---|---|
| 答案位置 | state 内**明确陈述**（带 `(current)` 标记） | 一次查找即可 |
| 推理深度 | **单跳** | 无中间状态 |
| 干扰项 | 量级分离的数值 | 不需排除，只需匹配 |
| 需要的操作 | 字符串/数值匹配 | 与 LLM 的强项完全重合 |

→ **Laya 与 LLM 的能力差距在此类任务上最大**（0.567 vs 1.000），但**正因为 LLM 做到 1.000，无法测量其错误结构**。
→ **互补性要求两个判定器「错在不同处」；若一方不错，Δ_catch 不可定义。**

---

## 2. 目标：让 LLM 出错，同时**保持真值可程序化计算**

**核心约束**（不可妥协）：

1. **真值必须由构造计算**，不能由模型或人工产出（否则重蹈基准循环性）；
2. **必须可程序化验证**，且**验证成本为零**；
3. **对 Laya 仍须可回答**（否则测的是窗口而非能力）→ **每个子步骤的 state 必须 ≤450 token**；
4. **难度必须来自推理结构，而不是来自模糊表述** —— 否则测的是「解读题目的能力」。

---

## 3. 建议的任务族：**多跳链式核验（CHAIN-AUDIT）**

### 3.1 结构

state 是一段**审计轨迹**，包含：

- **K 个操作行**（程序生成），每行形如 `step i: value := f_i(value)`，其中 `f_i ∈ {+d, −d, ×2, ÷2}`；
- **若干「作废行」**：形如 `step j: SUPERSEDED — do not apply`，用于制造**必须跳过的干扰**；
- **一行基准断言**：`baseline: value = V₀`（或由前序步骤推出）；
- **问题**：`what is the value after the last non-superseded step?`

**真值 = 程序按其自身记录逐步计算的结果**，与任何模型无关。

### 3.2 为什么这会让 LLM 出错

| 机制 | 说明 |
|---|---|
| **多跳** | 需要维持中间值，任一步出错即终局错（**误差复合**） |
| **作废行** | 必须**注意到某行被标记为无效** —— 正是本论文主线中判定器失效的同一位置 |
| **数值精度** | 除 2 会产生小数；乘 2 放大误差 |
| **链长可调** | K 是**难度旋钮**，可扫描（与 horizon 概念同构但可精确控制） |

**关键**：这些机制**不依赖语义模糊**，所以「题目读不懂」与「推理失败」可分离。

### 3.3 难度旋钮

| 旋钮 | 取值 | 预期效应 |
|---|---|---|
| **链长 K** | 2 / 4 / 8 / 16 | 误差复合；LLM 应开始出错 |
| **作废行比例** | 0 / 0.25 / 0.5 | 测「注意到缺席/无效」的能力 |
| **数值是否整除** | 全整除 / 混合 | 测精度处理 |

→ **2×3×2 = 12 个格子**，每格 ≥30 条 → **≥360 条**，且**每格可报准确率与 Wilson 区间**。

### 3.4 条目生成（全部程序化）

```
for each cell:
    V0 ← rng.choice([128, 256, 512, 1024])
    steps ← []
    for i in 1..K:
        op ← rng.choice(["+d", "-d", "*2", "/2"])
        superseded ← rng.random() < superseded_rate
        steps.append((i, op, superseded))
    truth ← simulate(V0, steps)          # 程序计算，权威
    state ← render(V0, steps)            # ≤450 token，故需控制 d 的位数与行格式
    question ← "what is the value after the last non-superseded step?"
    criteria ← {opaque keys: distinct plausible values, 含 truth}
```

**验证器**：`assert truth == simulate(V0, steps)`，并**断言「若忽略作废行则答案不同」**（保证作废行是有效的，而非装饰）。
→ **这正是 P5 的「证书」机制在本族的实现**：**带作废行信息可推导、去之则不可推导**。

---

## 4. 必须同时跑的对照

| 对照 | 目的 |
|---|---|
| **恒等基线** | 「不作废任何行」下的答案 —— 若与真值相同，则作废行无效，条目作废 |
| **LLM 非思考 vs max** | 检查「思考是否买来多跳能力」（P21 因触顶未能回答此问题） |
| **Laya 单臂** | 它是否具备任何多跳能力（预期接近 0，但有信息） |
| **Jev** | 可选；其 `check` 原语可对每一步单独判定，作为「分解式」对照 |

---

## 5. 预声明判读

| 观测 | 结论 |
|---|---|
| LLM 准确率 ≥0.95 且各档均如此 | **仍触顶** → 该模型在此类任务上确实强，**论文不再尝试制造它的错误**，互补性主张**永久放弃**并如实写明 |
| LLM 准确率随 K 明显下降（如 K=16 时 <0.7） | **上限解除** → **Δ_catch 可测**，且**误差复合本身成为一条新结果**（与 horizon 同构） |
| LLM 出错但 Laya 也全错 | **互补性仍不成立**，但**「两者失效于同一处」是更强的否证** |

## 6. 与已有结论的关系

- **不改变** Result A（成本/延迟）：与本电池无关；
- **可能加深** Result C：**误差复合 vs 能力塌缩**是同一条主线的两个面向；
- **唯一可能挽救** 架构主张的实验 —— 但**前提是 LLM 真的出错**，否则如 §5 第一行所述应**永久放弃**该主张。

---

## 7. 成本估算

- **生成**：纯程序化，**零 API 成本**；
- **LLM**：360 条 × 2 档（none/max）= **720 次调用**，约 **$0.036**（按 $0.00005/次）；
- **Laya**：360 次调用，本机约 **14 秒**算力；
- **总计约 4 美分、机器时间 < 10 分钟。**

→ **这是本项目最便宜的一个决定性实验。**

---

## 8. 风险

1. **程序化行格式可能过于规整**，使 LLM 用「模式补全」而非逐个应用 → **须加「行序打乱」与「无关行」对照**；
2. **除 2 引入小数**，需固定格式以免出现「格式不确定」而非「推理失败」→ 建议**先用全整除子集**；
3. **Laya 可能因行格式而非链长失败** —— 需**逐 K 校准**（K=2 时应接近其单跳表现）。
