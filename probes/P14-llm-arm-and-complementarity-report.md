## 1. LLM 臂结果

| 指标 | 值 |
|---|---|
| **强制选择（A1，JSON 约束）准确率** | **1.00（48/48）** |
| 自由散文（A0）准确率 | **0.958（46/48）** |
| 强制选择单次成本（低谷） | **$0.0000484** |
| 强制选择 p50 延迟 | **671 ms** |
| 最大延迟 | 1,008 ms |
| 解析失败 | **0** |
| 自报概率 | 大量 **1.0**（见 §4） |

### 1.1 我自己的一个测量错误（已修，且值得留痕）

第一版（n=12）跑出 **散文 0.50、强制选择 1.00**，看起来正是 R16 警告的「散文臂是稻草人」。
**但那是我的解析器错了。** 散文回答确实答对了，只是常常**只给数值不给选项键**（如「the answer is **47 minutes**」），而我的提取器**先尝试单字母分支**，把 "47" 里的 "4" 当成选项索引，返回了**错误的键**。

修正为「最具体优先」的顺序后（JSON → 字面键 → 键名出现在散文 → **选项值文本逐字出现** → 单字母），散文准确率从 **0.50 升到 0.958**。

→ **教训与论文相关性**：**「散文臂表现差」这个结论，可以由解析器的缺陷凭空制造出来。** 任何声称「结构化输出优于散文」的实验，**必须先证明其抽取器在散文上不掉分**。本条已并入协议强制项。

## 2. 跨物种错误互补性：**本任务类别上不存在互补**

V5 把「跨物种错误互补性」定为论文**唯一能救新意**的实验，因为既有的所有级联（FrugalGPT / RouteLLM / AutoMix / learning-to-defer）都是**同族**（LLM 判 LLM）。它问的是：

> **一个不同物种的判定器，是否会在同一批条目上失败于不同的地方？**

**48 个配对条目的结果**：

| 指标 | 值 |
|---|---|
| LLM 准确率（配对集上） | **1.00** |
| Laya 准确率（配对集上） | **0.458** |
| `P(Laya 对 \| LLM 错)` | **未定义——LLM 一次都没错** |
| `P(Laya 对 \| LLM 对)` | 0.458 |
| **Δ_catch** | **未定义** |
| **κ 一致性** | **0.0** |

**混淆矩阵**：两者都对 **22**，**仅 LLM 对 26**，仅 Laya 对 **0**，两者都错 **0**。

### 2.1 结论（直说）

**在这批条目上，Laya 从未捕获到任何 LLM 漏掉的东西（typed_only_correct = 0）。**

→ **本任务类别上不存在互补性。** LLM 严格占优：它在 26 个条目上对了而 Laya 错了，**没有任何一个条目是反过来的**。
→ **V5 寄望的那个「救新意」的实验，在第一个真正执行它的任务类别上给出了否定的答案。**

### 2.2 散文臂的版本（给出了数字，但同样弱）

| 指标 | 值 |
|---|---|
| LLM 准确率 | 0.958 |
| `P(Laya 对 \| LLM 错)` | **0.50**（n=2） |
| `P(Laya 对 \| LLM 对)` | 0.457 |
| **Δ_catch** | **+0.043** |
| κ | **−0.006** |

→ Δ_catch 虽为正，但**建立在 LLM 仅 2 次失败之上**，且 κ ≈ 0 说明**两者的一致性与随机无异**。**n=2 不足以支撑任何互补性主张。**

## 3. 这个负结果意味着什么（以及不意味着什么）

**意味着**：
- 在 **「state 明确陈述 + 需要定位权威来源」** 这一任务类别上，**前沿 LLM 是天花板（1.00），小判定器（0.458）在平均意义上明显更弱，且不提供增量覆盖**。
- 「用一个廉价的异种判定器做第一层、只在不确定时升级」这个架构，**在本任务类别上没有任何收益**——因为第一层没有捕获任何第二层漏掉的东西，它只是单纯更差。

**不意味着**：
- **不意味着整个组合架构无价值。** 互补性是否存在**必然依赖任务类别**。本电池是**模板匹配/权威定位**类；而 Laya 在**小候选集语义判别**上曾达 **0.867**（P7 第二层，+0.53 超出随机），那才是它可能真正有增量的区制。**互补性必须在 Laya 的相对强项区制上测，而不是在它的弱项区制上测。**
- **不意味着论文失败。** 论文的中心主张从来不是「Laya 更准」，而是「**成本不是约束**」与「**仪器自报不可信**」——两者都由 P1/P3/R12/P13 的证据独立支撑，**且本轮 LLM 实测进一步巩固了前者**（见 §4）。

## 4. 本轮对中心主张的**正面**贡献

**「成本不是约束」现在有三方实测支撑，不再是价格算术**：

| 判定器 | 单次成本 | 单次延迟 | 来源 |
|---|---|---|---|
| **LLM**（结构化判定） | **$0.0000484** | p50 **671 ms** | **本轮实测** |
| **Jev**（openrouter） | **$0.0000142–0.0000991** | p50 **1,380 ms** | P12/P13 实测 |
| **Laya**（本地 cuda） | 边际 ≈ $0（自托管算力） | **37.4 ms** | P3/P13 实测 |

→ **三者都在十万分之一美元量级**，而设计里只有 120 个检查点/运行。**「钱不是约束」这个结论现在是实测的，不是推算的。**
→ 而**延迟差三个数量级**（37 ms / 671 ms / 1,380 ms），**且方向对本地判定器有利**。这与 R3/R9 的裁定一致：**约束是延迟与窗口，不是美元。**

**另一条**：LLM 在 48 个条目上**全部返回接近或等于 1.0 的自报概率且全部正确**。
→ 与 Laya 的 confidence 解耦（P1：错答时 confidence 1.0000）**形成对照**：**同一批条目上，一个判定器的满置信度是对的，另一个的满置信度是错的**。这是「仪器自报不可信」主线的一个新的、有力的对照点。

## 5. 限制

1. **LLM 为上限效应**：强制选择 48/48 = 1.00，**该电池对 LLM 没有区分度**（无天花板以上空间）。**Δ_catch 因此不可定义**，这是设计问题而非测量问题。
2. **Laya 的 P9b 行是在顺序去相关条件下测的**（`presence == "full"` 共 48 行），**按索引配对**；`build()` 的种子为 `"20260922:{idx}"`，两脚本一致，故条目对应关系成立——但**这是靠种子复现而非共享文件**，属于脆弱耦合，应改为共享条目文件。
3. **`thinking: disabled`**：选择非思考模式是为了使采样臂成为可能（API 文档明确思考模式下 `temperature` 无效）。**但思考模式下的表现未测**，且 V3 实测 reasoning token 计入输出价 → **思考模式的成本可能高一个数量级**。
4. **单次采样、无重试、单一模型**（只测了 `deepseek-flash`，未测 `deepseek-v4-pro`）。
5. **未测**：logprobs 读数（R16 要求的「logit 风格」梯级虽已实现于 `deepseek_client.logit`，本轮未运行）、k 次自洽采样臂、P1–P4 提示词变体带。
