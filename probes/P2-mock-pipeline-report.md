## 2. 本轮最重要的发现：**位置偏差压低了真值 5 倍**

同一批条目、同一模板，**只改选项顺序**：

| 配置 | Laya 准确率 |
|---|---|
| 选项顺序 = 渲染顺序 | **0.125** |
| 选项顺序 = 每项确定性打乱 | **0.625** |

**诊断过程**：先看到 Laya 在 8 行里选了 6 次 `i01`，而 `i01` 恰好总是**第一个列出的数值**（因为 criteria 沿用了 state 的渲染顺序）。
→ **这不是阅读能力，是位置偏好。** 而且它**双向**欺骗：
- 当权威值恰好排在首位 → 看起来 1.00；
- 当它不在首位 → 看起来 0.125。

**裁定**：**选项顺序必须与正确性去相关**，已实现为每项确定性打乱，并记录 `meta.truth_pos_in_criteria` 以便位置效应仍可分析。

## 3. ⚠️ 因此 P5c 的 1.00 结论**不可信**，必须撤回

P5c 报告了「显式 `(current)` 标记：带载体 **1.00**、去载体 0.00」。**现在必须撤回那个 1.00**：

- P5c 的 criteria 顺序 = 渲染顺序，**且未打乱**；
- 与 P2 第一次运行完全同构（那一次得 0.125）；
- **P5c 的 1.00 极可能同样是位置伪影**——它只是在那一批条目里，权威值恰好落在选项首位。

**这是本项目第三次由「两臂/对照检查」逮住我方自己的错误**：
1. P5 v1：数值选项不可区分 → 0.25（动作作废）；
2. P5b：T4 题目根本不含所问信息（不可回答伪装成能力）；
3. **P5c：位置偏差伪装成能力。**

→ **协议强制项（新增）**：
> **任何分类类评测，选项顺序必须与正确性去相关，并报告位置分布。** 未去相关的准确率数字一律不得进入论文，无论其高低。

## 4. 修订后的模板结论（待重测）

在**顺序去相关**后，显式标记模板的实测为 **0.625**（5 项，n=8）。
→ **它不再是「1.00 可用」，而是「~0.6，需扩大样本确认」。**
→ 按 P5c 预声明的验收规则（`≥0.80` 且去载体 `≤0.40`），**当前不满足**。
→ **但这次不满足的原因与之前不同**：之前是条目构造错误，现在是**真实的能力水平不足**。二者必须分开报告。

**待办**：把显式模板扩到 **≥30 项**并用去相关顺序重测，同时跑去载体臂，才能判定它能否进主电池。

## 6. 限制

1. **n=8**（4 个 horizon 层 × 2 项）。0.625 的步长是 0.125，**不是精确估计**。
2. 单一 checkpoint（english）、单一设备（cuda / RTX 5060 Laptop sm_120）、单一模板。
3. **去载体臂本轮未跑**（P2 管线只跑带载体），故必要性尚未在去相关顺序下复验。
4. P5c 的原始 JSON 保留未改，其 1.00 数字**保留原样以留痕**，但**已在报告中标注为不可信**。
