# P23 — LLM logprobs：内部概率与口头概率**一致**（口头数字不是方法伪影）

> 实测：2026-09-22 · `deepseek-flash` · 非思考模式 · `logprobs=True, top_logprobs=20` · 60 个配对条目
> 原始数据：`results\P23-llm-logprobs.json` · 复现：`src\items\p23_llm_logprobs.py`

---

## 0. 为什么测这个

R16 要求四条 LLM 概率读数，并指出 **logit 路线是真实的**（官方文档确认支持 `logprobs`/`top_logprobs`）。
**本项目此前所有 LLM 概率都是「口头」的**——直接问模型要一个数字。

文献一致报告**口头置信度与内部概率存在差距，且口头偏过度自信**。因此必须回答：

> **本文的 LLM 校准数字（n=1100）是模型的性质，还是「索要方式」的伪影？**

**方法**：模型以**单个字母**作答（故 `top_logprobs` 在该位置是一个**选项字母上的分布**），同一批条目（复用 P19 的模板）再用强制选择 JSON 形式问一遍。

---

## 1. 结果：两者一致

| 指标 | 值 |
|---|---|
| n（配对） | **60** |
| verbal 准确率 | **1.0000** |
| logit 准确率 | **1.0000** |
| **平均口头置信度（对所选项）** | **0.9967** |
| **平均 logit 众数概率** | **1.0000** |
| **平均带符号差（口头 − logit）** | **−0.0033** |
| 平均绝对差 | **0.0033** |
| logit 解析失败 | **0** |

**原始分布形态**（一例）：

| token | logprob | exp(logprob) |
|---|---|---|
| **'B'**（所选） | −4.3e−06 | **1.000** |
| 'A' | −12.68 | 3.1e−06 |
| 'C' | −16.34 | 8.0e−08 |

→ **内部分布确实是极端的**，与口头声明的 ~1.0 **一致**。

**裁定**：
> **两个读数在 0.0033 内一致 → 本文的口头概率数字不是索要方式的伪影。**
> 这与「LLM 口头置信度普遍过度自信」的文献形成**对照**，可能因为**本语料对该模型触顶**（准确率 1.0000），故不存在可供过度自信的错答。

## 2. 我在本轮绕过的一个度量陷阱（值得留痕）

首轮汇总给出 `mean_p_true_corpus_level`：**verbal 0.4023 vs logit 0.4000**，看起来「一致」。
**但那是错的度量**：语料是 **60% 真 / 40% 假** 的构造，而 P(true) 在语料层面平均**必然趋于基率（0.40）**，**与模型行为无关**。

→ **正确的可比量是「对所答选项的置信度」**（口头：`prob`；内部：字母分布的众数概率），因为**两者问的是同一件事**。
→ 修正后：**0.9967 vs 1.0000**，差 −0.0033。

**教训**：**一个「看起来一致」的结果可能只是基率**。凡比较两个概率读数，必须先确认**两者测的是同一个量**——这是本项目第六次同类错误的变体（前五次见 §4.4），所幸在汇总层被数值形态发现（0.4023 ≈ 0.40 过于整齐）。

## 4. 限制

1. **n=60**，且**准确率两臂均为 1.0000（触顶）** → **无法评估「错答时两个读数是否仍一致」**，而那恰是过度自信最可能出现的位置；
2. **只测了一个模型与一个配置**（非思考模式）；
3. `top_logprobs=20` 只返回该位置最可能的 20 个 token；**已被归一化到出现的选项字母之间**，故是**选项间的相对分布**，不是完整词表分布；
4. **未测**：思考模式下的 logprobs、温度 >0 时的分布变化、k 次自洽采样（R16 第四级）。
