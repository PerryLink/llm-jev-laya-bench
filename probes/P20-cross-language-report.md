# P20 — 跨语言行为（**不是**路由测试，前提已更正）：英文 checkpoint 对非英文文本不区分真伪

> **⚠️ 探针缺陷（独立审计发现，报告数字前必读）**：假条目（`false_item`）的判据写的是**另一个值**。
> `p20_language_misrouting.py:89` 在真/假两个条目上复用 `crit = {"true": f"yes, {v}", "false": f"no, not {v}"}`，而 `q_false` 问的是 **`{w}`**（9700）。16 次调用中 **8 次**的判据与题面不是同一个值。
> ⇒ 假条目的 P(true) = 0.407–0.912 **至少部分由此造成**。
> ⇒ **本报告的定性结论仍然成立**（该缺陷在**各语言上恒定**，故「英文 0.407 vs 非英文 0.912」的**差异**不受影响），但**绝对水平不可引用**，且修复需重跑。

## 0. 我的前提错了，而且错得干净

本脚本原本要测**路由器的文档化缺陷**（只识别 en/fr/de/es/pt/it/nl，其余拉丁字母语言被送给英文模型并自信作答）。

**探针证明这件事无法经此接口测量**：

```
routing: {"model": "english", "reason": "explicit model selection"}
```

**对每一种输入都如此——包括俄语（西里尔）与印地语（天城文）**；**而且在不传 `--model` 启动时也一样**。
→ **HTTP sidecar 只预载单一 checkpoint，从不做语言检测。** 检测-分派逻辑在 DSH 插件使用的 Python `Router` 里，而本项目的客户端**直连 sidecar，绕过了它**。

→ **所以原脚本的组标签（「被检测 / 未被检测」）是假的**：**没有任何一组被检测过，因为根本没有检测在发生。** 已改标为**文字系统分组**。
→ **「misrouting cost measured」这个初版判据是错的**，已删除。

## 1. 数据实际显示什么

| 文字系统分组 | n | 准确率 | 真条目的平均 P(true) | **假条目的平均 P(true)** | 恒答「真」的基线 |
|---|---|---|---|---|---|
| **英文原生**（en） | 2 | **1.000** | 0.975 | **0.407** | 0.5 |
| **其他拉丁文字**（de, es, pl, tr, vi, id） | 12 | **0.500** | 0.917 | **0.747** | 0.5 |
| **非拉丁文字**（ru） | 2 | **0.500** | 0.968 | **0.912** | 0.5 |

**判据：是否优于「恒答真」基线** → 英文原生 **是**；其他拉丁 **否**；非拉丁 **否**。

**关键量是「假条目的 P(true)」**：

- 英文：**0.407**（低于 0.5 → **正确否定**）
- 其他拉丁：**0.747**（高于 0.5 → **错误肯定**）
- 非拉丁：**0.912**（**强烈错误肯定**）

→ **英文 checkpoint 在英文上完美区分真假；一旦文本不是英文，它就不再区分，而是倾向于肯定主张。**

## 2. 这与本论文其余发现的关系

这不是一个新现象，而是**同一条失效模式的第三个实例**：

| 实例 | 失效描述 | 出处 |
|---|---|---|
| 静默截断 | **没注意到输入被截掉了** | P3 |
| `no_support` | **没注意到证据不存在**（n=220，平均 P(true)=0.564） | P19 |
| **非英文文本** | **没注意到自己读的不是英文**，一律倾向肯定 | P20 |

→ **共同形态：该判定器在「必须注意到某个缺席或某种不匹配」的场合失效，而在「答案被明确陈述」的场合近乎完美。**
→ 而在这三种情况下，**它的自报置信度都不低**（非拉丁文字下假条目的平均 P(true) 高达 0.912）。

**这条统一形态，比三个孤立的现象更有力**，建议作为 Result C 的组织线索。

## 3. 对方法章节的贡献（重要，且是正面的）

**本项目的全部测量都在同一个、从不路由的接口上取得** —— 这消除了一整类关于「哪条路径服务了这次调用」的不确定性。

但同时暴露一条**必须写进论文的限定**：

> **本项目的全部 Laya 测量都是 `english` checkpoint 在显式选择下的行为，不含语言检测与分派。**
> 因此论文**不得**对 DSH 插件所用的 Python `Router` 作任何陈述——那是一个**本项目从未触达的组件**。

→ 这修正了 R2/D3 中「多语误路由」被列为**已知缺陷**的定位：**它是插件层的缺陷，不是本项目所测接口的缺陷**，且**本项目未测它**。

---

## 4. 限制（严格）

1. **n 极小**：英文与俄语各只有 **2 条**；其他拉丁文字共 12 条。**一个条目就能把一个组移动 0.13–0.50。**
   → **只有定性形态可报告，不作任何逐语言主张。**
2. **每种语言只有单一模板**，且翻译由我撰写 → **这不是翻译质量测量**。
3. **未测**：给 `lang` 参数显式指定（sidecar 是否支持未验证）、多语 checkpoint、插件层的真实 `Router`。
4. **俄语组 n=2 却给出 0.912 的假条目 P(true)** —— 方向清楚，但**样本不足以定论**。
