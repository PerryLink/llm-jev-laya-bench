# P3 — 逐 checkpoint 钳位标定：`truncated` 标志在两个方向上都是错的

> 实测：2026-09-22 · **Laya 0.2.1 · english / multilingual / typed-decisions · cuda · Path A（HTTP :8787）**
> 原始数据：`results\P3-clamp-calibration.json` · 复现：`src\instrument\p3_clamp_calibration.py`
> 方法：`DECOY + filler + CORRECTION`（更正置于**尾部**），2 选项 noul；按字符数扫描，读两个可观测量（`input_tokens_padded` 是否到达上限、`truncated` 是否出现）。
> **不依赖任何 tokenizer 估计** —— 这正是它比「按 token 预算拒绝」更可靠的原因。

---

## 1. 结论（三条，均可直接进论文）

1. **钳位逐 checkpoint 不同**：english **512**、multilingual **1024**、typed-decisions **1024** → **R13 把 512 当全局常量是错的。**
2. **`truncated` 标志在两个方向上都是错的**：english **滞后 111 字符**（静默窗口）；多语与 typed-decisions **提前 3,774–4,773 字符误报**。
3. **输出冻结在所有 checkpoint 上得到确认**，且**冻结起点与真实钳位起点精确对齐** → 尾部确实被丢弃。

---

## 2. 主表

| checkpoint | 实测钳位 | **真实损坏起点** | **`truncated` 首次触发** | **标志误差** | 输出冻结起点 | 冻结与钳位对齐 |
|---|---|---|---|---|---|---|
| **english** | 512 tok | **3,082 字符** | **3,193 字符** | **+111**（滞后＝静默窗口） | 3,193 | ✅ |
| **multilingual** | 1024 tok | **7,966 字符** | **3,193 字符** | **−4,773**（提前误报） | 7,966 | ✅ |
| **typed-decisions** | 1024 tok | **6,967 字符** | **3,193 字符** | **−3,774**（提前误报） | 6,967 | ✅ |

### 2.1 **最锐利的一条：标志在三个 checkpoint 上都在同一点触发**

**三个 checkpoint 的 `truncated` 首次触发字符数完全相同：3,193。**

而它们的**真实钳位差 2×**（512 vs 1024 token）、**真实损坏起点相差 2.6×**（3,082 → 7,966 字符）。

→ **这说明该标志是由一个单一的、基于字符的估计驱动的，而该估计没有随 checkpoint 的 token 预算缩放。**
→ **后果：同一个字符阈值被套用到三个 token 预算不同的模型族上**，于是
- 对**预算最小**的 english：**几乎准确**（滞后 111 字符）；
- 对**预算大 2×** 的两个：**在真正损坏前数千字符就报警**。

### 2.2 双向不诚实

```
english          :  真实损坏 3082 ──[111 字符静默]──> 报警 3193
multilingual     :  报警 3193 ──[4773 字符误报]──> 真实损坏 7966
typed-decisions  :  报警 3193 ──[3774 字符误报]──> 真实损坏 6967
```

→ **一个「有时沉默、有时喊狼来了」的仪器，在任何方向上都不可用作门控。**
→ **这比 R13 提出的「~300 字符静默窗口」更精确、也更严重**：不是「有一个固定宽度的窗口」，而是**同一个标志在两个方向上都不对，且误差量随 checkpoint 变化**。

### 2.3 输出冻结（侧车无关的证据）

钳位生效后，继续增加数千字符**完全不改变分数**：

| checkpoint | 钳位后的分数（逐位相同） | 覆盖字符跨度 |
|---|---|---|
| english | **0.3383** | 3,193 → 15,958 |
| multilingual | **0.0764** | 7,966 → 15,958 |
| typed-decisions | **0.4939** | 6,967 → 15,958 |

→ **`freeze_aligns_with_clamp = True`（三者皆是，容差 200 字符）** → 冻结起点即真实钳位起点，**这是「尾部被丢弃」最干净的证明**，且**不依赖任何估计**。

## 3. 与我先前测量的对齐

| 来源 | english 钳位 | `truncated` 首触 | 静默窗口 |
|---|---|---|---|
| 主控粗扫（R8 §1） | 3,083 字符 | 3,194 字符 | **111 字符** |
| **本次细扫（P3）** | **3,082** | **3,193** | **111 字符** |

→ **两次独立测量完全一致**（1 字符差来自填充取整）。**english 的 111 字符静默窗口是可复现的。**

**对 R8 §1 的更正**：R8 当时报告「多语窗口为 0–111 字符」，那是**粗扫采样不足**导致的错误结论。细扫（本文件）显示多语的标志**提前 4,773 字符误报**，方向与 english **相反**。

---

## 4. 工程侧的一个 bug（已修）

第一版检测器用「相邻两行 `in_pad` 相等」定位钳位起点，**返回的是最后一对相等行**，故把 multilingual 的起点误报为 9,964（实际 7,966）。
→ **已改为「首个 `in_pad` 达到上限的字符数」，并对冻结起点独立检测。** 结论未变，但**数值已更正**。

**记入方法学**：这类「看起来合理的静默错误」正是 V3 的 silent-wrong-number 登记表所针对的。**检测器本身也需要断言**。

## 5. 强制协议修订（并入 R9）

| # | 修订 |
|---|---|
| 1 | **`W` 逐 checkpoint**：english 512、multilingual 1024、typed-decisions 1024。R15 的 `integrity(t)=1[tokens≤W]` 须**每 checkpoint 一个 W**。 |
| 2 | **绝不用 `truncated`/`fits` 作门控**（双向错误）。**门控一律用自算 tokenizer 计数**；标志仅作**描述性报告**。 |
| 3 | **论文中报告「标志误差」这一新指标**（本文件的 `flag_error_chars`），因为它是**仪器诚实性的直接量化**，且**逐 checkpoint 可复现**。 |
| 4 | **截断曲线（M2 平面）必须逐 checkpoint 分别绘制**，不得合并。 |
| 5 | **`freeze_aligns_with_clamp` 作为断言**写入每次运行的前置检查（它是侧车无关的，因此比任何自报字段可信）。 |

## 7. 限制

1. 每个 checkpoint 一个 state 形状、一个问题类型（2 选项 noul）。**其他 shape 下的钳位起点未测。**
2. 字符扫描在细扫区（3,050–3,290）步长 30 字符，故 english 的钳位起点**精度约 ±30 字符**；111 字符的窗口**大于该精度**，结论稳健。
3. `block` 与 `option` 压缩未在本文件覆盖（P1 已记录 N≥15 触发截断）。
4. 本机为 **cuda（RTX 5060 Laptop, sm_120）**；CPU 上的钳位**未测**（钳位若由构建期长度决定则与设备无关，但**未验证**）。
