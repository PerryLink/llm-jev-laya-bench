## 1. P8：低基数异常**不复现，正式撤回**（开工前实测 #7）

同一 state、同一问题，五个基数，每格 8 项，**选项顺序按项打乱**：

| 基数 N | 准确率 | 随机 | 平均 p(true) | 平均 confidence |
|---|---|---|---|---|
| 2 | **1.00** | 0.50 | — | — |
| 5 | **1.00** | 0.20 | 0.874 | 0.670 |
| 8 | **1.00** | 0.125 | 0.968 | 0.908 |
| 12 | **1.00** | 0.083 | **1.000** | **1.000** |

**单调性成立，低端惩罚 = 0.00。**

→ **P1 的「N=2 得 0.33、AUC 0.33」是一个 3 样本格的伪影，撤回。** R13 关于 confidence 在 N=2 偏低的观察也未被复制为准确率劣势。
→ **协议含义**：`noul` 作为 choice 承载的二值项**不在更差的区制里**；原计划中大量二值项是安全的。

## 2. P7：真实 Banking77 上，**扁平 77 路彻底失效，第二层有效，但第一层被分类法质量卡住**

| 指标 | 值 | 随机基线 |
|---|---|---|
| **扁平（77 选项）** | **0.033** | 0.013 |
| **第一层（10 组）** | **0.200** | 0.100 |
| **第二层（条件于正确祖先，≤3 选项）** | **0.867** | 0.333 |
| 端到端 | **0.200** | — |

### 2.1 扁平 77 路 = 失效

**0.033**，是随机的 2.6 倍，但**远低于厂商自报的 0.425**。
→ 与 R13 的实测方向一致（20 选项崩塌），**坐实了「77 类不能单层喂给 choice」**。
→ 与厂商数字的差距**必须如实报告**：其 0.425 是在**77 类、默认 256-token head 预算、并调过 `head_max_len`** 的设定下取得的；本次未调。

### 2.2 第二层是整条链路里唯一有效的一环

**0.867**（随机 0.333）——说明**在小的、语义干净的候选集里，判定器是有真实判别力的**。
→ 这与 P8 的 1.00 互补：**候选集越小越干净，表现越好**，且这一规律在合成与真实数据上同向。

### 2.3 瓶颈完全在第一层，且原因是**分类法质量**，不是机制

**第一层只有 0.200（随机 0.10）**，端到端因此也停在 0.20。

**诊断**：我的分组是**程序化**的（按意图名的 token 集合做贪心平衡凝聚）。它把 `card_arrival` 与 `card_not_working` 归为一组（共享 "card"），而在真实的客服语义里这两者属于**不同的问题域**。
→ **第一层不可分 → 整条链路被封顶。**

**我第一版更糟（0.133）的原因也已定位并修正**：我最初把组选项渲染成「group N: <8 个意图名全列>」，约 40 token。**用一个短句去匹配 8 个拼接的意图，正是层级本要规避的高基数问题**——失败的是**选项文本**，不是层级。改为简洁描述后升到 0.200。

### 2.4 对 MASSIVE / CLINC150 的裁定

| 数据集 | 原计划 | 本结果后的裁定 |
|---|---|---|
| **Banking77（77 类）** | 纳入 | ⚠️ **仅在提供可信的顶层分类时可用**；程序化分组不够 |
| **MASSIVE（60 意图）** | 纳入 | ⚠️ 同上；**但 MASSIVE 自带 domain/scenario 层级**，需核验其顶层是否可分 |
| **CLINC150（150 类）** | 纳入 | ⚠️ 同上，且层数更多 |

**关键约束（新增协议项）**：
> **顶层分类必须是语义上真正可分的，且必须来自数据集自带的层级或人工撰写，不得由标签名的 token 相似度程序化生成。**
> 程序化分组的**可复现性优点**不抵消其**语义无效**。若无法获得可信顶层，则该数据集只能用于**低基数**实验（如 FEVER-gold 的主张核验、NFCorpus 的相关性），不得用于大规模意图分类。

## 3. 本轮浮现的主线：**「模板匹配」与「真解释」之间的鸿沟**

把本会话所有测量按**任务是否需要真正解释**排列，规律非常干净：

| 任务 | 需要什么 | 实测 |
|---|---|---|
| P8：选项是 state 中**明确陈述**的数字 | 模板匹配 | **1.00**（N=2…12 全对）|
| P5c：权威行带 `(current)` 标记 | 模板匹配 | 高（但受位置偏差影响，已修）|
| **P7 第二层：小候选集内的真实意图** | 真解释 | **0.867** |
| **P7 第一层：10 个语义混杂的组** | 真解释 | **0.200** |
| **P7 扁平：77 个真实意图** | 真解释 | **0.033** |
| **P1：20 个候选的相关性判断** | 真解释 | **0.00** |

→ **判定器在「答案被显式写在 state 里、只需匹配」时近乎完美；在「需要语义解释」时跌到接近随机。**
→ 而**它的 confidence 在两种情形下都接近 1.0**（P8 N=12 时 confidence = 1.0000；P1 错答时 confidence = 1.0000）。

**这是论文中心主张的最强形式**：
> **同一个判定器、同样的满置信度，在模板匹配任务上正确率 100%，在解释任务上正确率 3–20%。用户无法从返回的置信度区分这两种情形。**

这比「截断会丢输入」更锐利，且**完全不需要生成电池**——它是判定器本身的属性。

## 4. 限制

1. **P7：n=30**，一项动 0.033。绝对值不可作为精度主张，**方向与两臂对比才是结论**。
2. **污染**：Banking77 是 Laya 的先前集合（厂商发布过其数字），故**不得据此提出任何准确率主张**；本测试只支持**内部配对的结构对比**。
3. **与厂商 0.425 的差距**必须归因于设定差异（未调 `head_max_len`、未做多语路由、测试集子采样），**不可宣称「复现失败」**。
4. **P8：n=8 每格**，一项动 0.125；**只有大的低端惩罚才可解读**——而实测惩罚为 0，故撤回结论成立。
5. 单一 checkpoint（english）、单一设备（cuda / RTX 5060 Laptop sm_120）。
