# R3 — 修正后的经济性模型（对 R15 §6 的纠正，并回答其阻塞问题 #1）

> 作者：主控
> 起因：R15 交付时**未持有**本会话已验证的定价（R2），其成本模型依赖自标的「待核实假设」，而其中两条**与实际不符**。
> 方法：保留 R15 的**全部 token 量假设不变**（生成 1800 in + 900 out/步；LLM 判定 1500 in + 120 out/次；评分单元 1600 in + 250 out/单元），**只替换价格**，因此差额纯粹来自价格错误。
> 证据：R2 §A（一手官方定价）、R2 §C.1（一手集成方定价）。

**R15 的两个头条预算结论均不成立：**
- ✗「gold 评测占 55%、是判定预算的 17 倍，是最大成本项」→ 修正后 gold 评测仅约 **$13**，**不是**主导项。
- ✗「完整设计 $6,000–7,500，缩减 $2,500」→ 按已验证价格，**整个测量计划的边际 API 成本在数百美元量级**，主要成本变成**工程人力**（R15 自己也列了 $1,200–3,000 工程费，那部分不受价格影响）。

**注**：R15 的 $3,802 无法由其自身假设推出——按其假设，69,120 单元 × (1600 in × 0.28 + 250 out × 0.42)/1e6 ≈ **$38**，已接近修正值 $13 而非 $3,802。故该数字疑为 R15 内部计算失误，而非单纯价格偏差。→ **列为核对项**。

## 4. **关键结论：R15 的阻塞问题 #1 有确定答案了**

R15 问：「效率主张是关于**美元**还是关于**延迟/往返**？在 2026 年价格下，钱可能根本不是约束。」

**回答：钱确定不是约束。** 不需要等实测，现有已验证定价即可判定：

| 预算 | 能买到的 LLM 结构化判定次数 | 能买到的 Jev 次数 | 设计中的检查点数 |
|---|---|---|---|
| $0.10 / run | **≈913** | ≈1,587 | 120 |
| $1.00 / run | **≈9,126** | ≈15,873 | 120 |
| $0.10 / run（**0% 缓存命中**，最悲观） | **≈337** | ≈1,587 | 120 |

即便在**零缓存命中**的最悲观情形下，$0.10 也能买到 337 次 LLM 判定——**仍然是 120 个检查点的 2.8 倍**。

→ 因此：
1. **「等预算」在美元轴上没有区分力**：LLM 判定器在每个检查点都做一次结构化判定，成本仅约 **$0.013/run**，任何合理预算都覆盖得起。R15 的 `B_lo=$0.10`/`B_hi=$1.00` 两个档次**都远在饱和点之上**，A5 等预算臂设计因此**几乎无信息量**。
2. **必须改主指标**：R15 建议的「按匹配美元画前沿」会得到一堆重叠曲线。R15 自己的备选措辞才是对的——**主前沿应是「墙钟延迟 / 顺序往返 vs 错误发现提前量」**，美元轴改为**等价性检验（TOST）**并在论文中明确报告「美元轴上无显著差异」。
3. **这对论文是好事**：把「便宜」换成「**不占用顺序往返、且没有硬窗口上限**」，主张更窄但更硬，且避开了「LLM 也能缓存所以也便宜」这一审稿人必然提出的反驳。

## 5. Jev 的成本优势是真实的，但**与「更便宜」无关**

R15 假设 Jev 免费并据此推出「A2 Jev 检查次数无上限」。实际上 Jev 按 $0.042/1M 输入计费。但按 **1500 token/次** 的 state 规模计算，Jev **确实比结构化 LLM 判定更便宜**：

| 缓存命中率 | Jev 单次 | LLM 判定单次 | Jev 更贵的临界输入规模 |
|---|---|---|---|
| 0% | $0.000063 | $0.000297 | **>7,071** token/次 |
| 50% | $0.000063 | $0.000187 | >4,446 token/次 |
| 85% | $0.000063 | $0.000110 | **>2,609** token/次 |
| 95% | $0.000063 | $0.000088 | >2,084 token/次 |

→ **临界点由 context 缓存决定，且落在 2,100–7,100 token 区间**——这恰好是长线任务 state 规模向上增长时会穿过的区间。**所以成本优势不是常数，而是随 horizon 消失的**：state 越长，Jev 越可能反而更贵。
→ 这与 Laya 的窗口问题（R15 §3.5）**指向同一个方向**：两种判定器的经济性都随 horizon 恶化，只是一个**静默截断**、一个**按 token 涨价**。这是论文可以合并成一条主线的重要结构（见 §6）。

## 7. 对 R15 其余部分的影响评估

**不受影响（仍然有效）**：
- §0.2 双平面设计（在线控制 + 离线快照回放）——这是全文最好的设计决策，价格修正反而**加强了它**（回放成本更低）。
- §0.3 冻结序列化器与 `DROPPED: n` 放在**最前**（newest-first 使尾部截断丢掉最旧内容）。
- §0.6 `/ §1.2` A1 结构化自检臂为「不可谈判的守门人」。
- §3.2 错误发现提前量 `T90` 作为主终点。
- §4.6 **B0 良性改写对照**（防止「全部报警」刷分）。
- §5.3 以**任务族内随机化 + 随机化推断**为主推断（簇数少时的正确选择）。
- §5.5 `unknown` 一律作为**删失而非 accept**。
- 全部统计模型与多重比较层级。

**需要修改**：
- §1.6 / §5 等预算臂：**降级为次要分析**，并在论文中报告「美元轴等价」（TOST）。
- §6 全部数字：以上表替换。
- §6.5「成本削减杠杆」：优先级重排——最大杠杆不再是省评测钱，而是**工程人力**。

**需要补充（R15 缺失）**：
- **高基数选项区制未被覆盖**：R15 把 `choice` 固定为 8 选项（有意避开断崖），因此**永远不会触发** Laya 出厂温度 `choice:11+ = 0.1006`（logits ×10，见 R2 §B.2）所导致的「选项越多越自信」。→ 必须增加一个**高基数次级实验**（11–20 选项）专门测该效应，否则「confidence 不可用作门控」这一最重要的部署结论没有直接证据。
- **语言误路由**：R15 §1.4 提到记录 `detected_lang`，但没有把「非 en/fr/de/es/pt/it/nl 的拉丁字母语言被静默路由到英文 checkpoint」作为一个**独立区制**；R15 §6.4 只把它列为「可后补的廉价附加项」。鉴于它同时是 Laya 最强的失效模式与最现实的部署风险，建议提升为**完整区制**。
- **Jev 的计费口径**：Jev 响应含 output token 但输出价为 $0 → 须实测确认**是否真的不计输出费**（若计费，成本模型需重算）。
