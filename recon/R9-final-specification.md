## 1. ★ 主终点更换（V2 的核心裁决）

### 1.1 `T90` 为何双向无效

**(a) 退化**：R15:428 定义 `t_E = min{t ≥ t_0 : verdict ∈ {revise,halt}}`，**不要求该 flag 识别出被注入的故障**。
→ **一个「什么都报警」的判定器取得 `t_E = t_0+1` → 最小 `T90`、最大 `LEAD` → 它赢下 Gate 1。**
→ **B0 拦不住**，因为 B0 只是一列打印值（见 §3.3）。

**(b) 不可估计**：96 run/臂时，观测到的检测 CDF 必须达到 `87/96 = 90.6%`。
→ 若真实窗口内检测率为 **0.80**，`P(T90 有定义) = 0.004`；**0.85 时仅 0.075**。
→ **`T90` 恰好在论文预测表现更差的那些臂上无定义。** 这是致命的：**终点在需要它的地方消失。**

**(c) 三个文件三种定义**：R15:432「与在线调度完全交叉」／R15:452「在匹配判定美元下」／R5:152「在匹配顺序往返下」（而往返次数本身由臂构成，**不可实现**）。
**另**：`F_m(t)=P(t_E≤t)` 索引**绝对步**，而 `t_0 ∈ {10,30,60}` 是随机化的 → `T90` 是**起点混合**的属性，不是臂的属性；
**且** `LEAD = t_final − t_E` 被判定器**自身的 halt 摧毁**（在检测时 halt 的判定器 `LEAD≈0`）。

### 1.2 替换方案（V2 提出，我采纳）

**新主终点：固定 τ\* 的检测概率 `P_detect(τ*)`，配以 oracle 匹配的 flag。**

```
τ* = 预注册的固定滞后（如 τ* = t − t_0 = 3）
被计为「检出」的条件（两者都要）：
  (i) 判定器在 t_0 + τ* 之前或当时发出 revise/halt；
  (ii) 该 flag 经 oracle 判定，确实指向被注入的故障（标的匹配）。
```

**两个估计量，各司其职**：
- **判定器对比（主）**：**快照内配对**。五个判定器在**同一冻结快照**上回放 → 判定器因子是**单元内**的，因此不受臂随机化限制（见 §3.2）。
- **臂 ITT（次）**：把判定器接进控制流后的**部署效果**。

**同时保留 `LEAD` 作为描述性量**，但**不得**在判定器自身会 halt 的臂上解释为「提前量」。

## 2. ★ 双平面（V1/V3/V4/V5 四方同结论的修复）

**主电池在构造上截断率为 0**（R5 §4.2 #5 封顶 450 token；R5 §5.2 固定 token 数；R14 门 G1 拒绝一切会超窗的条目）。
→ 因此 **`token_ratio(t) ≡ 0`、`P(wrong|truncated)` 不可估计**，**标题所声称的现象没有仪器**；**且该选择不对称地保护了 Laya**（V1 的公平性读法）。

### 修复

| 平面 | 门的处置 | 测什么 | 对公平的要求 |
|---|---|---|---|
| **M1 主电池** | **有门**：state 一律在窗内（≤400 token） | 准确率、校准、`P_detect(τ*)`、跨物种互补性、漂移 | **严格公平**：所有判定器同字节 state、同问题、同选项 |
| **M2 增长探针** | **无门，故意越界**：state 300 → 1,500 token | **仪器诚实性**：真实损坏起点 vs `truncated` 告警起点 | **不与 LLM 对比**，只与「仪器自报」对比 |

**M2 的主测量（我实测可用，3 分钟/checkpoint）**：只扫字符数，读两个可观测量（`input_tokens_padded` 是否停住、`truncated` 是否出现），两者之差即**未告警的受损区间**。
**R4 的尾部删除配对探针**作为交叉验证（不依赖 tokenizer 估计）。

### 我实测的 M2 结果（一手，可直接进论文）

| checkpoint | 实测钳位 | `truncated` 首触发 | **未告警受损区间** |
|---|---|---|---|
| english | **512** | 3194 字符（钳位于 3083） | **111 字符** |
| multilingual | **1024** | 3194 字符 | ~0–111 字符 |
| typed-decisions | **1024** | — | — |

→ **`W` 必须逐 checkpoint**（推翻了 R13 把 512 当全局常量的做法）。
→ **english → 0.3594 在 3971→7967 字符间恒定**，独立复现了 R13 的「输出冻结」。

## 3. 其余必修项（按审计来源）

### 3.1 ★ 拨盘失效（V4）

`d = H − 4` **恒等** → 「距污染距离」与「运行位置」**完全共线**；局部块在槽内逐字节相同；**170/300 条（57%）的答案只依赖局部块**。
**修复**：把已有的 `L` vs `L+C` 变体对**提升为主分析**——**全部 300 条各跑两个变体 = 600 配对观测**（每条多一次判定调用），估计量变为 **carrier-lift × log2(H)**，**痕迹是否存在在条目内被操纵**；**增加 `H4-refreshed` 单元**打破共线；**170 条惰性项作为干扰项安慰剂报告**。

### 3.2 ★ 推断单位（V2 + V4）

三处错误：
1. **随机化推断无法检验判定器因子**：五个判定器**都在每个快照上回放** → 判定器因子是**单元内**的，**臂置换动不了它**；且**共享冻结的生成器状态**使单元**非独立** → RI 反而**反保守**。
2. **族数不足**：最小双侧 `p = 2/2^S`；4 族 → `p ≥ 0.125`；3 族 → `p ≥ 0.25` → **算术上不可能 p<0.05**。
3. **簇数在四处被写成 3 / 4 / 24 families / 24 tasks**，而 CR2、wild bootstrap、「≥10,000 次置换」全建立在它之上。

**修复**：
- **判定器对比**用**快照内配对**（这是 M1 的正确单位，也天然解决 RI 问题）；
- **臂 ITT** 的随机化单位改为**运行谱系（run lineage）且 S ≥ 8**；或**明确声明以这 4 个 authored 族为条件**，不再声称对族总体推断；
- **全项目统一簇定义**，写死一处。

### 3.3 ★ B0 处置（V2）

**B0 目前只是一列打印值，不是协变量、不是门、也不是终点** → 拦不住「全报警」策略。
**修复**：**把 oracle 匹配的 flag 要求写进检出定义本身**（§1.2 的 (ii)），使「全报警」**在定义上**无法获胜；B0 的假警报率作为**强制同表列**并进入 Gate 1 的对比。

### 3.4 故障注入的循环性（V2）

`F5` 的触发谓词（>2% 偏离 `GOLD`）**与故障 oracle 同构**（R15:614 自承）→ S3 调度在 F5 上的优势**按构造成立**。
**修复**：**F5 的触发与 oracle 解耦**，或**在该族上不报告调度优势**，并在论文中显式声明这一对齐。

### 3.5 功效：全部重算（V2，我采信，且推翻 R15 与我的部分说法）

| 量 | R15 声称 | **V2 复算** |
|---|---|---|
| 设计效应 | 2.2（ICC 0.15） | **1.45** |
| 有效样本 | 96 | **66.2** |
| MDE | 0.35 SD | **0.49 SD（α=.05）／0.59 SD（Holm α=.01）** |
| 达 0.35 SD 所需 | 576 run | **≈1,659 run** |

**另**：R14 的 McNemar **234 正确**，但**是 `ψ ≤ 0.30` 条件下的下限**（`ψ=0.50` 时需 **391**）。
**关键**：300 条**支持** R14 的 0.04–0.05/倍增目标（需 244）——**但那个目标是 28 个百分点的累计差距**；**10 个百分点的 horizon 分歧需 ≈1,910 条** → **R14 的 +375 扩展小了 5×**。
**载波升降探针是 50 对，不是 100** → MDE 0.17–0.21，在 0.15 处功效仅 **0.37**。

### 3.6 成本：三处修正（V1 + V2 + V3）

1. **$3,802 = $38.02 × 100.01**（V1/V2/V3 三方独立定案）；「5×120×576 = 69,120」**是错的，应为 345,600**。
2. **R15 §6.1 的单位成本是其自身 token×价格乘积的 2.6–7 倍** → **R3 声称「$229→$40 纯属价格效应」是错的**（按其自身价格应为 $34）。**R3 §3 该表述作废**，但**方向性结论（R15 的预算是错的）不变**。
3. **「钱不是约束」需限定**：在 85% 缓存 **+ 1,500 推理 token** 下，$0.10 只能买 **99 次**判定 **< 120 个检查点** → **该结论只在「非思考模式」配置下成立，而 R5 从未指明该配置**。→ **必须明确声明所依据的模式，并对 thinking 模式重算。**
4. **85% 缓存假设与 R15 §0.3 的 newest-first 序列化器矛盾**（50× 折扣需要**稳定前缀**）→ **缓存命中率必须实测**（V3 已实测 **95.4%**，但那是在特定提示下）。
5. **工程（$1.5–3k ≈ 预算的 70–85%）与人工评审成本被省略**，而标题却说成本不是约束 → **必须计入并明说**。

### 3.7 ★ Jev 交叉点：符号错误（V1，与 V3 一致）

V1：**R3 的交叉点表不可复现；在 0% 缓存下 Jev 在每一个规模上都更便宜——没有交叉点，符号相反。**
V3 则从另一角度：**在 52k token 时 Jev 贵 2.2×**。
→ **两者的差异源于缓存命中率假设。裁决：删除 R3 §5 的「交叉点 2,100–7,100 token」这一具体断言**，改为**按每次运行实测 token 数逐点计价并画成 horizon 曲线**，且**明确标注缓存命中率的取值来源**。**在实测之前不做方向性断言。**

### 3.8 ★ 弃权对所有臂都不可用（V1 更正 V5）

**V5 错，V1 对。** V1 检视了实际设计：**R15 §0.4 的问题库没有 abstain 选项** → **弃权对 A0 与 A1 同样不可用**，不只是 Laya 的 `choice`/`score`。
→ **R7 §7 第 2 条的裁决需扩大**：**弃权仅对 Jev 的 `check`（`insufficient`/`undecided`）与 `noul` 的 `band` 可测。**
→ **论文不得包含任何跨判定器的弃权对比**，除非先给 A0/A1 加入 abstain 选项（这会使选项集与类型化判定器不同 → 又破坏公平）。**建议：删除弃权作为对比维度**，改为报告**分布离散度**（top-1/top-2 间隔、熵）作为事后分析量。

### 3.9 ★ 缺回缺失的对照：`S0` judge-never（V2）

**`S0` 存在于 R15 §2，却在 R5 §5.3 中丢失** → **综合稿无法证伪「判断本身是否有帮助」**。
**修复**：**恢复 `S0`（真静默臂）**。注意它与 A0 不同（A0 仍记录散文 verdict），且**改变生成器提示词** → 作为**独立对照**报告，不与 A0 等价。

### 3.10 反稻草人控制缺失（V1）

**R16 §D.5 强制要求的 P1–P4 提示词变体带、以最优变体为头条、logit 读数、`uncertain`/计费重试——全部不在 R5 中。**
**另**：**A1 返回 `{label, prob}`，而类型化判定器必须报完整分布** → **核心校准结论在比较不对等的仪器**。
**修复（V1 给的，成本极低）**：**让 A1 也返回完整分布**，并用 **≈$0.44 的冻结快照回放**跑完 P1–P4 带。
**另外**：**A1 遗留自评混淆** → 免费修复 = **让同一 LLM 在「别的 run 的快照」上回放**（外来评估者对照）。

### 3.11 其他必修（V1）

- **选项规格互不满足**：R15 的「≤48 token/选项」与 R5 的「<49 = 设计失败」**互相冲突** → 统一。
- **A4 升级只有类型化侧；没有类型化批处理臂** → 补齐对称性。
- **微调分支给 Laya 域内标签，却没有 LLM 的对等物** → 要么给 LLM 同样的域内示例，要么明确声明这是不对等对照。
- **A5b 批处理破坏快照对等，且 Laya 在 512 token 内做不到** → 见 §4。

### 3.12 效率主张改口径（V3 + V2）

**A5b/A5c 在 Laya 侧不可构造**（Laya 无跨 state 批处理；答案确定性使 k 次采样无意义）。
→ **效率主张改为「每检查点所需的顺序往返次数」**，并在**双方各自最优打包方式**下测量：
- LLM 判定器：一次调用可判定 N 个检查点；
- 类型化判定器：一次调用只能一个 state，但同一 state 上可打包 q 个问题。

## 4. 最终实验矩阵（修订版）

**臂**：`S0`（真静默，恢复）· `A0`（散文自评）· `A1`（结构化同题，**返回完整分布**）· `A2` Jev（**当前阻塞**）· `A3` Laya · `A4` 自适应升级 · **外来评估者对照**（同一 LLM 评别的 run）

**平面**：M1 主电池（有门）+ M2 增长探针（无门）

**主终点**：`P_detect(τ*)`，**快照内配对**，**oracle 匹配的 flag**
**次终点**：臂 ITT、漂移曲线、**跨物种错误互补性**（`Δ_catch` + κ）、`token_ratio(t)` per checkpoint

**条目**：
- **300 条**（horizon 斜率，R14 的 x 剖面设计使其对斜率**充分**）
- **+ ~1,610 条**（若要做 10 个百分点的 horizon 分歧）→ **这是需要人类决策的岔路口**（见 §7）
- **≥1,000 条**（校准曲线，且需**留出切分** + **分辨率下限**）

**必删**：`score` 出主电池；弃权作为对比维度；R3 §5 的交叉点断言；固定 1,500 token 的成本行

**必加**：`off/low/high/max` 推理档位扫描（≥100 次调用）；G3b 符号基线上限 0.80；Q6 平衡准确率 + TRUE 率封 50±5；`H4-refreshed` 单元

## 6. 论文骨架（终版）

1. **摘要** — 判断层比较；成本非约束（**限定模式**）；**仪器自报不可信**；跨物种互补性
2. **引言** — 长线智能体的判断成本被误认为金钱问题
3. **背景与相关工作** — 判别式/生成式、级联与延迟决策、LLM-as-judge、验证器、长线退化；**明确承认架构不新**
4. **被测系统与仪器缺陷** — 5 个已确认缺陷（**mock Jev**、坏 `laya_plan`、字符规划器、**逐 checkpoint 钳位与静默窗口**、confidence 尺度不一致 + 高基数锐化）
5. **方法** — 生成器/判定器分解、双平面、序列化器、问题库、拨盘（含 `L`/`L+C`、`H4-refreshed`）、故障注入、**快照内配对 + oracle 匹配 flag**、预注册
6. **结果 A：成本不是约束（限定）** — 逐运行 token 计价、缓存命中实测、推理档位扫描、**含工程与人工**
7. **结果 B：仪器自报不可信** — 逐 checkpoint 钳位与未告警受损区间、输出冻结、**confidence 解耦（0.9981 错答 / 0.9989 噪声）**、高基数饱和、**mock 的 Brier 0.359**
8. **结果 C：过程质量** — `P_detect(τ*)`、漂移、复合错误、恢复、B0 同表
9. **结果 D：跨物种互补性** — `Δ_catch`、κ、增量检测成本（**免疫于准确率水平混淆**）
10. **讨论** — 部署建议；窗口权衡；两种判定器的经济性都随 horizon 恶化（**静默截断 vs 按 token 涨价**）
11. **局限** — T3 污染存活、单机单设备、**Jev 阻塞**、批处理不对称、弃权不可比
12. **可复现性** — 6 个仪器哈希、checkpoint 哈希、设备、时段、原始产物
