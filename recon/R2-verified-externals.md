### A.1 对实验设计的三条硬性影响（由价格直接推出，非推测）

1. **成本实验必须记录运行时段并固定之。** 同样的批次在高峰跑是低谷的 2 倍成本。论文的「成本」章节若不同臂跨越峰谷边界，成本对比即失效。→ 协议必须固定运行窗口，或按记录时段做归一化。
2. **缓存命中把输入成本压低到 1/50（0.003 vs 0.15）。** 这是对本文效率论断的**最强反驳**：若 LLM 判定器的共享前缀命中缓存，其输入成本可忽略，那么「廉价判定器省很多钱」的结论会被大幅削弱。
   → **必须把缓存命中率当作显式变量报告**，并在成本模型中单列 `hit/miss` 两项。等预算前沿要在「LLM 高缓存命中」这一对 LLM 最有利的设定下也算一遍，否则审稿人会替我们算。
3. **默认开启思考模式 → 推理 token 计入输出价（$0.60/1M 低谷）。** 判定类任务用 `off`/`low` 与用 `max` 的成本差异可能是一个数量级。→ 推理档位（off/low/high/max）是成本维度的**主要自变量**，必须纳入扫描，而不是固定在默认档。

### B.3 **核心发现：静默截断窗口 ≈300 字符**（论文的动机）

**规划器根本不跑 tokenizer**（`planning.py`：`_CHARS_PER_TOKEN = 4.0`，`_SAFETY = 1.15`，即 `chars/4×1.15`），**每一次响应里 `exact` 都是 `false`**。

| 事实 | 实测值 |
|---|---|
| 规划器隐含的字/词比 | **3.478** chars/token（4.0 ÷ 1.15） |
| 该编码器在英文散文上的**真实**密度 | **4.31** chars/token（⚠️ 2026-09-23 更正：原印 **≈6.33**，那是**截断扫描的合成状态**（同一句 filler 重复 45 遍）的密度，**不是英文散文**） |
| 规划器误差 | **对英文散文高估 1.239×**；对合成状态高估 1.949×；**对 JSON 低估 1.450×、源码 1.075×、中文 2.105×、CSV 2.150×**（⚠️ 原印「高估 ≈1.8×」，只对合成状态成立且漏报了危险方向） |
| **运行时真实钳位** | **512 token**，尽管 Path A 的规划器以为 `max_len = 1024` |
| 真实 state 预算 | **≈450 token ≈ 2850 字符**（2 选项 noul，head 61 token） |
| Path A 规划器首次告警 | **3148 字符** |
| **静默窗口** | **≈2850 → 3148 字符（≈300 字符 / ≈47 token）** |

**窗口内实测后果（TAIL 把决定性证据放末尾，HEAD 放开头；真值 TRUE）**：

| 字符数 | 真实 token | TAIL | 字段告警 | HEAD |
|---|---|---|---|---|
| 2836 | 453 | 0.4034 **错** | `truncated` **缺失**、`fits: true` | 0.7861 对 |
| 2936 | 469 | **0.2376** 错 | 缺失、`fits: true` | 0.7297 对 |
| 3136 | 500 | **0.2376**（逐位相同） | 缺失、`fits: true` | 0.7297（逐位相同） |
| 3236 | 515 | 0.2376 | **首次出现** | 0.7297 |

→ **输出冻结**：2936→5086 字符（跨 2150 字符）TAIL 恒为 `0.2376`、HEAD 恒为 `0.7297`，**逐位相同** → 模型确实不再看到新文本。这是「尾部被丢弃」最干净的证明。
→ **Path B 误差反向**：在 1399 字符处 `truncated` + warning + recommendation **全部触发，但根本没有截断**（`input_tokens_padded: 265`，仅用了 265/512）。**假阳性**。

**两条路径的错误方向相反**（A 乐观、B 悲观），根因同一个：规划器不 tokenize。

| 选项数 | 选择 | p(top) | confidence | 正确 | 每标签 token | 压缩 |

- 压缩起点：**Path A 11 选项 / Path B 4 选项**。
- 断点在 **(15, 20]**，每题一档 → **只是 bracket，不是准确率曲线**。
- 20 选项失败**逐位可复现**。
- **`fits: true` 与 `truncated.options` 同时存在** → `planning.py` 的 `fits` **只考虑 state**，模块 docstring 声称的「选项可读」条款**未实现**。

### B.5 `confidence` 实测：不可用于任何门控（决定性证据）

| 观测 | 值 |
|---|---|
| **全探测最高 confidence** | **0.9981 —— 出现在唯一的错误答案上**（20 选项） |
| 正确答案的 confidence | **0.2543**、**0.3337** |
| 同一 p≈0.54、仅改 framing | bare noul `max(p,1−p)` = **0.5399**；带 criteria 的 noul-as-choice `1−H/log k` = **0.0046**（**差 117×**） |
| 纯噪声 state | `noul 0.0011 / confidence 0.9989`（键盘乱敲上的近乎全信） |
| 空 state | 返回 `choice: technical`，**`ok:true`、无 error、无 warning、`fits:true`** |

→ 协议硬约束：**永不把 `confidence` 当作正确率概率、阈值或路由信号；永不跨原语或跨 noul framing 比较 confidence**。若必须用不确定信号，**只用 `noul` 的 `band`**（p=0.5001 时返回 `band: "uncertain"`，是唯一表现良好的「我判断不了」通道）；`choice`/`score` **没有** `band`，只能报完整分布。

### B.6 确定性、顺序敏感、退化输入

- **同请求逐位相同** → **不要为方差浪费重复调用**；重复只留给近平分情形（未测）。
- **criteria 顺序置换**：argmax **稳定**；但 p 摆动 ≤0.0515，**confidence 摆动 0.1107** → 协议必须**冻结一个规范顺序**并全程使用。
- **近义选项标签**：四个同义改写返回 `a: 0.4951 / b: 0.4736`，**仍给出硬选择 `"a"`** → 无「我无法裁定」通道。
- **空/噪声 state 一律 `ok:true` 静默接受** → **输入校验必须由 harness 自己承担**，不能指望 Laya。
- **`score` 在最弱原语这一说法上未能复现**（2/2 项 score 不劣于 choice）→ 与工具描述相反，但 n=2，**需 ≥200 项重测**。

### C.2 关键：Jev 定价与 LLM 定价的相对关系（**推翻「判定器必然更便宜」的直觉**）

以 deepseek-flash 低谷价（输入未命中 $0.15、缓存命中 $0.003、输出 $0.60 / 1M）对比：

| 对比 | 倍数 |
|---|---|
| Jev 输入 vs LLM **输入未命中** | Jev 便宜 **约 3.6×** |
| Jev 输入 vs LLM **输入缓存命中** | Jev **贵约 14×** |
| Jev vs LLM **输出** | Jev 免费 vs $0.60 → 在**输出密集**场景 Jev 优势巨大 |

→ **结论**：Jev 的成本优势**来自「不产生输出 token」**，而不是「输入更便宜」。
→ 因此等预算对比中，**判定类任务（输出极短）上 LLM 也可通过缓存命中把输入压到极低**，两者成本可能收敛到同一量级。**论文不得声称「typed judge 一律更便宜」，只能声称「在输出密集或判定密集的特定形态下更便宜」，并给出实测的交叉点。**

### C.4 **该文的方法学应被本文直接沿用**（这是目前找到的最佳模板）

该基准的做法比大多数学术论文更严谨，本文应逐条对齐：
1. **语料与协议在调用前冻结**，附 SHA256 哈希清单；原始产物打包下载（`cases.jsonl`/`protocol.json`/`attempts.jsonl`/`metrics.json`）。
2. **配对设计 + 种子化乱序 + 交替先后顺序**（seed `20260918`，交替 JEV 先行与 Haiku 先行）以消除顺序效应。
3. **聚类自助法**：10,000 次重采样**以「案例」为聚类单位**，保留同一案例的重复观测在一起，而非把 240 次调用当作独立样本 —— 与本文 R1 威胁模型第 3 条完全一致。
4. **按注册表价格逐条重算成本**，并与服务方自报成本核对；显式声明「不含 completion、embedding、预热与评测裁判成本」。
5. **显式声明未测项**：作者明确写出「本文不建立通用分类准确率或最终答案质量」「标签由同一作者撰写、未经独立评审或盲审裁决」。
6. **失败与剔除全部留痕**：早期三次配置失败的证据单独保留，未删除或重标任何案例。
7. **版本钉定**：`jev-latest` 先解析为 `jev-1.13.0` 再钉死，并声明未来解析结果变化需重做实验。

→ **本文的协议章节应直接采用 1–7，并在论文中声明对齐了该基准的方法学。** 这能极大降低「审稿人质疑实验严谨性」的风险。
