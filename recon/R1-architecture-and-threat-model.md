# R1 — 架构分解与威胁模型（本文档为全项目的概念地基）

> 作者：主控（team lead）
> 状态：**工作稿**。依赖 R11–R16 的实测结果回填。凡未经实测/未读源码支撑的数字，一律标注「未核实」。
> 用途：约束所有子单元的设计，防止各自朝不同方向漂移。

---

## 0. 一句话问题陈述

待研究的对象不是「三个模型谁更强」，而是：

> **在一个长线任务中，把判断工作交给一个廉价的、离散的、非自回归的判定模型（Jev/Laya），相比交给一个强大的自回归生成模型（DeepSeek-V41-Flash），在准确率、校准、成本、延迟，以及——最关键——过程质量和错误可发现性上，会付出什么、换回什么？**

这个陈述决定了三件事：不是同台竞技、不是单点比较、必须有过程度量。

---

## 1. 核心架构分解：三类评测者不是同一物种

必须先钉死的事实，否则整篇论文的对比都是伪对比：

| 维度 | LLM（DeepSeek-V41-Flash） | Jev（远程服务） | Laya（本地模型） |
|---|---|---|---|
| 类型 | 自回归**生成器** | 状态条件**判别器** | 状态条件**判别器** |
| 输入 | 任意文本 + 历史 + 工具 | 你交给它的**一个 state** | 同左（受硬预算限制） |
| 输出 | 自由文本 / 可调用工具 | 声明式题型的答案 + 概率 | 同左 + truncated/budget_summary/warnings |
| 能采取行动 | **能** | **不能** | **不能** |
| 能看到的东西 | 全局（自己维护上下文） | 单次调用内的 state | **单次调用内的 state，且 ≤512 token（英文版）** |
| 能否自我纠错 | 能（读到自己的错误后果） | **不能**（只看给定 state） | **不能** |
| 失败方式 | 幻觉、漂移、自信地错 | 静默截断、选到错标签 | 静默截断、语言误路由、未校准的 100%/0% |
| 单位成本主导项 | 输出 token + 推理 token + 往返 | state 编码 + 网络 | state 编码（**每题重编码 —— 见 §2**） |

**结论 1（不可谈判）**：Jev/Laya 不能执行任务。「长线任务中的 Jev/Laya 组合」在物理上只能有一种含义——

> **LLM 是执行者／生成者；Jev/Laya 是执行者身上的判断层与检查点。**

任何写成「Jev 独立跑一个长任务」的实验设计都是错的，必须在论文里显式说明这一点，否则审稿人第一句就会问「Jev 怎么写代码」。

---

## 2. 任务分解：生成类 vs 判别类

长线任务必须被切成两类子任务，两类分别度量：

- **(A) 生成类（generative）**：写代码、写文档、做规划、修复缺陷。**只有 LLM 能做。** Jev/Laya 在这一侧永远缺席，论文不得在此并列对比。
- **(B) 判别类（discriminative）**：是否一致、选哪个、打几分、证据是否支持、谁更相关。**三者都能做**，这才是公平赛道。

论文的主对比表只应出现在 (B) 类上。对 (A) 类，Jev/Laya 的影响只能通过「判断层改变了生成者的行为」间接体现，这是**(B)→(A) 的传导效应**，也是「组合」命题的真正内容。

## 3. 成本模型（这是效率章节的地基，必须先立起来）

单位不同不能被抹平，必须显式建模。

**LLM 单次判断成本**：
```
C_llm = (T_in·p_in + T_out·p_out + T_reason·p_out) + λ·R
其中 R = 往返轮数，λ = 每次往返的延迟惩罚
```
**判别器单次判断成本**：
```
C_disc = E(state) + q·c_q + λ·R
其中 E(state) = state 编码成本，q = 同批问题数，c_q = 单问题边际成本
```
**关键杠杆（论文独有的机会点，未核实需实测）**：Laya 目前**对每个问题重新编码同一个 state**（上游 issue #49 明确记录：PR #47 批处理了 state–question 对，但未跨问题共享编码）。这意味着：

- 对**同一个 state 问 1 个问题**：编码成本无法摊薄。
- 对**同一个 state 问 k 个问题**：接近线性增长，而不是只付一次编码。
- 因此「把 N 个判断拆成 N 次廉价调用」在本地方案上**并不廉价**；正确用法是与生成者的自然节拍对齐、批量下发。

→ 这直接决定了实验设计里**必须把「批大小 / 判断节拍」当作一个自变量**，而不是常数。同时它本身就是一个可发表的测量结果：**判别模型在长线任务里每单位判断的真实成本是多少**（README 里的 15–33 ms 是 GPU/单题的乐观数字；CPU 英文实测约 140 ms，来源为既有 recon，需在本机复测）。

**主分析口径**：不做「单次调用谁快」的比较（无意义），做**等预算质量前沿**——固定总花费，看每臂能买到多少次检查、最终质量如何。建议以该前沿曲线（而非单一准确率数字）作为论文主图。

## 4. 威胁模型（预先登记，防止事后自欺）

按危险程度排序。每条都必须有对应的控制手段，否则结论不可信。

1. **稻草人风险（最高危）**。把 LLM 拿去做强制选择，措辞稍变就能让结果上下翻飞。若无「结构化自检臂」（同样的题型问 LLM 自己），则 Jev/Laya 的任何优势都可能只是提示格式差异。
   - 控制：强制选择 + 结构化自检臂 + 同预算自洽性臂，三者缺一不可。
2. **基准循环性（ground truth 污染）**。若用 Jev/Laya 的输出去定义「正确答案」，则一切准确率数字自证。
   - 控制：ground truth 必须来自外部可判定来源（测试执行结果、数据真值、独立人工标注），并在方法章节写明标注流程与一致性系数。
3. **决策非独立（统计口径错误）**。同一次运行内的数百个判断高度相关，按判断数算 N 会严重高估显著性。
   - 控制：以「运行」为聚类单位，用分层模型或聚类稳健标准误；这一点必须写进统计方案。
4. **置信度不可比**。Laya 的 `confidence` 是**选项集中的集中度统计量，不是答对的概率**；Jev 的概率与 LLM 的口头概率语义各不相同。
   - 控制：只比较**校准曲线**（分箱后的实际正确率 vs 声称概率），永不直接比较 confidence 数值；不预设三者置信度可通约。
5. **隐蔽截断**。Laya 对超长 state 从**尾部**静默截断，答案本身未必报警；而长线任务中的 state **必然随时间增长**——这条威胁会随 horizon 单调恶化。
   - 控制：强制 `laya_plan` 预检；把「截断率 vs horizon」本身作为一条曲线来报告（这是威胁，也是发现）。
6. **语言误路由**。检测器只认 en/fr/de/es/pt/it/nl，其他拉丁字母语言被静默送给英文 checkpoint 且自信答错。
   - 控制：要么把语料限定在受支持语言并声明，要么把误路由做成一个显式的鲁棒性子实验（它能贡献真实发现，而非仅是缺陷）。
7. **未校准基线**。多语 checkpoint 出厂温度 1.0，会轻易给出 100%/0%。
   - 控制：先做校准测量并用标注集做标量温度拟合，再报告校准结论；否则校准章节毫无意义。
8. **生态快速漂移**。这是模型/服务层而非冻结基准，检查点与 API 会变。
   - 控制：记录 checkpoint 版本、服务端版本、日期与硬件；所有延迟数字**必须带设备限定词**（CPU vs GPU 差 4 倍量级）。
9. **ground truth 可得性偏差**。只在有客观真值的任务上做实验，会系统性偏向「可自动验证」的子问题。
   - 控制：显式声明适用范围，不外推到开放式任务。
10. **新意风险（定位问题）**。级联/升级（cascade/escalation）、LLM-as-judge、过程奖励模型都已有大量工作。
    - 控制：**不做算法新意的宣称**，把定位钉在「以真实、本地、非自回归判定模型替换 LLM 判定器」的**测量与刻画**上。详见 R16。

## 5. 度量清单（目标 − 手段 − 风险）

| 指标 | LLM 臂 | Jev 臂 | Laya 臂 | 风险 |
|---|---|---|---|---|
| 单次判断延迟 | 调用计时 | 调用计时 | 调用计时（**必须注明设备**） | Laya 冷启动 25–35 s 会污染均值 → 需 warm-up 后计时 |
| 单次判断成本 | token×单价 | 服务定价 | 本地算力摊销 | 本地成本如何货币化需明确口径 |
| 准确率（判别类） | 可 | 可 | 可 | 需外部真值 |
| 校准（分箱可靠性） | 可（口头概率） | 可 | 可 | 未校准基线须先修 |
| 弃权／不确定率 | 可（需允许"不确定"） | 可（insufficient/undecided） | 可（低置信） | **必须给 LLM 同样的弃权权**，否则不公平 |
| 解析失败率 | 结构化输出失败 | 调用错误 | warnings/截断 | 需统一「不可用」定义 |
| **错误发现提前量** | 可（步数） | 可（步数） | 可（步数） | **本文最有价值的过程指标** |
| 漂移曲线 vs 真值 | 可 | 可 | 可 | 需 gold reference |
| 截断／预算溢出率 vs horizon | 不适用 | 批量上限拒绝 | **核心风险曲线** | 需预检 |
| 重复性／顺序敏感性 | 温度=0 时的稳定性 | 需实测 | 需实测（选项顺序） | 顺序敏感则协议须固定顺序 |

- R16：基线阶梯、成本公式的取值来源、相关工作与可辩护的结论集。

## 7. 由此地基直接推出的三个设计命令

1. **每个臂共用同一个 LLM 生成者**，只替换判断层——否则不是「组合效果」而是「换了个更强的模型」。
2. **必须包含结构化自检臂**——它是全部结论的守门人。
3. **主图是「等预算质量前沿」+「错误发现提前量 vs horizon」**——不是一张准确率对比条形图。
