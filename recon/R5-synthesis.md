## 0. 一句话结论（论文的真实主张）

经过实测，原设想的三条主张**两条不成立**，一条被大幅加强：

| 原设想 | 实测裁决 |
|---|---|
| 「判定模型更便宜」 | ❌ **不成立**。钱不是约束（R3）：零缓存命中最悲观下 $0.10 也买 337 次 LLM 判定，设计只有 120 检查点。 |
| 「判定模型更准」 | ❌ **不能主张**。Laya 基座在决策任务上**接近随机**（自报 0.362 vs 多数类 0.461），且 R13 实测 n=10 的 0.80 置信区间 [0.49, 0.94]。 |
| 「判定模型适合长线任务」 | ⚠️ **部分成立，且方向被修正**：优势在**并行检查 + 无顺序往返 + 自带升级语义**；但**能力随 horizon 静默退化**（R13 实测静默窗口 ≈300 字符）。 |

**因此论文的诚实标题应当是**：

> **《长线任务中判别式判定器的真实代价：成本不是约束，静默退化才是》**
> 副标题：一个本地 421M 非自回归判定模型与一个前沿生成模型在相同条目上的过程级对照

**核心贡献从「证明判定器更好」改为「测量并刻画判定器在长线上的失效边界」**——这是一个更强、更难被推翻的主张，因为它建立在 R13 已经实测到的、可复现的静默截断与 confidence 解耦上。

## 1. 根本架构（不可谈判）

**只有 LLM 能生成。Jev 与 Laya 只能回答你交给它的 state 上的类型化问题。** 因此：
- 所有臂**共用同一个 LLM 生成器**（同 prompt、同工具、同 seed、同步数）；
- **只有判断层**在臂之间变化；
- 论文必须在**摘要**（不只是方法）中写明这是**判断层比较，不是智能体比较**；不存在「Jev agent」。

判定器的输出**只能是门，不能是驱动器**：`accept` / `revise`（把标签作为约束回注给**同一个生成器**重做）/ `halt`。
→ 保证「生成器恒定」字面为真，生成调用次数成为**协变量**而非隐藏自由度。

## 3. ⚖️ 单元冲突的裁决

### ⚖️ 冲突 1：等预算臂（R15 A5）该保留、降级、还是删除？
- R15：A5 是「效率主张生死的战场」，其中 **A5b（批量 LLM）绝不可删**，否则 LLM 臂是稻草人。
- R3（我）：钱不是约束，A5 在美元轴上无区分力。

**裁决：保留但**重新定位**。** 删除 **A5a**（均匀子采样，确实无信息量），**保留 A5b/A5c 并改名为「顺序往返匹配臂」**。
**理由**：R15 的论证在**换轴之后依然完全成立**——A5b 控制的是**往返密度**而非美元密度；R13 又独立提出「一个批处理另一个不批处理的比较不是比较」（其约束 22）。两者合起来要求：**LLM 判定器必须被允许批量与自洽采样**，否则论文可被一句话推翻。
→ 主前沿改为**双面板**：`墙钟延迟 vs 错误发现提前量` 与 `判定美元 vs 错误发现提前量`，后者预注册 **TOST 等价性检验**并报告「美元轴无显著差异」。

### ⚖️ 冲突 2：样本量 N（R14 说 300，R13 说 ≥1000）
- R14：300 条 = 60 匹配槽 × 5 horizon 档，配对 McNemar 下限 234。
- R13：准确率 ±0.05 需 **385**；可靠性/ECE 曲线需 **≥500**，比较两判定器 ECE 需 **≥1000**。

**裁决：两个 N 都要，且按主张分列。**
- **horizon 斜率 / 检测提前量**：R14 的 **300**（其配对设计针对该主张，power 论证成立）。
- **校准与可靠度曲线**：**≥1000**，因为 ECE 是本文的核心部署结论之一。
- **关键可行性论证**：R13 实测**同请求逐位相同** → **类型化判定器是确定性的**，因此可以对全部 1000 条只跑一次而无需重复；LLM 臂则需要重复采样（且必须走非思考模式）。**这个不对称是真实的，且对类型化判定器有利，应在论文中明说。**
→ 总条目 **1000**，其中 R14 的 300 条构成 horizon 子设计。

### ⚖️ 冲突 3：Laya 的准确率主张
- R2/R13：基座近随机；0.766 属于**在该基准自身训练集上微调过**的 checkpoint。
- R14：设计并未包含微调。

**裁决：把「零样本 vs 微调」提升为显式实验因子。**
- **主分析用零样本 Laya**，诚实报告其水平（预期接近多数类基线）。**不得引用 0.766。**
- **增加一个微调分支**：在**独立训练划分**上微调 `laya-typed-decisions`，在留出集上评测。这是**当前没有任何人做过的事**（上游自己承认是「可特化的基座」），因此是**独立可发表的小贡献**，且能回答「特化能否把 421M 推到前沿模型水平」。
- 若微调分支因预算取消，则**准确率主张整体删除**，论文退守为测量/刻画论文（仍成立）。

### ⚖️ 冲突 4：`score` 是否最弱原语
- 上游自述 `score` 最弱（SST-5 0.372）；R13 实测 **2/2 项 score 不劣于 choice**。

**裁决：按 R13 自己的建议，在用 ≥200 项重测之前不重复该说法。** 主分析以 `noul` 为主（唯一有 `band` 的原语），`choice` 次之，`score` 作为**独立的小型重测实验**。

## 4. 协议硬约束（由实测直接强制，违反即结论作废）

### 4.1 部署冻结
1. **钉死 Laya 入口**：主分析用 **Path A（插件 / :8787，planner 1024/512）**，并**同时用 Path B 做一次鲁棒性对照**（因为两者错误方向相反，这本身是一个结果）。
2. 记录 sidecar 启动参数、`/version`、checkpoint 路径、设备（`cuda`）、以及**设备回落到 CPU 的检测**。
3. 每次运行前**健康检查 + 自动重启** sidecar，并记录冷启动次数（冷启动 389.9 ms / 4935.9 ms vs 热 37 ms，混入会污染延迟）。

### 4.2 state 与预算
4. **一律用 token 表达预算**，用 checkpoint 自带 tokenizer 计数（`_models/laya/tokenizer/tokenizer.json`）。
5. **硬上限 450 state token/问**；`state_tokens ≤ 512 − head_tokens − 1`；安全区 ≤400。
6. **决定性证据永不放 state 尾部**（R13 已实测尾部先被丢弃）。
7. **预检以自己算的 token 数为准**，Laya 的 `fits/truncated` 只作旁证（Path A 假阴性、Path B 假阳性各已实测）。**不使用插件 `laya_plan`（已损坏）**，改用 `mcp__laya__laya_plan` 或直接 `POST /plan`。
8. **选项上限 10（Path A）/ 3（Path B）**；`tightest_option_tokens_each < 49` 视为**设计失败**而非警告；选项描述长度须接近等长。
9. **harness 自己拒绝空/纯空白/低字母表 state**。

### 4.3 判定与门控
10. **`confidence` 永不用于门控、阈值、路由**。若需不确定信号，**只用 `noul` 的 `band`**；`choice`/`score` 一律报**完整分布**。
11. **升级规则预注册为分布检验**（top-2 间隔或熵），**不是 confidence 阈值**；并报告间隔值，使 20 选项的饱和以「饱和」而非「确定」的形式可见。
12. **冻结一个规范 criteria 顺序**并全程使用（置换会移动 confidence 达 0.111）。
13. **重复调用只用于近平分情形**（确定性已实测），不用于方差估计。

### 4.4 测量
14. **延迟必须串行发起并自行计时**：并行工具调用共享同一结果时间戳（5 个调用落在 3 ms 内），会话记录只能给批量墙钟。
15. 会话记录（`.jsonl.zstd`）**有 token 数、无货币成本** → 成本按公开价目表自行计价，并声明口径。
16. **缓存命中率必须实测**（`usage` 直接报告命中/未命中），不得沿用 R15 的 85% 假设。
17. **思考模式下 `temperature` 无效、`top_p` 下限 0.95** → 自洽采样臂**必须切非思考模式**并记录该切换。
18. **固定运行时段为低谷**（高峰价为低谷 2×），并记录时段与时区。

## 5. 实验矩阵（最终）

### 5.1 任务族（R14，取 3 族以控制规模）
- **F2 `EVIDENCE-BRIEF`（主力）**：40 主张 × 60 文档，每片段带机器可读标注；标签由**覆盖函数在标注记录上计算**，不由任何判定器给出 → **避开基准循环性**。判定单元 ≤130 token + ≤60 token，**三种判定器都原生胜任**。
- **F1 `SPECSHIFT`**：残差舍入污染，~90 个静默接合点，**可执行 oracle**。
- **F4 `AUDIT-CASCADE`**：早期假阴性剪掉一个子树并**永久封顶召回** → 不可逆性。
- **废弃**：统一分诊（是「步数多」而非 horizon），仅保留作 **horizon 安慰剂**。

### 5.2 horizon 拨盘（R14）
地板 J1 + 距污染距离 `d ∈ {0, 4, 28, 124}`，**载体宽度、token 数、片段位置、选项位置、族混合全部固定**，分析为 **judge × log2(H) 斜率**。

### 5.3 臂（合并 R15 + R3 裁决）
| 臂 | 判定器 | 说明 |
|---|---|---|
| **A0** | LLM 自由散文，融入生成步 | 现任基线；**零额外往返**；须报告解析失败率 |
| **A1** | **同一 LLM，结构化同题**（JSON，含 `label` + `prob`） | **不可谈判的守门人**；消除「再问一次」「格式」「判定者身份」三个混淆 |
| **A2** | Jev | **当前阻塞**（mock） |
| **A3** | Laya（Path A） | 主分析 |
| **A4** | 自适应升级（先廉价后升级） | **Laya 自带 `act_costs.escalate` 语义**，且 `esc(t)` 随 horizon 上升本身是结果 |
| **A5b/A5c** | **顺序往返匹配臂**：批量（≤8 检查点/调用）+ 自洽采样 k=8 | **绝不可删**（R15 + R13 冲突 1 裁决） |
| **B0** | **良性改写对照** | **防止「全部报警」在提前量上刷分** |

### 5.4 双平面（R15，保留）
- **控制平面**（在线、按调度）：只有被调度的判定可影响控制流。
- **测量平面**（离线、穷举）：**每个 run 的每个检查点**写不可变快照 `SNAP[run][t]`（state JSON + 哈希 + 冻结序列化器下的 token 数）；run 结束后**全部判定器在冻结快照上回放**。
→ 否则「judge-never」按构造没有检测延迟，调度效应与判定器效应**不可识别**。**这是全文最好的设计决策**，且因成本极低而更可行。

### 5.5 过程指标
- **主终点：`T90`**（检测概率达 0.90 的步数），**在匹配顺序往返下**；离散时间生存模型 + **任务层随机化推断**（簇数少时的正确选择）。
- 漂移曲线 `D(r,t)`、漂移速度、复合错误率 `λ`、恢复率与恢复延迟、**`token_ratio(t)` 生存曲线**（Laya 可用性随 horizon）、成本-完成曲线（**串行 vs 可并行分别报告**）。
- **强制**：所有检测类指标必须与 **B0 假警报率**同表报告。

## 6. 定位（R16 核实后的诚实版本）

- **架构不新**：级联/升级已有 [Cascaded Language Models](https://arxiv.org/abs/2506.11887)、[FrugalGPT](https://arxiv.org/abs/2305.05176)、[RouteLLM](https://arxiv.org/abs/2406.18665)、[AutoMix](https://arxiv.org/abs/2310.12963)、learning-to-defer。
- **「decision model vs generative model」不是既有学术分类** → 改用可引用的框架：Ng & Jordan 判别式/生成式、非自回归解码、能量模型、decision-focused learning。
- **必须引用而非反驳** [Generative Verifiers](https://arxiv.org/abs/2408.15240)（验证正在朝生成走）。
- **诚实增量四点**：① 判定器是**真实存在的本地非生成模型**；② **截断率随 horizon 的实测曲线**（该文献中无人测过）；③ **带设备限定的第一方延迟与成本**；④ **错误发现提前量**作为过程指标。
- **可辩护的结论集**：SAFE = 测量/刻画；CONDITIONAL = 等花费下判定器胜出、因果 (B)→(A) 传导；**不得主张** = 「Jev/Laya 优于 LLM」、新范式、普遍校准优越、新的级联架构、无条件的「每任务更便宜」。

## 附录：论文骨架（供 P12 使用）

1. **摘要**——主张：判断层比较；成本非约束；静默退化是真实代价。
2. **引言**——长线智能体的判断成本被误认为金钱问题；实测表明是延迟与窗口问题。
3. **背景与相关工作**——判别式/生成式、级联与延迟决策、LLM-as-judge、过程奖励与验证器、长线退化；**明确承认架构不新**。
4. **被测系统**——三个判定器的真实接口、实测限制、**两个 Laya 宿主**、5 个已确认缺陷（mock Jev、坏 `laya_plan`、字符规划器、静默截断窗、confidence 尺度不一致）。
5. **方法**——生成器/判定器分解、双平面、序列化器、问题库、horizon 拨盘、故障注入、统计层级、预注册。
6. **结果 A：成本不是约束**——价目表、缓存命中实测、等预算前沿 + **TOST**、Jev 交叉点随 horizon 移动。
7. **结果 B：静默退化**——截断窗口、输出冻结证明、`token_ratio(t)` 曲线、**confidence 解耦**（0.9981 错答 / 0.9989 噪声）、高基数饱和。
8. **结果 C：过程质量**——`T90`、漂移曲线、复合错误、恢复、B0 假警报。
9. **结果 D：组合架构**——A4 升级率 `esc(t)` 随 horizon 上升；微调分支。
10. **讨论**——部署建议（输入校验归 harness、证据前置、禁用 confidence 门控、批量摊销、双宿主风险）；**4096 与 512 的窗口权衡**。
11. **局限**——T3 污染存活、单机单设备、Jev 阻塞项、裁决的适用范围。
12. **可复现性**——哈希、版本、设备、时段、原始产物打包。
