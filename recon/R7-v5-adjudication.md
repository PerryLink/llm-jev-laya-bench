## 1. **核心矛盾（V5 最重要的一条，完全成立）**

### 指控

> 论文的中心主张是「静默截断 vs horizon」，但 **R14 的门 G1 拒绝每一个会触发截断的条目**（`laya_plan` strict、≤512 token、「reject never trim」），且载体被冻结在 5 行 / ≤55 token。
> → **在该电池上测出的截断率按构造为 0。** 而 R15 的 `token_ratio(t)` 曲线**需要**超出窗口的 state。
> → **同一个设计里存在两个互不相容的 state 增长模型。**

### 裁决：**成立，且这是设计层的致命缺陷。**

### 修复：**把测量拆成两个平面，并改写中心主张**

**平面 M1（主电池，有门）**：所有判定器必须**同等胜任**，因此 state 一律在窗内（≤400 token）。这里**不测截断率**，M1 测的是准确率、校准、错误发现提前量、跨物种互补性。
→ M1 上截断率恒为 0 **是设计目标，不是缺陷**——只要论文**不在此处声称截断率**。

**平面 M2（state 增长探针，无门，故意越界）**：state 规模作为**自变量**从 300 token 扫到 1,500 token。这里**不要求公平**——只测**仪器诚实性**。

**中心主张因此改写**（这是 V5 修复的实际效果，且**比原主张更强**）：

> ❌ 旧：「Laya 在长 state 下会截断。」
> ✅ 新：「**当一个本地判定模型静默丢弃输入尾部时，它的自检字段仍报告请求有效**——实测在决定性证据已被丢弃、答案已翻错的情况下，`fits:true`、`truncated` 缺失、无 warning，持续约 300 字符。」

**新主张是关于「测量仪器诚实性」的，不是关于「模型能力」的。** 这一改写带来三个好处：
1. **不需要不公平的比较**——M2 不与 LLM 对比，只与「仪器自报」对比。
2. **V5 的第二个问题自动消解**——窗口机制未被隔离不再是软肋，因为**论文不再声称机制**，只声称「自报字段与事实不符」，而这一点 R13 已用**输出冻结**（2936→5086 字符逐位相同）**独立证明**了。
3. **它把 V6 的 mock 发现并入同一主题**——mock 也是「仪器报告了一个并非测量的数字」。**两者合成论文的方法论主线：判定器评测中，仪器的自报值不可信，必须外部断言。**

### R13 §2.5/§2.4 的内部不一致（V5 指出）

V5 正确指出 R13 同时写了「真实 state 预算 >450 token」与「硬 512 token 断言」。
**裁决**：二者并不矛盾——**450 是「2 选项问题下、head 占 61 token 时的可用 state 预算」**，**512 是总序列长度的运行时钳位**。但 R13 的表述让二者看起来冲突。
**修复**：论文中一律使用 `state_tokens ≤ 512 − head_tokens − 1` 这一**公式**，并在方法章节给出本协议所用问题的实际 `head_tokens` 与由此得出的实际上限，**不再出现裸的「450」或「512」**。

## 3. **新意不足（V5：按现规格是 workshop 论文，主会会被拒）**

### 我接受这个判断，并接受 V5 给出的补救实验

**V5 的补救：跨物种错误互补性（cross-species error diversity）**

在**冻结电池**上让**所有判定器回答所有条目**，报告**配对的条目内对比**：

```
Δ_catch = P(类型化判定器捕获 | LLM 判定器判错) − P(类型化判定器捕获 | LLM 判定器判对)
```
配套报告成对误差相关性 **κ**、以及**增量检测成本**。

**为什么这能救论文**：
- **它免疫于准确率水平混淆**——不比较谁更准，只问「它们错在不在同一处」。所有「A 比 B 准」的对比都死于准确率水平差异，这个不会。
- **它解释了为什么异种第一层优于同种第一层**——而 FrugalGPT/RouteLLM/AutoMix **全都是同族（LLM 级联 LLM）**。这是**真正区别于全部先例的一点**。
- **不需要新机制**，只用在 M1 电池上多跑一遍判定（Laya 每问 3.2 ms，成本可忽略）。
- **不依赖 Jev live**——LLM vs Laya 两方即可成立。这一点在当前 Jev 阻塞的情况下**极其重要**。

→ **裁决：把跨物种错误互补性提升为论文的第二个主要贡献（与「仪器自报不可信」并列），并保留 V5 建议的次级方案**（在 ≥3 个 checkpoint 上复现窗口曲线 + 一个非 Laya 实现，如 R2 §D 记录的 `von` drop-in）作为「类级主张」的备选。

## 10. **V5 的三条审稿意见（我认为最可能命中的一条）**

V5 给出的一条，我要单独记录，因为它**同时命中三处**：

> 「Laya 判定器什么都被允许，而 LLM 判定器被禁止检索与工具使用；你自己的 A5b 让 LLM 一次批 8 个检查点，而类型化臂一个都不批；而你的 Jev 结果是一个哈希函数。」

**裁决：三处中两处是我们的，必须在任何效率数字计算之前修好：**
1. **工具/检索对称性**：明确两种判定器**可用信息相同**（同一冻结 state，均无检索、无工具），并在方法中显式声明。
2. **批处理对称性**：**类型化臂也必须批量**（Laya 批 20 时每问 3.2 ms，因此批量对它同样有利且可测）。**不得让一侧批量另一侧不批量。**
3. Jev 是 mock——已由 P4 判别器处理。
