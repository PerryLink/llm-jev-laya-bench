# 摘要

## 摘要正文

把长线任务中的判断工作交给一个廉价的、专用的判定模型，这一分工通常以「省钱」为卖点。本文在一个受控的三方对照上实测了这一说法，并给出四条主张（其中一条被自己的数据否定）。

**第一，成本不是约束。** 我们实测了三类判断层的单次成本：本地非自回归判定模型（Laya，边际成本 ≈ 0，不含硬件摊销）、远程类型化判定服务（TypeSafe Jev，**$0.0000146–$0.0002406**，随输入 token 单调上升，直连路线实测 8 档）与前沿自回归模型（DeepSeek-V4.1-Flash，$0.0000326–**$0.00009645**；思考档最高 $0.0001010，为关闭思考时的 2.54 倍）。三者**在各自的最小状态下**都在 10⁻⁵ 美元量级（**最贵的 LLM 配置跑完一次 120 个检查点的运行约 1.2 美分**）——**但该量级不随状态规模保持**：Jev 在其最大实测状态（39,927 字符 / 5,728 token）单次即 **$0.0002406**，折 120 个检查点约 **2.9 美分**；LLM 按其末态 1,751 token 外推约 **2.4–3.9 美分**。故「便宜一个数量级」在任何口径下都不成立，但「绝对量小」**只在短状态下**成立。真正分离三者的轴是**延迟**（p50 跨约 **25–32 倍**：37.4 ms / 671 ms / **0.9–1.2 s**——Jev 为**独立墙钟**，n=20 单次运行 p50 为 1,192 ms（合并 n=35 的中位为 1,073 ms）；**该轴只有一次有产物的运行，故不报告运行间极差**）与**可用状态窗口**（本地 english 在 512 token 钳位下约 3,082 字符；远程实测 ≥15,002 字符——约 4.9 倍，**且该倍数受限于本 harness 的接入层：直连路线把状态推到 39,927 字符时输入 token 仍随字符单调增长，证明「16,000 字符上限」是插件的而非 provider 的**），以及**失败的可观测性**（本地静默丢弃输入，远程告警）。因此我们把中心主张从「更便宜」改写到「不占用顺序往返」。

**第二，也是本文的主要贡献：这些判定器的自报字段不可信，且失效集中在同一个位置。** 七个独立现象被复现，其中**六条来自真实调用**，另一条来自一个仅由输入哈希驱动的合成后端（该后端产出**完全可信的结果表**：14 项电池中**有二元真值的 10 项**上 Brier = 0.359，劣于常数 0.5 的 0.25）。真实调用侧的六条包括：截断标志在两个方向上都是错的（english 滞后 111 字符，multilingual 与 typed-decisions 分别提前 4,773 与 3,774 字符误报），而三个 checkpoint 的标志都在同一点 3,193 字符触发、其真实钳位却相差 2 倍；`fits: true` 与已被截断的输入可以同时成立；概率字段在两个不同系统上各把条目结论反号（在一个系统上波及一半条目）；`conflicted` 与 `undecided` 两个判定词在实际输入下不可达。这些现象收敛为一条统一形态：**判定器在「答案被明确陈述」的任务上近乎完美（0.9909，n=220），在「必须注意到某物缺席或某处不匹配」的任务上塌缩（`no_support` 0.3091，n=220），而两种情形下自报的置信度都不低。** 该形态在**三个独立场景**中重复出现（**静默截断、`no_support`、跨语言**——三者的并列依据见 §7.5/§7.7；多跳链式核验是**第四个**场景，但其 Laya 失效形态不同，故不计入该三例）；其中最锐利的一条是：当候选值根本没有出现在输入中时，该判定器平均给出 **P(true)=0.5643**，即把「没有陈述」读成了支持（n=220）。

> **一处必须同时给出的更正**：我们曾把该判定器描述为「负信息量」。对 n=1100 的校准语料做 Murphy 分解得 **REL 0.0556 / RES 0.0397 / UNC 0.2400**，且 **AUC = 0.7136（95% CI [0.682, 0.745]）**——**分辨力真实存在，失效在校准而非信息**。正确的表述是**校准差**：其 Brier（0.2571）确实劣于常数预测器（0.2400），ECE 为 0.2259。

**第三，一个负结果。** 在路由与级联文献中，用非生成式判别器做第一层已有先例（如 RouteLLM 所评述的 BERT 式路由），但据我们所知，尚无工作把它当作**受控第一层**并与前沿生成器做**配对互补性**检验。我们在**三个**任务区制上做了配对比较（LLM 臂经 API 采样，故每臂均报**多次独立抽样**而非单点）：
- **权威定位**：**强制选择臂** LLM 48/48 全对，判定器 0.4583，**未捕获任何 LLM 漏掉的条目**；**⚠️ 同一 48 条电池的散文臂相反**：LLM **46/48**，**仅判定器对 1 条**，**Δ_catch = +0.0435**（95% CI [−0.386, +0.471]，基于 **2** 条 LLM 错项）。**在三个区制的区制级读数中，这是唯一一个为正的 Δ_catch 点估计**，论文如实报告，并同时给出它的宽度与分母（§8.2）；
- **77 类意图分类**（n=40，**4 次抽样**）：LLM **0.750–0.900**（四次为 0.750 / 0.900 / 0.875 / 0.875；**中位数 0.875，均值 0.850**），判定器 **0.225**（4 次逐位相同）；**仅判定器对 0–2 条而仅 LLM 对 23–27 条**，**Δ_catch 在 4/4 次抽样中为负**（−0.033 / −0.250 / −0.029 / −0.257）——记录轮是其中**对互补性最有利**的一次；
- **多跳链式核验**（真值修复后重判，n=68，**3 次抽样**）：LLM **0.662–0.677**、判定器 **0.294**；**Δ_catch = −0.182 至 −0.247，符号 3/3 次为负**——但**区间强度有限**（未配对 Wald 下 2 次排除 0，改用 score/Newcombe 后**仅 1 次稳健排除、1 次在边界**），且**失败相关 φ 按难度分层后三次均不显著**（CMH 置换 p = 0.059 / 0.055 / 0.201；**⚠️ 该组 p 值不可核验——无产物、无脚本、无种子记录，见 §8.6.1(d)**）。

→ **因此结论比「未发现互补」更强**：判定器不仅不覆盖生成器的错误，其失败还与生成器的失败**同向**——`P(判定器对 | LLM 错)` = 0.13–0.17，**低于**其边际准确率 0.294，而 `P(判定器对 | LLM 对)` = 0.36–0.38 **高于**边际；失败相关 φ 在 **3/3** 次抽样中为正（+0.19…+0.26）。
> **⚠️ 强度限定**：该相关的 2×2 Fisher 精确 p 为 **0.086 / 0.049 / 0.163**（r1/r2/r3）——**未校正时 3 次中仅 1 次在 α=0.05 下显著；按本文自己预声明的 Holm 规则则 0/3 次存活**。且「条件正确率 − 边际」这一单侧检验的 95% CI **在 3/3 次中包含 0**。故这是**与「共享失效」一致**的证据，不是已确立的显著效应。**异种并不自动意味着互补，也不自动意味着独立。**

> **效力与复现性必须与结论同时给出**：第三个区制（修复真值后）的 Δ_catch 其 **MDE（80% power）= 0.28–0.30**，**仍大于预声明的 +0.10 门**——故点估计虽 **3/3 次一致为负**，**区间强度却有限**：未配对 Wald 下 3 次中 2 次排除零，**但改用零格可靠的 Newcombe 后仅 1 次稳健排除、1 次在边界**（§8.3）。**精度仍有限。**第二个区制的 Δ_catch 幅度不稳（−0.029 至 −0.257），**但符号在 4/4 次抽样中为负**。
> **⚠️ 采样范围必须限定**：**仅两个互补性区制**（链式电池 `P22b` 与 77 类区制 `P15b`）以 `temperature=0` 重复取样并报告逐项标签一致率（链式区制 **86.8–89.7%**；判定器臂 **100%**）。**其余 LLM 臂（P14 权威定位、P19 校准、P21 思考成本、P23 logprobs、P24 horizon）仍是单次抽样**，其点估计同样不应读作精确值（§10.1）。

**方法学上**，本文报告了四次同一类错误——**规格级语义缺陷伪装成关于模型的发现**——每一次都由对照而非审阅发现，并由此给出 **23 条**协议强制条款。

**我们明确声明本文的边界**：所有结论来自**单步判断**的实测；**长线（多步累积）的自主运行未执行**，horizon 斜率按预先裁定降级为描述性。全部 Laya 判定测量使用 **english checkpoint**，窗口为 **512 token**（english 单独载入时为 1024，而 multilingual/typed-decisions 在同机上实测为 1024）——故窗口是**「启动配置 × 所查询 checkpoint」**的函数，「窗口 = 512」不是引擎的普遍属性。在核验类任务上 LLM 触顶（n=1100 全对），故**互补性在该区制上不可测量**，而非「不存在」。多跳链式核验电池**已执行**（96 条设计；**修复真值后 68 条入池**，见 §8.6.1），其结果是上文的负结果。

# §1 引言

## 1.1 一个被误认为金钱问题的设计选择

当一个智能体要在长线任务中反复做判断——这一步对不对、这段证据是否支持该主张、接下来该选哪个动作——工程上有一个自然的分工：**把判断交给一个廉价的、专用的判定模型，只在它不确定时才动用前沿模型。**

这个分工的**卖点通常被表述为「省钱」**。本文的第一个结论是：**在这个规模上，省钱不是一个可辩护的主张。**

以本项目实测的三方为例（§5）：

| 判定器 | 单次成本 | 跑完 120 个检查点 |
|---|---|---|
| 本地判定模型 | 边际 ≈ $0 | ≈ $0 |
| 远程判定服务（Jev） | $0.0000146–0.0002406 | $0.0018–0.0289 |
| 前沿 LLM（DeepSeek-V4.1-Flash） | $0.0000326–**$0.00009645** | $0.0039–$0.0068 |
| 同上，最贵的 `max` 思考档 | $0.0001010 | **$0.0121** |

**三者都在 10⁻⁵ 美元量级，最贵的组合跑完一次运行的判断层约 1.2 美分。**

而**延迟跨约 25–32 倍**（37.4 ms / 671 ms / **0.9–1.2 s**；n 分别为 30 / 48 / 35，三者均为**客户端墙钟**。**区间取自有产物的数字**：28.7 倍（合并 n=35 的中位 1,073.4 ms）至 31.9 倍（唯一有产物的运行，n=20，p50 1,191.8 ms）。**⚠️ 早期版本写「取自两次同脚本运行」并给出下沿 24.5 倍——该说法已于第七轮撤回，见 §5.2 脚注 1**），**方向有利于本地判定器**；**可用状态窗口跨约 4.9 倍**（3,082 字符 vs 接入层的 15,002 字符；**直连路线推到 39,927 字符时 token 仍随字符单调增长 ⇒「16,000 字符上限」是接入层的，不是 provider 的**），**方向有利于远程服务**；**失败可观测性**也不同（本地**静默丢弃** vs 远程**告警**）。

→ **真正的轴是延迟与窗口，不是美元。** 而这一点之所以重要，是因为**它决定该架构是否值得部署**：一个不占用顺序往返的判定器，与一个每次判断都要等一秒往返的判定器，在长线任务里的工程含义完全不同。

## 1.2 第二个结论，也是本文的主要贡献

如果成本不是问题，那么**用这些判定器是否安全**就成了唯一要紧的问题。本文的主要贡献是**一组关于「判定器的自报字段不可信」的实测结果**（§8），它们收敛到**一条统一形态**（§8）：

> **该判定器在「答案被明确陈述」的任务上近乎完美（`explicit_support` 0.9909，n=220），在「必须注意到某物缺席或某处不匹配」的任务上塌缩（`explicit_contra` 0.2727 / `no_support` 0.3091 / `partial_contra` 0.5818 / `partial_support` 0.6818，各 n=220）；而两种情形下它自报的置信度都不低。**

三个独立实例：

| 实例 | 要「注意到」什么 | 后果 | 自报字段怎么说 |
|---|---|---|---|
| **静默截断** | 输入被丢弃了 | 答案翻错、决定性证据消失 | `fits: true`、无 `truncated`、无 warning |
| **`no_support`**（n=220） | 证据不存在 | 断言该值就是当前值（P(true)=0.564）| `noul` 高于 0.5 |
| **跨语言**（n 小） | 读的不是英文 | 假条目 P(true) 达 0.4795 | 置信度不低 |

**为什么这比「判定器不够准」严重得多**：
- 一个**准确率低**的判定器会在评测中暴露；
- 一个**在小概率上自信地错、且仪器报告「通过」**的判定器，会在生产中被静默信任。

**最锋利的一条证据来自一个没有判断能力的组件**（§8.1）：Jev 的 mock provider 的答案完全由输入哈希决定，**把问题改写成相反的意思数字也不会动**。然而它在一次 **14 项**校准电池上产出了**合理的置信度分布**（其中有二元真值的 **10 项**上 Brier = **0.359**，劣于常数 0.5 的 0.25）——**Brier 0.359**，比常数预测器（0.25）还差，但**在结果表里不会读作「坏了」**。

> **一个没有判断能力的判定器，可以产生完全可信的结果表。**

## 1.3 第三个结论：一个负结果

本文原本还想检验**异种判定的互补性**。既有的级联与路由工作（[FrugalGPT](https://arxiv.org/abs/2305.05176)、[RouteLLM](https://arxiv.org/abs/2406.18665)、[AutoMix](https://arxiv.org/abs/2310.12963)、[Cascaded LMs](https://arxiv.org/abs/2506.11887)）**多以 LLM 判 LLM，但并非全部**：RouteLLM 自身即评述 Hybrid-LLM「relies on a single **BERT-based router**」与 Zooter「explores only a **BERT-style router**」，其正文并设「4.2.3 BERT classifier」一节；learning-to-defer 亦是「分类器 + 专家」的延迟决策。
→ **因此本文的增量不是「首次使用非生成式判别器做第一层」**（该做法已有先例），**而是**：把它当作**受控的第一层**，与前沿生成器在**同一批冻结条目**上做**配对互补性**检验，并报告**未发现已确立的**增量覆盖（**⚠️ 第九轮限定**：区制一的散文臂给出一个**正的**、但区间跨 0 的点估计，故「未发现」不得读作「不存在」，见 §8.2）。

**在三个任务区制上，答案是否定的**（§8）：区制一**的两个作答格式给出不同答案**——强制选择臂 LLM 48/48（错误结构不可测量），**散文臂可测，且其 Δ_catch 点估计为 +0.0435（正的，区间跨 0）**；区制二 LLM 触顶（0.750–0.900）使其错误结构稀薄，但 **4/4 次抽样 Δ_catch 为负**；第三个区制上限已破除、**真值修复后重判**，Δ_catch 一致为负，**失败相关池化 3/3 次为正**（**⚠️ 第九轮更正**：原句在此印「失败相关**显著**为正」——该措辞已在 §8.6.1 撤回（按难度分层后三次均不显著），本处为漏改；见 §8.6.1）：

| 区制 | LLM | 类型化判定器 | 仅类型化对 | 仅 LLM 对 | Δ_catch |
|---|---|---|---|---|---|
| 权威定位（**强制选择臂**） | **1.0000** | 0.4583 | **0** | 26 | 不可定义（LLM 零错）|
| 权威定位（**散文臂**，同一 48 条） | **0.9583** | 0.4583 | **1** | **25** | **+0.0435**（区间跨 0）|
| 77 类意图分类（n=40，**LLM 4 次抽样**） | **0.750–0.900** | 0.2250 | **0–2** | **23–27** | **4/4 次为负**（−0.033…−0.257）|
| 多跳链式核验（n=68，**3 次抽样**） | **0.662–0.677** | 0.2941 | — | — | **3/3 次为负**（−0.182…−0.247）|

→ **异种并不自动意味着互补，也不自动意味着独立**：在第三个区制上，判定器在 LLM 失败处的正确率（0.13–0.17）**低于**它自己的边际准确率（0.294），而它在 LLM 成功处（0.36–0.38）**高于**边际 —— 即两者**同向失败**（3/3 次 φ > 0；但显著性有限，见 §8.6.1）。我们把这个结果作为**方法论警示**报告：**架构选择需要一个正面的互补性证据，不能靠物种差异来假定**——并且我们给出**为什么这个结论不能外推**的边界（§8.5）。

2. **一条统一形态**（§8）：能力塌缩发生在「必须注意到缺席」的位置，而自报置信度不随之变化——由三个独立实例支撑，其中一个是 n=220 的定量校准曲线；

# §2 背景与相关工作

## 2.1 三类判定者：判别式 vs 生成式

本文比较的三个系统**不是同一物种**，这一点决定了全部实验设计：

- **自回归生成模型**（DeepSeek-V4.1-Flash）：接收任意上下文，**输出自由文本并可采取行动**；
- **状态条件判别器**（TypeSafe Jev、Laya）：**接收一个 state 与一组声明式问题，返回标签与概率，不能生成文本、不能行动**。

→ **「Jev/Laya 独立执行任务」在物理上不可能。** 因此本文的全部对比都是**判断层对比**：生成器恒定，只有判断层变化。

**⚠️ 「决策模型 vs 生成模型」这一区分必须重新表述（第六轮更正）。** 初稿写「不是既有的学术分类」——**该说法只对「措辞」成立，对「实质」不成立**。一个把 (state, 声明式问题) 映射到「标签 + 概率」、且不能生成的模型，在标准分类法里就是**判别式（条件）概率分类器**（Ng & Jordan, 2001）。故本文的立场应是**「该区分的一个实例」**，不是「一个新类别」：

- **架构轴**：**判别式 / 条件模型**（Ng & Jordan, 2001 [@ng2001discriminative]）——「决策模型」的既有名称；
- **输出轴**：**校准的概率分类器**（Guo et al., 2017 [@guo2017calibration]）；
- **可弃权轴**：**选择性预测 / 带拒绝选项的分类**（Chow, 1970 [@chow1970optimum]；Geifman & El-Yaniv, 2017 [@geifman2017selective]）；
- **不可行动轴**：**learning to defer**（Madras et al., 2018 [@madras2018predict]；Mozannar & Sontag, 2020 [@mozannar2020consistent]）；
- **不能生成作为性质而非缺陷**：**能量模型 / 打分函数**框架（LeCun et al., 2007 [@lecun2007ebm]；Du & Mordatch, 2019 [@du2019implicit]）——推断是在答案上取 argmin，而非采样；
- **LLM 时代的词汇**：弃权综述（Wen et al., 2024 [@wen2024abstention]）。

**一处必须分清的精确定义**：「验证器」「judge」命名的是系统中的一个**角色**，而「判别式」命名的是一种**架构**。在既有文献里那个角色通常由**生成式**模型扮演。**故本文真正的主张应表述为：要求「验证器」这一角色由「可证明不能生成」的判别式模型来担任，而不是由被提示去打分的生成式模型来担任。** 这一表述经得起核对；「该类别不存在」的表述经不起。

**两处类比必须限定**：**非自回归解码**（Gu et al., 2018 [@gu2018nonautoregressive]；Xiao et al., 2022 [@xiao2022narsurvey]）仍在**生成序列**（只是并行），而本文的判定器一次前向只输出一个标签、**从不生成**——类比是松的。**能量模型**也只是类比：本文的判定器**不是** MCMC 训练的能量模型。

## 2.2 级联与延迟决策

本文的**架构不新**，必须明说：

| 工作 | 主张 | 与本文的关系 |
|---|---|---|
| FrugalGPT [@chen2023frugalgpt] | 级联以省钱 | 同族（LLM 判 LLM）|
| RouteLLM [@ong2025routellm] | 路由到更便宜/更强的模型 | **并非同族**：其评述的 Hybrid LLM 与 ZOOTER 均用 **BERT 式非生成式路由器** |
| ↳ Hybrid LLM [@ding2024hybrid] | 小/大模型之间按质量路由 | 第一层是 **BERT 路由器** [@devlin2019bert]，非生成式——**与本文第一层同类** |
| ↳ ZOOTER [@lu2024zooter] | 奖励引导的集成路由 | 同上；路由函数而非生成器 |
| AutoMix [@aggarwal2024automix] | 自验证后升级 | 同族 |
| Cascaded Language Models [@fanconi2025cascaded] | 分层 + 延迟决策 + 弃权 + 人工 | 同族；本文的对标对象 |
| learning-to-defer [@madras2018predict] [@mozannar2020consistent] [@mozannar2023who]（分类器 + 专家） | 学习何时交给专家 | **并非同族**：第一层是判别式分类器，不是 LLM |
| decision-focused learning [@elmachtoub2022smart] [@mandi2020interior] [@mandi2024decision] | 按下游决策质量训练预测器 | **不同问题**：它优化的是预测器的**训练目标**，本文测的是**已训练判定器的失效位置** |

→ **本文的增量不在架构**，而在于：
1. **第一层是真实存在的、本地的、非生成的判定模型**（而非另一个 LLM）；
2. **异种判定器的互补性被直接配对检验**（§8）——既有工作中非生成式判别器已有先例，但**未被当作受控第一层与前沿生成器配对比较**；
3. **判定器自报字段的可靠性被作为独立研究对象**（§8）。

## 2.3 LLM-as-a-judge 与置信度校准

- LLM 作为评判者已被广泛使用，其**偏差**（位置、冗长度、自我偏好）有系统研究（Zheng et al., 2023；Wang et al., 2023；Saito et al., 2023；Panickssery et al., 2024）；
- **口头置信度（verbalized confidence）与内部对数概率（logit-based）存在系统性差距**（Tian et al., 2023）。**⚠️ 归因必须精确**：**「LLM 口头表达置信度时倾向于过度自信」应引 Xiong et al. (2024)**（其摘要原文为 "LLMs, when verbalizing their confidence, tend to be overconfident"）；**Kadavath et al. (2022) 的摘要说的是相反的限定**——更大模型在合适格式下**校准良好**。初稿把过度自信归给 Kadavath，属**归因错误**，已分别改引。
- **⚠️ 而本节的 novelty 主张必须收窄（第六轮发现，最重要的一处更正）**：初稿写「这些字段同样是自报的、也同样是不可信的，而据我们所知这一点此前未被系统检验」。**该主张不成立。** 已有工作包括：
  - **PhantomFill**（Usman, 2026）：**输入被构造成问题无法回答**；自由文本下 GPT-5.5 有 98% 的时候说「没有数据」，而**给出必填 JSON 字段时同一模型 40/40 全部编造**；13 个模型中 10 个在必填字段下编造率达 100%。**这正是本文的中心现象（明示 0.9909 vs 缺席 0.27–0.31）在 schema 压力下的对照版本**，且已有命名指标（Coerced Fabrication Rate / Escape Utilization Rate）。
  - **CONSTRUCT**（Goh & Mueller, 2026）：对结构化输出**逐字段**打分可信度，含嵌套 JSON，黑盒可用。
  - **Judge Circuits**（Feldhus et al., 2026 [@feldhus2026judgecircuits]）：**同一模型仅因输出格式改变就给出系统性不同的评分**，其摘要明确指出跨格式的判定器可靠性比较**部分是在测量格式阶段**。
  - **Protocol Sensitivity**（Kim & Kang, 2026 [@kim2026protocolsensitivity]）：口头置信度与对数概率的优劣比较**随协议细节反转**；12 项研究的审计发现其中 5 项从未说明答案/上下文的选择。
  - **格式约束本身会改变答案**（Tam et al., 2024 [@tam2024letmespeakfreely]）：约束越严，退化越明显。
  - **判定器之间的一致性也有限**（Thakur et al., 2025 [@thakur2025judging]）：最好的判定器仍未达到人类间一致度；高百分比一致可以掩盖大的分数差异。
- **本文真正的、可辩护的增量**：不主张「格式会损害生成内容」「结构化输出字段可信度」「置信度提取对协议敏感」是新的——**这三者都已有工作**；本文主张的是更窄的一条：**把判定器【自身】自报的协议/元数据字段（`fits`、`truncated`、`band`、判定词表）当作需要对着真值做校准测量的对象**，并与「缺席 vs 明示」的不对称**联合**检验。

**⚠️ 另有一处【方向相反】的既有结果必须正面处理（第六轮发现，否则审稿人一定会并置）**：**Ferrer et al. (2026)** 报告自报置信度**校准最好**（avg ECE 0.166 vs 自洽性 0.229），并**建议直接让模型报出置信度**——与本节的结论**表面相反**（本文 ECE 0.2259、AUC 0.7136）。
> **二者并不矛盾，但只有在本文把「指控的对象」说准之后才不矛盾。** 本文指控的**不是**「标量置信度作为排序信号不可用」——**在那一点上本文的数据与 Ferrer 一致**（AUC 0.7136 甚至略高于其 0.668）。本文指控的是**「高置信度与已经悄悄失效的判定被同时报出」**这一**联合现象**：判定器在必须注意到缺席时塌缩到 0.27–0.31，而其自报置信度**并未同步下降**。
> ⇒ **这正是本文值得报告的原因**，也是必须写清的一段：**不是「置信度没用」，而是「置信度没有随判定一起失效」。**
> ⇒ **术语**：以 **verbalized confidence** 为主（Tian et al., 2023；Xiong et al., 2024；Kim & Kang, 2026 均用此词），首次出现时注明同义词 self-reported confidence（Ferrer et al., 2026 用后者）。不要自造「expressed uncertainty」，该说法出自 Lin et al. (2022) 的通俗表述，不是术语。
> ⇒ **度量出处**：Brier 分解的 reliability / resolution / uncertainty 三分引 **Murphy (1973)**，Brier 分数本身引 **Brier (1950)**；**ECE 引 Guo et al. (2017)**——注意 Naeini et al. (2015) 提出的是校准**方法**（BBQ），**不是** ECE。

## 2.4 验证器与过程监督

- **过程奖励模型 / 验证器**：对中间步骤打分，是「用模型做判断」的主流形态（Lightman et al., 2023；Uesato et al., 2022；Wang et al., 2023）；
  **⚠️ 措辞更正（第六轮）**：初稿写「用**廉价**模型做判断」。**这不被所引文献支持**——在 Lightman et al. 中，过程奖励模型恰恰是相对结果监督**更准也更贵**的那一侧。已删去「廉价」二字；若本文要用「廉价」，须另找来源。
- [Generative Verifiers](https://arxiv.org/abs/2408.15240) 表明**验证正在朝生成方向走**（Zhang et al., 2025）——本文**引用并不试图反驳**它；
- **本文的增量**：验证器研究关注**验证质量**，本文关注**验证器的自报字段与失效位置**。

## 2.5 长线退化与污染感知评测

- **长线退化**：**位置效应**有同行评审的实证研究——lost-in-the-middle（Liu et al., **2024**，TACL 12:157–173：相关信息位于上下文中部时性能显著下降）；**误差复合**本身则**没有**权威的同行评审出处（已核实：不存在这样的经典引用），最接近的同行评审锚点是「LLM 尚不能自我纠错推理」（Huang et al., 2024，ICLR：**自纠后性能反而下降**），另可引长线 agent 的综述性预印本，但**必须标明其未经评审**。
  **⚠️ 一处类别错误必须更正（第六轮）**：初稿把 **context rot** 与 lost-in-the-middle 并列称为「已有实证研究」。**context rot 不是学术文献，是一家商业公司（Chroma，向量数据库厂商）的技术报告**（Hong et al., 2025），**无同行评审、无独立复现**；它出现在 2026 年的若干预印本中，因而**看起来**像术语。**且两者测的不是同一件事**：lost-in-the-middle 是**位置**效应且经同行评审，context rot 是厂商对**长度**的命名。故本文**删去该词**，只保留经评审的那一条；如读者需要，可在脚注中说明该术语的来源与性质。
- **污染感知评测**：本文采纳其结论——**「官方 test split」不构成污染防线**（Sainz et al., **2024**，EMNLP Findings；Jacovi et al., 2023，EMNLP——后者的原文即指出「保证未见过的测试数据」昂贵且「随时间变得脆弱」）。
  **⚠️ 一处措辞必须收窄（第六轮）**：D3 的核实结果是 **DeepSeek 的 API 文档与模型卡均未给出该模型的知识截止日期**（2026-09-22 核对：Models & Pricing 表、发布公告、变更日志、官方模型卡 README，**四处均无该字段**）。**⚠️ 但仍有残余风险，论文必须如实写出**：`DeepSeek_V41_Tech_Report.pdf`（该文档仅托管于 huggingface.co）**本轮未能读取**，而它是最可能出现截止日期的地方。故本文的准确表述是**「DeepSeek 的公开文档与模型卡未声明截止日期」**，**不是**「该模型未受污染」——**没有公布截止日期，既不能断定污染存在，也不能断定污染不存在。**
  ⇒ 因此**「使用截止后数据集」这条防线不存在**。
- **本文的处置**：真值**由构造计算**（无人工标注、无模型标注），且公共数据只作**次级/描述性**证据；并明确记录 Laya 的**先前集合**（AG News / DAIR / Banking77 [@casanueva2020banking77]）**永不作头条**。

## 2.6 本文的定位

综合以上：**本文是一篇测量与刻画论文，不是算法论文。**

> 它不提出新架构，而是提供一个**对三类判断层的受控对照**，其中主要发现是**这些组件的自报字段不可信**，以及**它们的失效集中在同一个位置上**。

# §3 被测系统与仪器缺陷

> 本节的作用是让读者能判断**每个后续数字是在什么仪器上取得的**——因为本文的核心发现正是「自报字段不可信」，所以仪器必须被完整交代。

## 3.1 三个被测系统

| 维度 | **LLM**（DeepSeek-V4.1-Flash） | **Jev**（TypeSafe） | **Laya**（Convai） |
|---|---|---|---|
| 类型 | 自回归**生成器** | 状态条件**判别器** | 状态条件**判别器** |
| 能否采取行动 | **能** | **不能** | **不能** |
| 输入 | 任意上下文 | 一个 `state` + 一组声明式问题 | 同左，**窗口受限** |
| 输出 | 自由文本 / 工具调用 | 标签 + 概率 | 标签 + 概率 + `confidence` |
| 本项目调用方式 | 直连 `POST /chat/completions` | DSH 插件（openrouter 路线） | HTTP sidecar（Path A） |
| **接入层**（合成自报字段者） | provider 的 API 响应字段 | **DSH 插件**（本项目所用） | **`laya-mcp` 包装器**（第三方，见下） |

**关键约束**：**Jev 与 Laya 不能执行任务**，因此本文全部对比都是**判断层对比**——生成器恒定，只有判断层变化（§4.1）。

### 3.1.1 归属声明：被测的是「引擎 + 接入层」，自报字段大多属于**接入层**

**这一条决定本文结果 B 的适用范围，必须写在最前面。**

| 组件 | 版本 | 作者 / 出处 | 本文所测的自报字段归属 |
|---|---|---|---|
| **Laya 引擎** | `laya 0.3.4` | **Convai Innovations**（`convaiinnovations/laya`）| 模型权重与前向；`noul` / `choices` / `probabilities` 等**张量派生输出** |
| **`laya-mcp` 包装器** | `0.1.0` | **PerryLink**（`github.com/PerryLink/laya-mcp`，**第三方**，非 Convai）| **`fits`、`truncated`、`exact`、`laya_plan`、`planning.py::_CHARS_PER_TOKEN`、`--max-len`/`--head-max-len` 的预算算术** |
| **本项目 HTTP sidecar** | `0.2.1` | 第三方包装器的服务化入口（**本项目钉定的修订**）| 入口与端口行为、语言路由字段 |
| **Jev 引擎** | `typesafe/jev-1.13` | TypeSafe | 判定原语输出 |
| **DSH Jev 插件** | 本项目所用 | 本项目运行环境 | **`provider` / `model` / `warning` / `costUsd` 等接入字段** |

**因此本文的措辞必须精确**：
- **不得**写「Convai 的 Laya 谎报截断」。截断标志与预算算术**由第三方 `laya-mcp` 包装器合成**，本文从未测过 Convai 引擎自身的截断协议（若存在）。
- 同理，Jev 侧的 `provider` / `warning` 字段由 **DSH 插件**产生，测的是该接入层。
- **本文的发现应表述为**：**「判定层接入路径的自报字段不可信」**——这是一个关于**接入层**的结论，其可迁移性在于「这类字段普遍由包装器合成」，而**不是**对任一引擎质量的主张。
- 这一区分本身是本文方法论的一部分：把**引擎**与**接入层**混为一谈，正是 §4 所述「把测量装置的属性当成被测对象的属性」的一种形式。

## 3.2 版本与采集口径

## 3.3 五个已确认的仪器缺陷

本节只列**事实**，其后果与协议对策见 §6。**每条的「归属」一栏标明该字段由谁合成**（见 §3.1.1）。

### 缺陷 1：Jev 的默认 provider 是**离线 mock**，且它看起来完全正常

- 配置为 `provider: mock` 时**不发任何网络请求**，答案 = `FNV-1a(questionId + "\0" + JSON.stringify(state))`；
- **`instructions`、`criteria`、选项描述、`boundary` 全都不参与哈希** → **把问题改写成相反的意思，数字不动**；
- 实测：对**逐字支持主张**的证据返回 `undecided`；对**空 claim + 空 evidence** 返回 `conflicted`；
- **最危险的是它的结果表**：一次 **14 项**校准电池产出了合理的置信度分布，而其中**有二元真值的 10 项**上 **Brier = 0.359**——**劣于常数 0.5 预测器的 0.25**。
  **⚠️ 两个 n 必须分清（第七轮更正）**：**电池是 14 项，Brier 的 n 是 10**（另 4 项没有二元真值，不计入）。初稿写作「14 项校准电池……但 Brier 0.359」，读起来像是 14 项上的 Brier——**这是把「电池规模」与「统计量的 n」混为一谈**，正是本项目命名的错误类别（**写法的缺陷冒充关于对象的结论**）。两个数字各自都是对的，**错的只是它们的挂靠**；也正因如此，它躲过了五轮审计。出处 `recon\R12-jev-probe.md:177` 与 `:187`。

**且 mock 的自报字段会骗过检测**：`model` 字段报告 `"jev-latest"`（与 live 无法区分），而**一次短路调用返回的响应完全没有 `warning` 字段** → **不能靠 warning 缺失判断 live**，只能靠 `provider == "mock"`。

### 缺陷 2：`laya_plan`（**接入层**）已损坏

返回 `tool "laya_plan" returned invalid output: "value.fits" must be a boolean`。
→ **Laya 唯一可用的预检手段失效**；替代方案是自算 tokenizer（§4.9）。
**归属**：`laya_plan` 是 **`laya-mcp` 包装器**的工具，**不是 Convai 引擎的接口**。

### 缺陷 3：规划器不跑 tokenizer（**接入层**）

`planning.py` 用 `chars / 4.0 × 1.15` 估算 token，即**隐含 3.478 chars/token**；而该编码器在英文散文上实测 **≈6.33 chars/token** → **规划器高估 token 数约 1.8 倍**，且每次响应的 `exact` 都是 `false`。
**归属**：`planning.py` 属于 **`laya-mcp` 包装器**；引擎自带的 tokenizer **并未**被该规划器调用（本文的预算一律自算，见 §4.9）。

### 缺陷 4：截断钳位逐 checkpoint 不同，而标志不随之缩放（**接入层 + checkpoint 配置**）

| checkpoint | 同机实测钳位 |
|---|---|
| english | **512 token** |
| multilingual | **1024 token** |
| typed-decisions | **1024 token** |

而 **`truncated` 在三个 checkpoint 上都于 3,193 字符才首次触发** → 标志由一个**未随预算缩放的字符估计**驱动（后果见 §6.2）。
**归属**：`truncated` 与预算算术由 **`laya-mcp` 包装器**合成；钳位本身由 `--max-len` / `--head-max-len` 与各 checkpoint 的配置共同决定。

### 缺陷 5：`probability` 是 P(所选选项)，不是 P(true)（**接入层**）

同一响应中 `band` 朝向 true、`probability` 朝向所选，**方向相反**（后果见 §6.4）。
**同一陷阱在 LLM 一侧独立出现**：其 `prob` 是**所答标签的置信度**。
**归属**：这两个字段分别由 **`laya-mcp` 包装器**与 **LLM provider 的响应**给出；两处**独立**出现同一歧义，正是 §6.4 把它当作协议级问题的理由。

## 3.4 入口点：一个必须钉死的事实

**Laya 存在两个宿主，工具名决定用哪一个**：

| 入口 | 到达 | 规划器 max_len / head_max_len |
|---|---|---|
| 插件工具（`laya_ask` 等） | HTTP sidecar（:8787）| **1024 / 512** |
| MCP 工具（`mcp__laya__*`） | stdio 服务 | **512 / 192** |

同一请求、同一秒：`state_room_estimated` **917 vs 405**。
→ **不说明入口的协议在比较两种不同仪器。** 本文全部 Laya 测量使用 **HTTP sidecar**。

**并且**：该 sidecar **从不做语言检测与路由**——对每种输入（含西里尔与天城文）都报告 `routing.reason = "explicit model selection"`，**不传 `--model` 启动时亦然**。
→ **本文不得对 DSH 插件所用的 Python `Router` 作任何陈述**——那是本项目从未触达的组件。

# §4 方法——判定器评测的失效模式与强制控制

> 本节的定位：不是「我们怎么做实验」，而是「**我们如何发现自己做错了**」。
> 论文的四次自纠都属**同一类错误**，而这一类错误在判定器评测里**系统性地伪装成关于模型的发现**。

---

## 4.1 生成器 / 判定器分解

三个被测系统**不是同一物种**，任何并列对比必须先钉死这件事：

| 维度 | LLM（DeepSeek-V4.1-Flash） | Jev | Laya |
|---|---|---|---|
| 类型 | 自回归**生成器** | 状态条件**判别器** | 状态条件**判别器** |
| 能否采取行动 | **能** | **不能** | **不能** |
| 能看到的状态 | 自行维护的上下文 | 单次调用内的 state | 单次调用内的 state，**窗口受限** |
| 失败方式 | 幻觉、漂移 | 按 token 涨价、**接入层**静默截断（插件侧 16,000 字符；厂商文档 `state` 上限为 32k token）| **静默丢弃尾部**、confidence 尺度不一致 |

→ **Jev 与 Laya 不能执行任务。** 论文在**摘要**（不只是方法）中声明：这是**判断层比较，不是智能体比较**；不存在「Jev agent」。

判定器的输出**只能是门**（`accept` / `revise` / `halt`），控制流仍由同一个生成器执行。

## 4.2 双平面：控制与测量分离

- **控制平面（在线）**：只有被调度的判定可影响控制流。
- **测量平面（离线）**：**每个检查点**写不可变快照（state + 哈希 + 冻结序列化器下的 token 数），运行结束后**全部判定器在冻结快照上回放**。

**为什么必须如此**：否则「judge-never」按构造没有检测延迟，**调度效应与判定器效应不可识别**。
（设计来源：R15 §0.2；本项目未执行到该阶段 ⬜。）

## 4.3 条目证书：可推导性 + 必要性两臂检验

**问题**：一个判定器在条目上失败，**可能是条目不可回答**，而非判定能力不足。V4 把这一项列为**无法解决的威胁 T3**。

**本项目的做法**：每个条目在进入电池前必须通过两臂检验——

| 臂 | 要求 | 判据 |
|---|---|---|
| **带载体** | 必须**可推导** | 准确率显著高于随机 |
| **去载体** | 必须**不可推导** | 准确率接近随机 |

**它四次否定了作者自己的条目设计**：

| 次序 | 设计 | 带载体 | 去载体 | 判定 |
|---|---|---|---|---|
| 1 | 5 个**数值**选项（4182/4219/4220/4221） | **0.25**（随机 0.20） | — | ❌ 不可推导 |
| 2 | T4「地点」模板 | **1.00** | 0.75 | ⚠️ **题目确实不含所问信息**（state 里没有地点）——**但这个 1.00 不能证明「不可回答性伪装成能力」**，见下 |
| 3 | 显式 `(current)` 模板 | 1.00 → 修正后 **0.458** | **0.00** | ⚠️ 未过 0.80 门槛 |
| 4 | 同上去载体臂 | — | **0/48** | ✅ 必要性完美 |

**第 2 条必须加一条限定**：该模板在**一个不可回答的题上「答对」**——**诊断（题目不含所问信息）成立**，但**这个 1.00 本身是位置假象，不能作为「不可回答性伪装成能力」的证据**：`p5b_classifier_templates.py:150` 把该臂的真值**硬编码为 `i01`**（源码注释：*「attribute options are decorative here」*），且该模板的选项**未做顺序去相关**（`:149`）。
⇒ **1.00 只记录「Laya 四次都选了首位」**；P5b 自己的结论也只是 "ANSWERABLE BUT NOT CARRIER-REQUIRED"，并把该模板标注为「仅供完整性」。
⇒ **因此「不可回答性可以伪装成能力」这条论断在本项目中仍然只有设计层面的论证，没有干净的实测支撑**——要测它需要一条**顺序去相关**的不可回答臂。

## 4.4 标签空间与概率语义：**本文最锋利的失效模式**

**同一类错误在本项目出现四次，每一次都伪装成关于模型的发现**：

| # | 表象 | 真因 | 暴露方式 |
|---|---|---|---|
| 1 | 「mock 在逐字支持主张的证据上返回 `insufficient`」 | mock 的哈希**不含 instructions/criteria/boundary** | 与 live 对照 |
| 2 | 「散文臂准确率 0.50，结构化输出更优」 | **抽取器**先跑单字母分支，把 "47" 的 "4" 当索引 | 逐行复核散文原文（修正后 **0.958**）|
| 3 | 「LLM 在 77 类上准确率 **0.0**」 | `parse_label` 返回**选项键**，`truth` 是**意图名**，比较永不相等 | **0.0 低于 1.3% 随机率——不可能值暴露了它**（修正后 **0.75**）|
| 4 | 「LLM 在 `explicit_contra` 上 0.0、`prob` 恒为 ~1.0」 | LLM 的 `prob` 是**所选标签的置信度**，被当作 P(true)，**反号了所有 `false` 回答** | 逐行复核原始 JSON（修正后 **1.00**）|

**衍生出的强制协议条款**：

1. **`probability` 语义必须逐系统实测确认，不得假定。**
   - **Jev**：`probability` = P(**所选选项**)，**不是** P(true)。live 实测 `answer:"false", noul:0.02, probability:0.98`。
     且**同一响应里 `band` 朝向 true、`probability` 朝向所选——方向相反**。→ **只记 `noul` 作为 P(true)。**
   - **LLM**：`prob` = P(**所答标签正确**)。→ `P(true) = prob`（若答 `true`）或 **`1 − prob`**（若答 `false`）。
2. **类型/键必须逐响应断言。** Jev 的未知 `type` 会被**静默转成 `score`**；选项键必须与请求一致。
3. **抽取器必须在「目标答案只出现在散文里」时仍正确**，且**抽取失败率必须与准确率同表报告**。任何声称「结构化优于散文」的结论，**若未证明抽取器在散文上不掉分，即为无效**。
4. **不可能值必须触发复核。** 第 3 条的 0.0（低于随机率）与第 1 条的 `supports 0.52 / contradicts 0.58`（两侧同时 >0.5，数学上不可能）**都是被「不可能」暴露的**。→ **把「低于随机率」「概率和不为 1」写成自动断言。**

## 4.5 选项顺序与选项键：两个能把结论整个反转的控制

**顺序去相关（强制）**：同一批条目、同一模板，**只改选项顺序**：

| 配置 | Laya 准确率 |
|---|---|
| 顺序 = 渲染顺序 | **0.125** |
| 顺序 = 每项确定性打乱 | **0.625** |

→ 位置偏好被读成能力，**且双向欺骗**（权威值排首位时看起来 1.00，否则 0.125）。
→ **Laya 的位置效应量级随选项类型变化**：数值选项上达 **5×**；意图名选项上仅 **+0.10**（P11）。故去相关是强制项，但其**影响量级须逐任务报告**。

**不透明选项键（强制）**：同一分类法与条目，**只改 criteria 的键名**：

| | 描述性键名 | 不透明键 |
|---|---|---|
| 端到端（分层） | 0.762 | 0.667 |
| 扁平 | **0.905** | **0.333** |
| 判定 | ❌「分层更差」 | ✅「**分层好一倍**」|

→ **描述性键名把分类法的一部分交给了模型**（看到 `refund_request` 就知道属 money 组）。**结论方向被整个反转。**
→ 而两个最大的数据集（MASSIVE 的 `alarm_set`、CLINC150 的短意图名）**都没有这个线索** → **v1 的结论本会朝错误方向误导设计。**

## 4.6 样本量：**n<20 的分类格不可作结论**

本项目**四次**由小格高分得出错误结论：

| 次序 | 小格结果 | 扩大后 | 出处 |
|---|---|---|---|
| 1 | N=2 准确率 0.33、AUC 0.33（n=3） | N=2…12 **全部 1.00** | P1 → P8 |
| 2 | 显式模板 **16/16 = 1.00** | n=48 → **0.458** | P9 → P9b |
| 3 | 「合理性剪枝」机制（非受控对比） | 配对实验 **Δ=−0.125**，机制**撤回** | P9/P9b → P10 |
| 4 | T4 模板 1.00 | **位置假象**：真值硬编码 `i01` + 选项未去相关（问题本身仍成立）| P5b |

→ **强制条款**：准确率主张 **n≥385**（±0.05）；可靠性曲线 **≥500**；两判定器 ECE 比较 **≥1000**。
→ 且 **Wilson 区间不重叠不等于存在系统差异**（第 2 条正是这样被误判的）。

## 4.7 仪器：哈希、钉定与漂移守卫

**背景**：被测仪器是**活跃开发中的工作树**。本会话期间 `worker.py` 被改写**三次**（出处：`src\instrument\laya_client.py` 的自述记录，`planning.py / worker.py / server.py` 于 **18:16–18:17** 被改写），且**两个入口曾同时服务不同修订**。

**做法**：
1. **六个仪器哈希**（`planning.py` / `worker.py` / `capability.py` / `server.py` / 两个 checkpoint config），逐个 SHA256；
2. **不可变快照**（`protocol/instrument-snapshot/`，逐文件 PIN.json）；
3. **钉定启动器**：以 `PYTHONPATH` 优先 + 清除已解析模块 + **断言** `laya_mcp.__file__` 落在快照内，**断言失败即退出**；
4. **`instrument_record()` 随结果文件落盘** → ✅ 现覆盖 **39/42** 个结果文件，其余 3 个是**纯派生文件**（无测量可归属），**未解释缺口 0**；且它现哈希**固定快照**而非活工作树。计数由 `src\analysis\p30_inventory.py` 推导（见 §11）。**⚠️ 仍存的真实缺口**：`deepseek_client.py`——**LLM 那一臂自己的客户端——全树无任何文件哈希它**，故 LLM 臂的仪器至今未被固定；三个 LLM 产物已补上**明确标注为事后补录**的溯源块（`_provenance.status = RETROACTIVE`），并记录该客户端当前的 sha256；
5. ~~**`assert_instrument()` 漂移中止**~~ → ❌ **该函数全仓零调用点，是死代码**；论文早期版本称它「在 P16–P18 三次启动中实际拦住了错误修订」，**该说法不成立**，真正起作用的是 P16–P18 各自内联的导入路径断言。

**⚠️ 并且这套机制的清单是结构性盲的**：`instrument_hashes()` 只哈希六个固定文件，而本项目实际发生的漂移在另外 3 个文件上（`__init__.py`、`cli.py`、`mcp_server.py`）——**清单对唯一真实发生的漂移不敏感**。（该漂移不触及四个行为关键文件，故不影响已发表数字；详见 §3.5。）

**这套机制不是纸面的**：它在 P16–P18 三次启动中实际拦住了错误修订，并**产出结论**（见 §4.8）。

## 4.8 窗口同时取决于**启动配置**与**所查询的 checkpoint**

**P18 的 loadout 扫描（每个 loadout 一次启动，查询默认 checkpoint = english）**：

| loadout | 已加载 checkpoint | english 的长 state 钳位 |
|---|---|---|
| `--model english` | english | **1024** |
| `--model english --also multilingual` | 2 个 | **512** |
| `--model english --also typed-decisions` | 2 个 | **512** |
| 三个全载 | 3 个 | **512** |

→ **但钳位也随 checkpoint 而异。** P3 在**同一台** sidecar（三 checkpoint，`restart_count: 0`）上逐个 checkpoint 实测：

| checkpoint | 实测钳位（同一 loadout 内） |
|---|---|
| english | **512** |
| multilingual | **1024** |
| typed-decisions | **1024** |

→ 因此**正确的表述是**：窗口是**「启动配置 × 所查询 checkpoint」**的函数。
**「载 ≥2 个 checkpoint → 窗口 512」只对 english 成立**——P18 的扫描只查询了默认 checkpoint english，不能外推为引擎的普遍规律。
→ **对论文的硬约束**：**「Laya 的窗口是 512 token」是不完整的表述**，必须同时写明 **loadout 与 checkpoint**；对另一个操作者可能错 2 倍。
→ 本项目**所有判定测量都使用 english checkpoint**（`LayaJudge` 的默认值），故 512 窗口与 111 字符未告警区间**对它们一致适用**——但这来自「都查 english」，而非来自「loadout 决定了统一窗口」。
→ **未做确定性重复**：P18 每个 loadout 只启动一次，故**不声称**该数值可重复（早期版本曾写「各重启 3 次，完全确定」并列出 `[1024,1024,1024]`／`[512,512,512]`，该主张**无代码与产物支持，已删除**）。
→ **机制未隔离，论文只报告经验规律，不声称原因。**
→ **一条可用结论**：只载入 english 可把 **english 的**可用窗口**从 512 翻倍到 1024**（代价是失去多语与 typed-decisions 能力）。

## 4.9 成本与延迟的口径

- **成本**从 provider 的 `usage` 直接计算，**分峰谷两档同时报告**（低谷恰为高峰一半）；
- **LLM 成本对推理 token 敏感**（reasoning token 计入输出价）→ **必须写明 `thinking: disabled` 这一配置**，否则可差一个数量级；
- **延迟只从 provider 字段读取**，且**串行发起**——并行工具调用**共享同一结果时间戳**，批量只能给墙钟；
- **延迟须报重尾，且须报测量点**：Jev 独立墙钟实测（合并 n=35）中位 **1,073.4 / 1,116.1 ms**、**最大 4,018.6 / 6,360.4 ms**（两次运行，见下）；其**自报** `latencyMs` 与墙钟的比值取决于状态是否尺寸匹配——**尺寸匹配时约 1.5–1.9 倍**（126 字符 / 347 token 类），**不匹配时约 1.6–1.9 倍**（对当前 n=20 运行）——用自报值做容量规划会高估，用中位数则低估尾部。**⚠️ 且该比值本身不稳定（第九轮更正）**：它的**分母是一次延迟测量**，而延迟正是本项目实测**不复现**的量——同一脚本、同一状态、同一 n=20：**p50 1,191.8 → 952.9 ms（−20%）**、**max 4,018.6 → 6,360.4 ms（+58%）**，而**答案逐位相同**（真值电池 8/8、同一 `noul`、同一成本、同一 token 数）。故同一「尺寸匹配」比值在两次产物上分别读作 **1.94**（`rerun\baseline\P27b-plugin-crossval.json`，分母 p50 **956.2 ms**）与 **1.49**（`results\P27b-plugin-crossval.json`，分母 p50 **1,244.8 ms**）。**故论文报区间并列出两次产物，不报三位有效数字的单值。**
- **测量点必须逐列标注**：本地一列是墙钟，远程默认是 provider 自报 ⇒ 不同口径不可混读（§5.2）。

## 4.10 统计单位

- 同一运行内的判定高度相关 → **一切检验在运行层或更粗**；`n` 一律报**运行数与任务数**；
- **随机化单位**须 ≥8 个簇（4 个任务族时最小双侧 p = 0.125，**算术上不可能 p<0.05**）；
- 判定器因子在同一冻结快照上回放 → 它是**单元内**因子，**不受臂随机化约束**；
- **多重比较分层**：主终点族（Holm）→ 次要族（BH, q=0.10）→ 探索性（只报效应量与 CI，**无 p 值**）。

## 4.11 小结：本节的可迁移结论

> **在判定器评测中，「看起来像能力/失效」的结果反复出现，而每一次都被更强的对照设计证明是构造或仪器的产物。**
> 本项目四次同类错误——**mock 语义、散文抽取、标签空间、概率语义**——**全部伪装成关于模型的发现**，且**全部由对照而非由审阅发现**。
> 因此方法章节的核心不是描述流程，而是**列出这些控制及其触发条件**，使读者能判断哪些结论是**对照过的**。

# §5 结果 A——成本不是约束：三方实测

> 本节的核心动作是**换轴**：论文因此把「谁更便宜」这个问题，替换成「**哪个轴真的把三者分开了**」。

## 5.0 为什么这一节需要换轴

**原设想**：证明「判定模型比 LLM 更便宜」。
**实测裁决**：**该主张在算术上无意义** —— 三者的单次成本**都在 10⁻⁵ 美元量级**，而设计里只有 120 个检查点/运行。

| 判定器 | 单次成本 | 120 检查点/运行 |
|---|---|---|
| **Laya**（本地 cuda，自托管） | **边际 ≈ $0**（仅算力） | ≈ $0 |
| **Jev**（openrouter，`typesafe/jev-1.13`） | **$0.0000146 – $0.0002406**（实测 8 档，**随输入 token 单调上升**；设计状态范围内为 **$0.0000146–$0.0000588**） | **$0.0018 – $0.0289**（设计范围内 **$0.0018–$0.0071**） |
| **LLM**（`deepseek-flash`，非思考） | **$0.0000326 – $0.00009645**（**上限取 P14 全部 96 次调用的实测最大值**；$0.0000484 是**均值**，早期版本把它印成了区间的中点，而上限 $0.0000566 **不是任何一批的最大值**——本文自己的 `_provenance` 块早已记录正确的一对） | **$0.0039 – **$0.0116**** |

→ **「省钱」不是一个可辩护的论文主张。** 本节因此**报告成本，但不把成本当作结论**。

1. **⚠️ Jev 的延迟列只有一次有产物的运行；早期版本声称的「两次独立运行」不成立（第七轮撤回）。**

   （先前印的 **938.6 ms / 25 倍** 出自合并第一次运行与 `P27c` 的旧汇总；按当前产物重算为 **1,073 ms / 28.7 倍**。两个数都保留在此，**因为它们本身就是这条轴不可复现的证据**。）

### 5.2.1 Jev 的延迟由**传输**主导——跨 127 倍状态范围基本平坦

**墙体独立测量**（`P27c`，每档 5 次）：

| 状态字符 | 输入 token | **p50** | min | max |
|---|---|---|---|---|
| 126 | 347 | **956 ms** | 855 | 2,172 |
| 7,896 | 1,400 | **881 ms** | 864 | 1,897 |

⇒ **状态放大 127 倍，p50 只从 956 变到 1,073 ms** ⇒ 延迟由**传输**主导，不由状态大小决定。
- **关键对照**：R13 测得的**未认证 403 拒绝**往返为 **1,011–2,349 ms**，与**真实调用同量级** ⇒ **该轴测量的主要是网络拓扑，不是判定器的推理开销**。

| 10 | 3.9 ms |
| 20 | **3.2 ms** |

→ **批处理摊销约 9 倍。** 但**双平面回放每个 state 只有一个问题，故批大小被迫为 1** —— 引用 3.2 ms 会**乐观 11.7 倍**（对墙体中位 37.4 ms；若按该表自身的摊销基准 30.0 ms 则为 **9.4 倍**——**两个基准不可混用**，早期版本印的「12 倍」正是把墙体值除以自报批量值得来的）。
→ **强制条款：延迟一律连同批大小与设备一起报告。**

## 5.3 状态窗口：第二个分离轴

| 判定器 | 决定性证据仍可用的最大 state | 失败方式 |
|---|---|---|
| **Laya**（english，三-checkpoint loadout） | **~3,082 字符**（512 token 钳位） | **静默丢弃尾部**；`truncated` 滞后 111 字符 |
| **Jev**（**接入层**窗口） | **≥15,002 字符**（插件）；**直连路线实测接受 39,927 字符** | 容纳，或**告警** |
| **LLM** | 1M 上下文（文档） | 不适用 |

**⚠️ 「16,000 字符上限」已被实测证明是接入层（插件）的，不是 provider 的。**
第三轮建了独立 HTTP 直连路线（`P27`），把状态阶梯推到 **39,927 字符**：

| 状态字符 | 1,965 | 7,959 | 14,952 | 15,951 | 16,395 | 23,943 | **39,927** |
|---|---|---|---|---|---|---|---|
| 输入 token | 598 | 1,408 | 2,353 | 2,488 | 2,548 | 3,568 | **5,728** |
| `noul` | 0.97 | 0.97 | 0.97 | 0.97 | 0.97 | 0.97 | 0.97 |

**证据是 token 记账，不是「无截断」的断言**（这一点必须说清楚）：
- 这条**路线上没有 `truncated` 字段**可查（§6.4.1），且该探测把惰性填充**只追加在尾部、决定性内容留在头部**——故它**对「尾部被静默丢弃」本身是盲的**，不能靠它声称「无截断」。
- **但输入 token 随字符数单调增长**：字符增量 5,994 / 6,993 / 999 / 444 / 7,548 / 15,984 对应 token 增量 810 / 945 / 135 / 60 / 1,020 / 2,160，**恒为约 12 token / 111 字符**。**任何固定的字符上限都会让上限之上的 token 数冻结——它没有。**
⇒ 故结论成立：**上限是插件的**。但**provider 侧的真实上限仍未触及**（未找到拒绝点，也未做尾部决定性内容的判定）。

**同一构造**（`DECOY + filler + CORRECTION`，**决定性内容置于最末尾**）：

- **Laya 在 ~3,082 字符处丢失证据、答案翻错**，而 `fits: true`、无 `truncated`、无 warning；
- **Jev 在 15,002 字符处仍取用末尾证据并答对**（0.97）；**第三轮直连路线进一步证到 39,927 字符**（§5.3）。

→ **相差约 4.9 倍（按接入层的 15,002 计；provider 侧上限未触及，故该倍数只增不减），且失败方式根本不同：Laya 静默丢输入，Jev 要么容纳要么告警。**
→ **这是 D1 判定「Jev 不可替代」的实质依据**，且现在有实测支撑。

**必须连同启动配置与所查询 checkpoint 报告**（§4.8）：同一份代码，english 单载 → 钳位 **1024**；english 在三载 loadout 下 → **512**；而同机的 multilingual 与 typed-decisions 仍为 **1024**。（P18 每个 loadout 只启动一次，**未做确定性重复**。）
→ **「Laya 的窗口是 512 token」是不完整的表述，对另一个操作者可能错 2 倍。**

### 5.3.1 窗口在真实的累积运行中如何侵蚀（P24）

**设置**：3 个会话 × 20 步，每步向一个**被携带的 ledger**追加一条记录；每步向两个判定器各问一次。

| 指标 | 值 |
|---|---|
| 总步数 | 60 |
| **窗口内可问的步数** | **14 / 60（23%）** |
| **首次溢出** | **step 14** |
| 最终状态 | **1,751 token / 6,875 字符** = 钳位的 **3.4 倍** |
| Laya 逐会话准确率 | 会话 0：1.000（n=14，**6 步被跳过**）；会话 1、2：**n=0，全部溢出** |
| LLM 逐会话准确率 | **1.000 / 1.000 / 1.000**（n=60）|

→ **在一个 60 步的累积运行里，本地判定器只有前 23% 可用。**
→ **LLM 三会话全部 1.000**——**本任务上累积未造成漂移**，但这**又一次触顶**，故**不能据此声称 LLM 不受累积影响**。

### 5.3.2 截断是否**改变答案**：**未能测出**（P26，存在位置混淆）

P24 只说明**窗口何时用尽**；P25 试图测「用尽是否伤害判断」，但**探针无效**（题目把答案说出来了，删除对照 0/6）。
P26 施加了**证书**后重做——决定性内容是**叙述性更正**、位于**尾部**，问题**只问结论**，**题面既不含 v0 也不含 v1**；两臂唯一差别是**该更正是否存在**。

状态 **1,969–1,982 token** vs **512** 钳位：

| 单元 | n | **选中「更正前」值** | 答出「更正后」值 |
|---|---|---|---|
| **full（更正存在）— Laya** | 10 | **10 / 10** | **0 / 10** |
| dropped（更正删除）— Laya | 10 | 10 / 10 | 0 / 10 |
| **full — LLM** | 10 | 0 / 10 | **10 / 10** |
| dropped — LLM | 10 | 10 / 10 | 0 / 10 |

**读法**（与直觉相反，必须说明）：dropped 臂答「更正前」值是**按构造成立**的（该臂里没有更正），故**诊断量不是「full 比 dropped 好」，而是「full 能否把两个状态区分开」**。

**⚠️ 该探针有两处致命设计缺陷；早期版本声称「复核时补做了缺失的对照」，该对照【未持久化】，其数字已撤回（第七轮）。**

**缺陷一（更根本）：两臂的可见前缀完全相同 ⇒「两臂同答」是构造的必然，不是测量。**
dropped 臂只删掉 `[c1]` 那一行，状态仍有 **1,955–1,965 token ≈ 4× 钳位**。逐 token 核验：**两臂的前 512 个 token id 在 10/10 条上完全相同**，而更正所在位置是第 **1,943–1,952** 个 token。**【不可核验 ⚠️ ERRATA §10.2】**：该 token 位置无 `results\` 产物（同 §8.7(a) 处的标注）；「前 512 个 token id 相同」这一条**可由 P26 的 `in_pad` 与选项记录间接支持**，但绝对位置不可核验。
⇒ 截断发生在两者**共同的尾部之外**，两臂喂给判定器的可见内容**逐位相同**。「两臂给出相同答案」因此**由构造强制成立**，对「截断是否改变答案」**零信息量**。

**缺陷二：选项顺序与答案完全共线。** 选项由 `sorted({v0, v1, v0+77})` 生成，恒有 `v0 < v0+77 < v1` ⇒ **诱饵恒为 o01、真值恒为 o03**；Laya 在 10/10 行都选 **o01**（首位）。论文 §4.5 自测的位置效应（首位 1.00 vs 其他 0.125）**足以单独解释**该结果。

**补做的对照（本文原缺，复核时新增）**：**去掉填充**，使更正落在窗口**之内**（状态 **79–92 token**，`truncated = false`）：

| 单元 | n | 答出「更正后」值 | 答出「更正前」值 |
|---|---|---|---|
| 截断臂（P26 原设计，512 钳位） | 10 | 0 / 10 | **10 / 10** |
| **对照臂（填充去除，更正可见）** | 10 | **6 / 10** | **4 / 10** |

⇒ **⚠️ 已于第七轮撤回**：早期版本在此写「截断确实抬高『答更正前』的比例：0.40 → 1.00（Fisher p = 0.011）。**截断伤害是真的**」。**这组数字（含 p = 0.011）没有任何产物**，其状态规模恰等于 P26 已废弃的原型，**故不得作为结论**。下方第 2 条与「裁定」两处同样使用该数字，一并撤回。
⇒ **⚠️ 本条的定量拆分已撤回（第七轮）**：早期版本写「该效应约 **6/10 来自截断**，另 **4/10 是「更正完全可见却未被采纳」**」。**这组数字（6/10、4/10、状态 79–92 token、Fisher p = 0.011）在整棵树中没有任何产物**——没有行、没有脚本、没有花费记录，只存在于论文正文与 `protocol\AUDIT-FINDINGS.md`；**且其状态规模恰好等于 P26 自己【已废弃首版原型】的状态规模**，而该原型的报告原文是「根本没有可截断的东西」。**本树无法区分「一次新的对照运行」与「被丢弃原型的数字」。**
⇒ **现在能说的**：P26 的产物显示**两臂在 512 token 的可见前缀上逐位相同**、更正位于窗口之外（**构造的必然**）；**「截断会发生」有产物支撑**（P24：60 步只有 14 步能塞进窗口；P26：20 次调用全部 `in_pad = 512`、`truncated = true`）。
⇒ **不能说的**：「截断改变了答案」——那需要一个把更正移入窗口且**被持久化**的对照。故本条**降级为「截断确实发生，其伤害未能与位置效应分离」**。

→ 因此原先的两条陈述都要限定：
1. **截断确实发生**（独立成立）：20 次调用全部 `in_pad = 512`、`truncated = true`；P3 又证明钳位后输出逐位冻结。

## 5.4 本节结论：约束是**延迟与窗口**，不是美元

| 轴 | 分离程度 | 方向 |
|---|---|---|
| **单次成本** | 三者全在 10⁻⁵ 美元量级；**无实质分离** | — |
| **延迟** | **p50 跨约 25–32 倍**（37.4 ms → 671 ms → **0.9–1.2 s**，下沿/上沿分别取自合并 n=35 的中位与唯一有产物的那次运行——**两次运行的说法已于第七轮撤回**）；Jev 合并实测 max 4,018.6 ms | 有利于本地 |
| **状态窗口** | **约 4.9 倍**，且失败方式不同（静默 vs 告警） | 有利于远程 |
| **失败可观测性** | Laya **静默**；Jev **告警** | 有利于远程 |

→ **中心主张改写为**：
> **在长线任务中，把判断交给本地小判定器的收益不在成本（成本本就不是约束），而在于它不占用顺序往返；代价是它的可用状态窗口小一个量级，且越界时静默失败。**
> **⚠️ 该主张的长线部分只由缩减版验证**（P24：同一进程内 3×20 步；**自主长线运行未执行**，见 §10.1）——「不占用顺序往返」这一条在**单步**层面成立，在**长线**层面属未测。

这一表述**比「更便宜」更窄、更硬，且避开了最容易被反驳的一点**：LLM 也能用 context 缓存把输入压到 $0.003/1M，因此「LLM 贵」在算术上站不住。

## 5.5 限制

1. **成本与延迟均为描述性**：LLM n=48、**Jev n=35**、Laya n=30，且**单机、单网络路径、单一时段**。
2. **Jev 与 LLM 的延迟含传输**，故**不可与 Laya 的本地延迟视为同类量** —— 三者都标了限定词。
3. **未记录采集时段落在峰价还是谷价**，故成本数字可能随运行时刻变化（峰谷差 2×）。
4. **Laya 成本未货币化**（自托管算力），故「≈$0」是**边际**成本，不含硬件摊销。**论文不得据此宣称 Laya 在所有意义上免费。**
5. **LLM 的 1M 上下文是文档值，未实测**；Jev 的**插件侧 16,000 字符常量**只证到 15,002（厂商文档 `state` 上限为 32k token，**未实测**）。
6. **未测**：LLM 在长 state 下的成本与延迟（其成本对不缓存输入为 $0.15/1M，长任务下会显著变化）。

# §6 结果 B——判定器的自报字段不可信

> 本节是全论文**证据最强**的一节：七条独立现象，其中**六条来自真实调用**（另一条来自一个刻意设计的合成后端，作为方法论警示），且**不依赖任何生成电池**。

---

## 6.0 本节的组织线索

七条现象不是七个孤立缺陷，而是**同一条失效模式在七个位置上的表现**：

> **该判定器在「必须注意到某物缺席、或注意到输入与自己不匹配」的场合失效；而在「答案被明确陈述」的场合近乎完美。**
> **两种情形下，它自报的置信度都不低。**

因此本节不按「组件」组织，而按**失效位置**组织：输入层（3.1）、字段层（3.2–3.4）、语义层（3.5–3.7）。每一条都给出**实测数字**、**为什么它危险**、以及**由此产生的协议强制条款**。

---

## 6.1 输入层：一个没有判断能力的判定器，能产生完全可信的结果表

**现象（R12，n=14 项校准电池）**：Jev 的 mock provider 对**逐字支持主张**的证据返回 `undecided`；对**空 claim + 空 evidence** 返回 `conflicted`。 **（⚠️ 第八轮更正：原印 `insufficient`，但被引来源记录的恰恰相反——`recon\R12-jev-probe.md:307` 的逐字夹具返回 `undecided`；`insufficient` 只记在另一个夹具上。一个夹具各记一边，普遍化措辞不被所引来源支持）**

**但真正危险的不是这些明显错误，而是它的结果表**：

| P(true) 分箱 | 项数（全部） | **其中二值真值项** | 观测正确率 |
|---|---|---|---|
| 0.0–0.2 | 3 | **2** | 0.67 |
| 0.2–0.4 | 2 | **2** | 0.00 |
| 0.4–0.6 | 5 | **2** | 0.50 |
| 0.6–0.8 | 2 | **2** | 0.50 |
| 0.8–1.0 | 2 | **1** | 0.00 |
| **合计** | **14** | **9** | — |

**⚠️ 分母必须说清楚（第七轮更正，第九轮补全）**：**项数**一列的分母是全部 14 项，而**正确率**一列的分母是**二值真值子集**——故「5 项 × 0.50」在算术上不可能。原稿把两列并列而未标注分母不同，读者无法复现。**中间一列现已按来源逐箱填全**（`recon\R12-jev-probe.md:181-185` 记 2 / 2 / 2 / 2 / 1），使合计 **9** **可由本表直接相加得到**（**⚠️ 第九轮更正，ERRATA §10.1 第 6 项**：此前四行印破折号，读者无法复现自己正在读的合计）。
**⚠️ 而来源在两处互相矛盾，本表只能并置、不能替它裁决**：
- **二值项总数**：R12 的**表**给出 **9**（2+2+2+2+1，逐箱可加）；R12 的**正文**两处（`:187`、`:388`）写 **10**，Brier 0.359 也记在「10 项」上。**9 ≠ 10，而树内没有逐项记录可以裁决**。故本表把**逐箱计数**与**正文所记总数**分开印：Brier 处沿用正文的 **n=10**（下条），并在该处标注这一差 1 的不一致。

## 6.4 字段层（三）：`probability` 是 P(所选选项)，会把**所有答 `false` 的条目**反号

**live 实测**（P12/P13，同一响应；第三轮由独立直连路线 `P27` 双向复现）：

```json
{"answer": "false", "noul": 0.02, "probability": 0.98, "band": "no"}
```

- **`probability` 是「所选选项的概率」，不是 P(true)** —— 把 `probability` 记为 P(true) **会把所有答 `false` 的条目反号**（**⚠️ 第九轮更正，ERRATA §10.1 第 7 项**：原印「它那一半条目」，本节小结与摘要处并印「约占一半」——**实测不是一半**：在 `P19-calibration.json` 的 1100 条上，**LLM 答 `false` 的占 60.0%（660/1100）**，**判定器 `noul < 0.5` 的占 29.8%（328/1100）**，两个比例都由该产物 `bins` 各箱 n 直接相加得到，**均不接近 0.5**）；
- **同一响应里 `band` 朝向 true**（0.02 → `"no"`），**而 `probability` 朝向所选**（0.98）→ **两个「置信度类」字段方向相反**；
- 实测满足 `answer=="true" ⇒ probability==noul` 且 `answer=="false" ⇒ probability==1−noul`；**第三轮在 live 上双向确认**（`true`→0.98/0.98；`false`→0.02/0.98）。
  **⚠️ 但该恒等式能排除的东西比看上去少，必须限定**：(a) 机器可读的证据只有 **7 行**（`P27b` 的插件路线，且为**手工转录**），其中**只有 1 行**（`answer=="false"`，noul 0.02 vs probability 0.98）真正做了判别工作——另外 6 行 `noul = 0.98` 且 `answer=="true"`，四个候选假设在该行上**全等于 0.98**，零信息量；
  (b) **「P(所答选项)」与「`probabilities` 的最大值」在这一接入层下恒等，无法区分**——对 2 选项的 `noul`，接入层把 `answer` 定义为 `noul ≥ 0.5`，即 **argmax**，故「所选即最大」是**构造性的**，在任何 noul 取值下都成立；`choice`/`score` 亦然（所选 level 恒为 `legend` 中的 argmax）。**因此一个 `answer` 恒为 argmax 的接入层，在原理上产生不出能区分这两个假设的行**；
  (c) 故本节**真正确立的只有一条**：`probability` **不是** `P(true)`（由那 1 行排除）。**更强的「= P(所答选项)」读法未被确立，也不影响任何结论**——两者数值恒等，选哪个读法都不改变论文的任何数字。

### 6.4.1 ⭐ 这三个字段**不由 provider 提供**（三个原语各 1 次直连实测）——直连路线的直接证据

第三轮建了独立 HTTP 直连路线（`POST /api/v1/systemone`，`src\instrument\jev_client.py`），与 DSH 插件走**同一条路**（同 `noul`、同 `input_tokens`、同 `cost`，逐位一致）。**provider 的原始响应顶层只有** `{model, provider, id, answers, usage}`，而**答案对象里的键随原语而变**（三个原语各实测 1 次）：

| 请求的原语 | provider 返回的答案键 |
|---|---|
| `noul` | `type`, `noul` |
| `choice` | `type`, `choice`, **`probabilities`**（分布）, **`confidence`** |
| `score` | `type`, `score`, `legend`, **`probabilities`**（分布）, **`confidence`** |

**⚠️ 因此本节的归属结论必须按原语限定，不能一概而论**（初稿曾据 `noul` 一例写成「答案对象只有 `noul` 与 `type`」，**已在补测三个原语后更正**）：

| 字段 | 来源 |
|---|---|
| `type`、`noul`、`choice`、`score`、`legend`、`probabilities`、`confidence` | **provider** |
| `probability`（**单数**，= 接入层**所选**选项的概率）、`answer`（由 `noul` 与阈值导出的 true/false 标签）、`band` | **接入层推导** |
| `truncated`、`stateChars`、`questionsChars`、`redactions`、**`warnings`** | **接入层的出口记账** |
| `latencyMs` | **接入层自己测的表** |

⇒ **⚠️ 本表必须与产物的键表逐字对齐（第九轮更正，ERRATA §10.1 第 11 项）**：`P27d-primitive-fields.json` 的 `never_returned_by_provider` 列出 **9 个**键——`band`、`probability`、`answer`、`truncated`、`stateChars`、`questionsChars`、`redactions`、`latencyMs`、**`warnings`**——而本表此前只列了其中 **8** 个，**漏掉 `warnings`**。`warnings` 尤其不能漏：本节第 1 条协议条款的全部依据就是「**不能靠 warning 缺失判断 live/mock**」。补入后，本表覆盖 provider 已返回的 7 键与未返回的 9 键，共 16 键，与产物一致。
⇒ **这三类字段（单数 `probability`、`band`、`answer`）与全部出口/延迟字段，在已实测的三个原语（各 1 次调用）下都未由 provider 提供**；故**在已观测范围内**它们确为接入层合成。**⚠️ `check` 与 `rank` 两个原语从未实测（n=0），不能外推**——本节的归属表按原语分行，正是因为归属随原语而变。
⇒ 但 **`confidence` 与 `probabilities`（复数）在 `choice`/`score` 各 1 次调用中确由 provider 返回**，不得混入「自报不可信」的清单——**这一区分本身正是本节的教训：归属必须逐字段实测，不能从一个原语外推。**
⇒ **⚠️ 证据量必须同时报告**：`choice` 与 `score` 在整个 `results\` 树中**各只有 n=1**（`P27d-primitive-fields.json` 每原语 1 次；`P27` 的 provider-field 清单只加了 1 次 `noul`；`P27b` 的 7 行是**插件路线、由 AI 手工转录**的 `noul` 行，其产物自带 `transcription_risk` 声明）。故本节的结论是**「在这 3+1 次观测中未见」**，不是「provider 从不返回」——**单次观测足以确立「这些键确实存在」，不足以确立「那些键从不出现」。**

⇒ **这是论文「自报字段不可信」这一主张的直接、线上证据**：这些字段**不是被评测方报告的**，而是**中间层合成的**。
⇒ 因此 Result B 的准确表述是**关于接入层**的，而不是关于任一引擎自身协议的 —— 与第 3.1.1 节的归属声明一致，且现在有了机制层面的证明。
⇒ **附带一项待验证旗标**：插件的 `latencyMs`（n=7，p50 **1,851 ms**）**高于**独立墙钟，但**比值不稳定，故报约 1.5–1.9 倍并列出两次产物**——**尺寸匹配**（126 字符 / 347 token 类，n=5）分母 p50 **956.2 → 1,244.8 ms**（`rerun\baseline\P27b-plugin-crossval.json` → **1.94**；`results\P27b-plugin-crossval.json` → **1.49**）；不匹配的当前 n=20 运行分母 p50 **1,191.8 → 952.9 ms**（→ **1.55 / 1.94**）。**⚠️ 第九轮更正**：此处原印单值 1.94 倍；**原因写在同一句里**——该比值的分母是一次**延迟测量**，而 Jev 的延迟**不复现**（同一脚本、同一状态、同一 n：p50 −20%、max +58%），**只有答案逐位相同**。**⚠️ 但形状可复现、移动的只是绝对水平**：p50 在 **127×** 的 state 跨度（126 → 15,999 字符）上基本持平——published **+12%**、re-run **−10%**（`rerun\baseline\P27c-jev-latency-sweep.json` / `results\P27c-jev-latency-sweep.json`），逐档水平移动 **+4.0% … +32.6%**；故「延迟不由状态大小主导」这一读法在两次产物中都成立。两组非同批采集，故记为旗标而非结论（§5.2）。

**同一陷阱在 LLM 一侧也出现（本项目第四次）**：LLM 的 `prob` 是**所答标签的置信度**。首版把它当 P(true)，**反号了所有 `false` 回答**，报出 `explicit_contra` 档 0.0 准确率——而模型**全部答对**。
→ **修正为 `P(true) = prob`（若答 true）或 `1 − prob`（若答 false）后，准确率 1.00**（n=1100）。

**为什么危险**：这是**规格级缺陷**，不是舍入误差——**它把结论符号翻转**，且在两个不同系统上**独立出现**。

**协议条款**：
8. **`probability` 语义必须逐系统实测确认，不得假定**；
9. **只记录朝向 true 的字段**（Jev 记 `noul`；LLM 记由 label 推导的 P(true)）；
10. **类型/键必须逐响应断言**——Jev 的未知 `type` 会被**静默转成 `score`**。

## 6.6 语义层（二）：`no_support` —— 把「没有陈述」读成支持

**设计**：1100 条二值项（5 难度 × 220），**真值由构造计算**（无人工标注、无模型标注），两个判定器**配对运行**。其中 `no_support` 一项的**唯一目的**就是检验 R12 写进协议的那条规则：

> 「某物只有在 STATE 真的说了它时才被支持。**没有陈述不构成对它的证据。**」

| 判定器 | `no_support` 准确率（n=220） | **平均声称 P(true)** | 真值 |
|---|---|---|---|
| **Laya** | **0.3091** | **0.5643** | 全部 FALSE |
| LLM | **1.0000** | 0.0012 | 全部 FALSE |

→ **面对「候选值根本没出现」的条目，Laya 平均给出 P(true) = 0.564，即倾向断言该值就是当前值。**
→ **它把「没有陈述」读成了对主张的支持。**

**另一处严重不对称**：`explicit_support` **0.991** vs `explicit_contra` **0.273**（各 n=220）。
→ 当 state **明确声明另一个值才是当前值**时，它反而**更容易**把候选值判为当前值——**它在找「候选值出现过」，而不是「它是当前值」**。
→ **这解释了本项目早期简单条目上 Laya 拿 1.00 的原因**：那正是它唯一擅长的形态。

**协议条款**：
13. **评测语料必须包含「候选值不出现」的条目**，否则会系统性高估判定器在核验类任务上的表现。

## 6.7 语义层（三）：跨语言区分能力塌缩

**前提更正**：本脚本原要测路由缺陷，但探针证明**HTTP sidecar 从不路由**——它对每种输入（含西里尔与天城文）都报告 `routing.reason = "explicit model selection"`，**不传 `--model` 启动时亦然**。故此项**不是**路由测量；它是**英文 checkpoint 面对非英文文本的行为**。

| 文字系统分组 | n | 准确率 | 真条目平均 P(true) | **假条目平均 P(true)** | 恒答真基线 |
|---|---|---|---|---|---|
| **英文原生** | 2 | **1.000** | 0.975 | **0.407**（正确否定）| 0.5 |
| 其他拉丁文字 | 12 | **0.500** | 0.917 | **0.747** | 0.5 |
| 非拉丁文字 | 2 | **0.500** | 0.968 | **0.4795** | 0.5 |

→ **英文上完美区分真假；一旦文本不是英文，就不再区分，而是倾向肯定主张**，且**假条目的 P(true) 高达 0.4795**。

**限制**：英文与俄语各仅 2 条，其他拉丁共 12 条 → **只有定性形态可报告**。
**并且**：论文**不得**对 DSH 插件所用的 Python `Router` 作任何陈述——**那是本项目从未触达的组件**。

## 6.8 本节小结

**七条现象，一条形态**：

| # | 失效位置 | 一句话 |
|---|---|---|
| 1 | 输入层（mock） | 没有判断能力，却能产出可信的结果表 |
| 2 | 字段层 | `truncated` 在两个方向上都是错的 |
| 3 | 字段层 | `fits: true` 与已截断的输入同时成立 |
| 4 | 字段层 | `probability` 是 P(所选选项)，反号**所有答 `false` 的条目**（实测占比 **60.0%**（LLM）/ **29.8%**（判定器），**不是「约一半」**），且与 `band` 方向相反 |
| 5 | 语义层 | `conflicted`/`undecided` 实际不可达；冲突被报成「证据不足」 |
| 6 | 语义层 | 「没有陈述」被读成支持（n=220） |
| 7 | 语义层 | 非英文文本下不区分真伪（n 小，定性） |

> **统一形态**：**该判定器在「必须注意到缺席或不匹配」的场合失效，而在「答案被明确陈述」的场合近乎完美；两种情形下自报置信度都不低。**

**这七条不依赖任何生成电池**，也不依赖长线任务——它们**全部落在接入层**（见第 3.1.1 节的归属声明与 §6.4.1）。因此本节是全论文中**最稳、最可复现**的一节。

## 6.9 局限

1. **第 7 条 n 极小**（2/12/2），只有定性形态；
2. **第 1 条是 mock provider 的行为**，不是 live Jev 的行为——它的价值在于**方法论警示**，不在于评价 Jev；
3. **第 2、3 条在 english/multilingual/typed-decisions 三种 loadout 下取得**，且**全部为三-checkpoint loadout**——窗口数值须连同启动配置报告（见 §4.8）；

## 7.3 实例一：`no_support` —— 把「没有陈述」读成支持（n=220）

| 判定器 | 准确率 | **平均声称 P(true)** | 真值 |
|---|---|---|---|
| **Laya** | **0.3091** | **0.5643** | 全部 FALSE |
| LLM | **1.0000** | 0.0012 | 全部 FALSE |

|---|---|---|

| `partial_support` | 0.6818 | 0.5881 |

| 实例 | 要「注意到」什么 | 未注意到的后果 | 自报字段怎么说 |

# §8 结果 D——跨物种互补性：一个负结果

> **写法原则**：负结果的价值在于**它否证了什么**，而不是「我们没找到」。故本节先陈述被否证的架构主张，再给出**三个区制**的配对证据，最后说明**它能外推到哪、不能外推到哪**。

---

## 8.0 被否证的主张

**主张**：在长线任务中，用一个**廉价的、不同物种的**判定器做第一层，只在它不确定时升级到前沿模型，可以以更低代价获得**同等或更好的**判断质量。

**该主张依赖的唯一前提**：**异种判定器与 LLM 会在不同的条目上出错**（互补性）。若两者错在同一处，第一层就只是「更差的第二层」。

**在既有工作中，第一层多为 LLM 判 LLM**（[FrugalGPT](https://arxiv.org/abs/2305.05176)、[RouteLLM](https://arxiv.org/abs/2406.18665)、[AutoMix](https://arxiv.org/abs/2310.12963)、[Cascaded LMs](https://arxiv.org/abs/2506.11887)）。**但非生成式判别器并非没有先例**——RouteLLM 自身即评述 Hybrid-LLM 的 **BERT-based router** 与 Zooter 的 **BERT-style router**；故 **「异种是否意味着互补」的问题不是「此前无人用过异种第一层」，而是「此前无人把它当作受控第一层与前沿生成器做配对互补性检验」。**

**本节的答案：在测过的三个区制上，均未发现互补。**

---

## 8.1 度量

在**同一条目**上让两个判定器各答一次，做**配对比较**：

```
Δ_catch = P(类型化判定器正确 | LLM 错误) − P(类型化判定器正确 | LLM 正确)
```

- **配对**设计使条目难度**在条目内相消**，因此 Δ_catch **不受准确率水平差异的混淆**——这是所有「A 比 B 准」类比较无法避免的问题；
- 同时报告**混淆矩阵**（两者皆对 / 仅类型化对 / 仅 LLM 对 / 皆错）与 **Cohen's κ**；
- **判据以 Δ_catch 的符号为准**，不以「仅类型化对」的计数是否非零为准（见 §8.4 的一处修正）。

---

## 8.2 区制一：权威定位（模板匹配类）

**条目**：`DECOY + filler + CORRECTION`，多处陈述中需找出被标记为权威的那一条；**所有选项在数值上都合理**（避免「用合理性排除」这条捷径）。48 个配对条目。

| 指标 | 值 |
|---|---|
| **LLM 准确率** | **1.0000（48/48）** |
| **Laya 准确率** | **0.4583** |
| 仅 LLM 对 | **26** |
| **仅 Laya 对** | **0** |
| 两者皆对 | 22 |
| κ | **0.0** |

→ **LLM 一次都没错**，因此 `P(Laya 对 | LLM 错)` 与 **Δ_catch 均无定义**。
→ 能说的只有：**在这个区制上 Laya 未捕获任何 LLM 漏掉的条目（仅 Laya 对 0 / 仅 LLM 对 26）**，而是在 26 个条目上单独失败。

| 指标 | 值（P14 散文臂，n=48） |
|---|---|
| **LLM 准确率** | **0.9583（46/48）** |
| 判定器准确率（同一批判定器读数） | **0.4583** |
| 两者皆对 / 仅 LLM 对 / **仅判定器对** / 皆错 | 21 / 25 / **1** / 1 |

→ **这是区制一唯一可测量的 Δ_catch，而它的符号是正的。** 本节此前只报了强制选择臂，因而把整个区制写成「不可测量」——**该判断对强制选择臂成立，对散文臂不成立。**
→ **分母必须与点估计同时给出，否则 +0.0435 会被读成它不支持的强度**：散文臂上 LLM 只错 **2** 条，故 `P(判定器对 | LLM 错)` 是 **1/2**；两个 95% 区间都很宽且都包含 0，Fisher p = 1.0000。**它不是已确立的互补性；但它也不是 0**——把 +0.0435 读成「无互补」与把它读成「有互补」同样没有依据。
→ **两条臂是同一批 48 条电池的两种作答格式**（该产物的 `_provenance.consumes` 即 `P9b`；判定器在两条臂上同为 0.4583），**不是两份独立证据**；能力画像里它们各自只占一行并须注明配对关系（§6.1）。
→ 上表全部数字由 `src\analysis\p28_recompute_all_stats.py` 重算并写入 `results\P28-recomputed-statistics.json` 的 `regime1` 块；该块同时记录**强制选择臂的 Δ_catch 因 `n_wrong_arm = 0` 而未定义**（不得印成 0）。
→ **⚠️ 该产物的 `_provenance.published_figures_at_risk` 本就列着「prose arm 0.958」**——这一臂自记录起就在「若被改动则论文数字有风险」的清单上，此前却从未在正文出现。

## 8.5 结论与外推边界

**结论**：
> 在测过的**三个**任务区制上，**异种判定器不提供增量覆盖**。其中一个区制上 LLM 严格占优（强制选择臂：仅 LLM 对 26 / 仅判定器对 0；**⚠️ 同一 48 条电池的散文臂是 25 / 1，Δ_catch = +0.0435——该区制唯一的可测 Δ_catch 为正，见 §8.2**）；另一个上 LLM 触顶使其错误结构**无法测量**；第三个区制上限被打破，**真值修复后重判**，Δ_catch 一致为负（3/3；未配对 Wald 下 2 次排除零，**⚠️ 但该区间收窄的原因与区制二不同：本区制的格子是 17/29/3/19，没有零格**——零格是**区制二**的情形，早期版本把那条解释误植于此。改用 Newcombe 后**仅 1 次稳健排除、1 次在边界**），且失败相关**在 3/3 次抽样中为正**——即证据**与「共享失效」一致**，而非互补。**⚠️ 但这句话在第九轮被加了一条限定（见 §8.6.1 的重测披露）**：把「忽略作废」的值放进选项后，Δ_catch 由 **−0.233…−0.182** 变为 **−0.056…−0.066**、φ 由 +0.19…+0.26 降到 +0.06…+0.11——**方向不变，幅度是选项构造的函数**；「与共享失效一致」的读法在重测下失去原本就微弱的支持。
> **⚠️ 强度限定**：该相关的 Fisher 精确 p = **0.086 / 0.049 / 0.163**（r1/r2/r3）。**未校正时仅 1/3 次在 α=0.05 下显著（r2，p=0.0487，距阈值仅 0.0013）；而按本文自己的 Holm 规则（§4）三次全部不存活**（首个阈值 0.0167）。「条件正确率 vs 边际」的单侧检验其 95% CI 在 **3/3** 次中包含 0。
> **MDE（0.28–0.30）仍大于预声明门（+0.10），故这是「方向 3/3 次一致、Wald 下 2 次排除零（Newcombe 下 1 次稳健、1 次在边界）」，不是精确的效应量。**
> **「廉价异种判定器做第一层」这一架构，在本项目测过的任务上得不到支持。**

**能外推到哪**：

| 可以 | 不可以 |
|---|---|
| 「异种 ≠ 自动互补」——**架构选择需要一个正面的互补性证据，不能靠物种差异假定** | **不能**说「任何情况下都无互补」 |
| 在**单文本、有明确标签、可单跳判定**的任务上，LLM 的准确性优势足以淹没异种第一层的任何收益 | **不能**外推到开放式任务、需多跳检索的任务、或标签空间极大且需外部知识的任务 |
| 在**任一判定器触顶**的电池上，互补性**不可测**（而非「不存在」） | **不能**把「不可测」当作「不存在」 |

**必须写入局限的**：本项目测了**三个区制**，其中**前两个都让 LLM 触顶或接近触顶**（因而**不可测量**），第三个上限已破除但**效力不足**（MDE = 0.311 远大于预声明阈值 +0.10）。**因此这是一个关于「如何判定架构主张」的方法论结果，不是一个关于「异种判定器无用」的普适结论。**

## 8.6 区制三：多跳链式核验（**上限已排除；真值修复后 Δ_catch 一致为负，失败相关同向**）

**预声明判读的裁决**（判读写于运行前）：
> 「若上限破除但 Δ_catch 不 > +0.10 → 即使在 LLM 失败处，类型化判定器也不覆盖其错误。」

**实测：修复前电池 Δ_catch = −0.007（n=69），修复版三次抽样 Δ_catch = −0.233 / −0.247 / −0.182（n=68）→ 三次全部未达阈值，且方向与阈值相反。**

**⚠️ 但这个检验的效力必须同时报告**：
- Δ_catch 的 SE = **0.1111** ⇒ 95% CI = **[−0.225, +0.211]**；**MDE（80% power）= 2.80 × 0.1111 = 0.311**。
- **预声明阈值 +0.10 远低于 MDE 0.311** ⇒ 在 n=69 下，**该检验几乎不可能检出它自己设定的支持阈值**。
- 逐 K 拆分（论文此前只报池化值，此处补齐）：

| K | n | `P(Laya 对 \| LLM 错)` | `P(Laya 对 \| LLM 对)` | Δ_catch |
|---|---|---|---|---|
| 2 | 12 | 0.500 | 0.400 | **+0.100** |
| 4 | 12 | —（LLM 12/12） | — | 无定义 |
| 8 | 21 | 0.333 | 0.222 | **+0.111** |
| 16 | 24 | 0.214 | 0.300 | **−0.086** |

→ K=8 的 +0.111 **单点越过**了代码中的 +0.10 门，但 K=2 为 +0.100、K=16 为 −0.086，**无一致趋势**；且预声明（`protocol\HARDER-BATTERY-DESIGN.md`）只预声明了**区制层**的判读，**未**预声明逐 K 的门，故这属于**事后子组**，需多重比较校正后方可解读。**它不构成互补性证据。**
- **oracle 并集对照（修复前电池）**：49/69 = 0.7101 vs LLM 0.5942（+0.1159）；仅 Laya 对 8/69，Wilson95 **[0.060, 0.212]**。**并集增益必须与独立性的期望比较**：若判定器与生成器独立且准确率 0.2899，则在生成器的 28 个失败中期望命中 **8.1** 条，**实测 8 条** ⇒ **该增益正是独立性的预期值，不是互补性**。修复后 φ 为正，但**按 K 分层后并不显著**（详见 §8.6.1）——该论证**仍停留在「独立」**，未被升级为「共享失效」。
- **独立性检验（修复前电池）**：2×2 的 χ²(1) = 0.0039，Fisher 精确双侧 **p = 1.0000** ⇒ 记录轮的 Δ_catch = −0.007 与「两判定器独立」完全相容。**修复后同一检验给出 p = 0.086 / 0.049 / 0.163**——不再相容于独立。

→ **裁定（按修复版重写）**：**架构主张不予支持，且证据强度高于修复前。** 上限效应不能再用作辩解——**上限已破除，LLM 确实在失败（约 33%），而廉价判定器不仅未覆盖其错误，其失败还与生成器的失败同向（3/3 次 φ > 0；但 Fisher p 仅 1/3 次 < 0.05，见上）。**
→ 修复前的记录轮（69 条、Δ_catch = −0.007）作为一次**已披露缺陷的测量**保留，其真值缺陷已在上文说明。

### 8.6.2 附带结果：两种根本不同的失效模式

**⚠️ 形状必须更正（第五轮）：不是「随深度单调崩塌」，而是「在 K=4→8 之间跌落一次，此后完全平坦」。**
逐 K 复算（三次固定抽样合并，LLM 判定数 / 该 K 的总判定数）：

| K | LLM 准确率（3 次合并） | Laya | 相邻对比的 Fisher 精确 p |
|---|---|---|---|
| 2 | 33/36 = **0.917** | 0.417 | — |
| 4 | 36/36 = **1.000** | 0.250 | K=2 vs K=4：**p = 0.239**（不显著，且方向是**上升**） |
| 8 | 32/63 = **0.508** | 0.286 | K=4 vs K=8：**p = 3.6×10⁻⁸** |
| 16 | 35/69 = **0.507** | 0.261 | K=8 vs K=16：**p = 1.000**（**完全平坦**） |

⇒ 浅层（K∈{2,4}）与深层（K∈{8,16}）的合并对比：**23/24 = 0.958 vs 45/88 = 0.511，Fisher p = 1.4×10⁻⁴（3/3 次抽样均在 10⁻⁴ 量级）**。
⇒ 故**「崩塌」只发生在一次跨越上**：K≤4 时接近上限，K≥8 时降到约一半并**不再随深度变差**。
⇒ **原文「随深度崩塌」「K=2 → K=16，0.917 → 0.478」只描述了 r1 这一条抽样**；r2/r3 在 K=8→K=16 上是**上升**的（0.476 → 0.522），三次抽样**没有一次**是单调的（K=2→K=4 在 **3/3** 次中都是上升）。
⇒ **机制尚未确定**：深层错误**不是**「算错一步并累积」——若是复合误差，K=16 应显著差于 K=8，而实测差为零。**逐条看，LLM 在 K≥8 的错误几乎全部落在真值邻域的近似诱饵上**（而非「恰好等于忽略作废后的值」，后者在 K≥8 只占 16.7% / 其错误的 29–32%，见 §8.6）。更可能的解释是**在某个深度上从「执行」切换到「在近邻候选中择一」**；本电池**没有**区分这两种机制的设计，故此处只记现象，不作机制断言。

| | LLM | Laya |
|---|---|---|
| K=2 → K=16（修复前电池） | 0.833 → **0.417** | 0.417 → 0.250 |
| K=2 → K=16（修复版三次） | 0.917 → **0.507**（K=4 时 1.000） | 0.417 → 0.261 |
| **形状** | **一次跌落（K=4→8）后平坦** | **平坦，恒在随机附近** |

→ **Laya 在 K=2（本电池最简单形态）时就只有 0.417，且随深度不再变化** → **它不是「随深度退化」，而是根本没有在执行链式计算。**
→ 这与 §6.3 一致：它**在「需要注意到某物缺席」的任务上塌缩**，而本电池**每一行都要求它注意 `SUPERSEDED` 标记**。

| 判定器 | 失效方式 | 是否随负载恶化 |
|---|---|---|
| **LLM** | **一次跌落**：K=4→K=8 之间下降，此后平坦（**非误差复合**——K=8 与 K=16 的 p = 1.000，机制未定，见 §8.6.2） | ⚠️ **否** |
| **Laya** | **能力缺位**：恒定在随机附近 | ❌ 否 |

→ **对「长线任务」的含义**：**用恒定失效的组件去兜底累积失效的组件，在原理上不可能奏效** —— 这正是 Δ_catch 为负的结构性背景（**⚠️ 第八轮更正：原印「Δ_catch ≈ 0」是修复前的 −0.007；修复版三次为 −0.182…−0.247**）。

## 8.7 截断的证据（P24 + P26）

§5.3.1–5.3.2 报告了累积运行中的窗口侵蚀与截断伤害。此处只记其对**本节主张**的意义。

**可作为证据的部分是「截断会发生」**：P24 显示 60 步里只有 14 步能塞进窗口、末态 3.4× 钳位；P26 的 20 次调用全部录得 `in_pad = 512`、`truncated = true`。

**⚠️ 但 P26 原设计不足以证明「截断改变了答案」**（详见 §5.3.2），有两处缺陷：
(a) **两臂的可见前缀逐位相同**——dropped 臂仍有 ~4× 钳位，更正位于第 1,943–1,952 个 token，**超出两者共同的 512 窗口**，故「两臂同答」是**构造的必然**；**【不可核验 ⚠️ ERRATA §10.2】**：该 token 位置**没有产物**——`P25`/`P26` 的产物记录的是 `in_pad`、`truncated`、选项与判定，**不含更正所在 token 的绝对位置**；1,943–1,952 出自审计期间的一次性核验。**该论证的方向有产物支撑**（两臂的共同窗口为 512、真值恒在末位），但**这一具体位置不可核验**；
(b) 选项顺序与答案共线（诱饵恒首位、真值恒末位），而 Laya 10/10 选首位。
**复核时补做了缺失的对照**：**⚠️ 该定量断言已撤回（第七轮）**：那组数字（6/10、4/10、p = 0.011、状态 79–92 token）**在整棵树中没有任何产物**，且其状态规模恰等于 P26 **已废弃首版原型**的规模。**撤回**；本节只保留「截断会发生」这一有产物支撑的部分。

→ 因此本节的「统一形态」有**两个有产物支撑的实例，第三个的支持不足**：截断那一格**只能证到「截断会发生」**——早期版本印的「解释其中约 6/10、另 4/10 发生在证据完全可见时」**所依据的对照臂无产物，已撤回（第八轮）**。

| 任务 | 需要「注意到」什么 | Laya | LLM |
|---|---|---|---|
| 链式核验（K=2…16） | 某行被标记作废 | **0.25–0.42（恒定）** | **0.917 → 1.000 → 0.508 → 0.507**（修复版三次合并；K≥8 后平坦，**非单调**）|
| `no_support` 档（n=220） | 候选值**根本没出现过** | **acc 0.3091，平均 P(true)=0.5643** | ~1.00 |
| 超窗状态（对照臂，n=10） | 更正**完全可见**却未被采纳 | **⚠️ 该对照无产物，数字已撤回** | — |

→ **前两者都不是「算力不足」，而是「缺少检测缺席的通道」。**
→ **第三者性质不同，必须分开说**：（该拆分已撤回：所依据的对照臂无产物），属「看见却不采纳」，**不是**检测缺席。故「缺少检测缺席的通道」**不能**涵盖它。

## 8.9 限制

1. **区制一的上限效应只出现在强制选择臂**（LLM 48/48）；**散文臂上 LLM 46/48、仅判定器对 1 条，Δ_catch = +0.0435（Newcombe 95% CI [−0.386, +0.471]），点估计为正但只基于 2 条 LLM 错项** ⇒ 该臂同样**不能证明无互补**，而它**能**给出一个（不精确的）**正向**点估计；本节其余结论建立在**强制选择臂**的「仅判定器对 0」之上，该读数不受此更正影响；
2. **区制二 n=40**，一项动 0.025；**Δ_catch 的幅度在 4 次抽样间从 −0.029 变到 −0.257** ⇒ 能说的是**「4/4 次方向为负、记录轮是最有利的一次」**，不能说「效应量是 −0.033」；
3. **污染**：Banking77 是 Laya 的**先前集合**，而 **LLM 侧的暴露更直接**——`D3` 自己记录该模型在 45T token 上训练且含 Common Crawl，并写明「the LLM may have memorised the labels」。
   **⚠️ 因此「污染是保守的」这一论证只覆盖一侧，必须更正**：Banking77 的测试语句与 77 个标签名都是公开纯文本，LLM 的 0.75 若无记忆很难达到；而 **Δ_catch 为负正是由「仅 LLM 对 23 条」撑出来的**——**LLM 侧污染与本文的负结论同向，不是保守方向**。
   ⇒ 本区制的负结果因此**更强**（污染若抬高 LLM，只会让互补性更难看），但**「异种无用」的普适外推不能建立在这个区制上**。真正干净的区制是**区制三**（真值由程序模拟生成，不来自任何公开语料）。
4. **Laya 的层级用程序化分组**（按标签名 token 相似度凝聚），**顶层分组质量本身是瓶颈**（组选择 0.275）。**换一个语义更好的分组可能改善端到端**，本轮未测 —— 这是本节最重要的未排除解释；
5. **LLM 只测了一个配置**（`deepseek-flash`、非思考、单次采样）；
6. **区制三的效应幅度对「选项如何构造」敏感**（重测披露，§8.6.1）：Δ_catch 在两种选项策略下为 **−0.18…−0.25** 与 **−0.06…−0.10**。**能跨电池成立的只有符号（3/3 次为负）与「上限已破除」，效应量不得跨电池引用。**

# §9 讨论：如果要用这类判定器，该怎么做

本节只给**有实测支撑**的建议，每条注明依据与代价。不写没有证据的工程意见。

## 9.1 把输入校验放在 harness，不要放在判定器

**依据**：Laya 对**空 state 与纯噪声 state** 返回 `ok: true`、**无 error、无 warning、`fits: true`**（R13）。对空输入它仍给出 `choice: "technical"`。
**依据二**：`no_support` 档（n=220）——**候选值根本不出现时，它平均给出 P(true)=0.564**。
**做法**：在调用前拒绝空/低信息量 state，并**显式检查「证据是否真的存在」**，而不是让判定器回答一个它没有检测通道的问题。
**代价**：需要 harness 侧的实现，且需为每类任务定义「存在」的判定。

## 9.2 绝不用自报字段做门控，一律自算

**依据**：`truncated` **双向皆错**（english 滞后 111 字符；multilingual 提前 **4,773** 字符误报；typed-decisions 提前 **3,774**）（§8.2）。三个 checkpoint 的标志都在**同一点 3,193 字符**触发，而其真实钳位差 **2 倍**。
**依据二**：`fits: true` 与**已截断的输入**可以同时成立（§8.3）。
**做法**：
- **用 checkpoint 自己的 tokenizer 计数**，与 `512 − head_tokens − 1` 比较；
- 把 `truncated`/`fits` 只作**描述性报告**，并**同时报告「标志误差」**这一指标；
- **把决定性证据前置**——Laya 丢的是**尾部**。

## 9.3 不要跨系统、跨 framing 比较置信度

**依据**：
- Jev 的 `probability` 是 **P(所选选项)**，不是 P(true)——把 `probability` 记作 P(true) 会**反号所有答 `false` 的条目**（实测占 **29.8%**（328/1100）；同一语料上 LLM 为 **60.0%**（660/1100）——**均非「约一半」**，来源 `P19-calibration.json`，见 §8.4）；且**同一响应里 `band` 朝向 true 而 `probability` 朝向所选**（§8.4）；
- LLM 的 `prob` 是**所答标签的置信度**，同一陷阱（本项目在两侧各踩一次）；
- Laya 的 `confidence` 是**集中度统计量**，同一 p 在不同 framing 下为 **0.5399 vs 0.0046**（差 117×）。
**做法**：**只记录朝向 true 的量**（Jev 记 `noul`；LLM 记由 label 推导的 P(true)）；**报告完整分布**而非赢家。

## 9.4 按「会不会注意到缺席」而不是「准不准」来选任务

**依据**（§8 的统一形态）：
| 任务形态 | Laya 实测 |
|---|---|
| 答案被明确陈述 | **0.9909**（n=220）|
| 需要找权威来源 | 0.4583（n=48）|
| 证据不存在 | **0.3091**（n=220）|
| 需语义解释（77 类） | 0.0333（n=30）|
**做法**：**把「证据存在性」当作一等检查项**；在这些判定器上不要部署「证据缺失也应给出判断」的流程。

## 9.5 若需要大 state，重新考虑 loadout

**依据**（P18，每个 loadout 一次启动；**未做重复启动，故不声称确定性**）：
| 载入 checkpoint 数 | 可用窗口 |
|---|---|
| **1** | **1024 token** |
| **≥2** | **512 token** |
**做法**：**只载入一个 checkpoint 可把可用窗口翻倍**，代价是失去多语与特化 checkpoint。
→ **并且必须把窗口连同启动配置一起记录**——「窗口 = 512」对另一个操作者可能错 2 倍。

## 9.6 混合架构：不要假定互补，先测

**依据**（§8）：**三个**区制上，异种判定器均未提供**已确立的**增量覆盖——
- 区制一（权威定位，n=48）：**强制选择臂**上它**未捕获任何** LLM 漏掉的条目（仅判定器对 **0**，对比仅 LLM 对 **26**）；**⚠️ 但同一 48 条电池的散文臂上 LLM 错 2 条、判定器捕获其中 1 条，Δ_catch = +0.0435（区间跨 0）**——故本节的措辞只能是「未确立增量覆盖」，不能是「无增量覆盖」（§8.2）；
- 区制二（77 类意图分类，n=40，**LLM 臂 4 次抽样**）：仅判定器对 **0–2** 条，而仅 LLM 对 **23–27** 条，**Δ_catch 在 4/4 次抽样中为负**（−0.033 / −0.250 / −0.029 / −0.257）；判定器准确率 4 次逐位相同（0.225）；
- 区制三（多跳链式核验，**真值修复后重判**，n=68，**3 次抽样**）：LLM **0.662–0.677**、判定器 **0.294**，**Δ_catch = −0.182 至 −0.247**，**未配对 Wald 下 3 次中 2 次排除零，但该区间因零格而虚假收窄；改用 Newcombe 后仅 1 次稳健排除、1 次在边界**，**失败相关 φ = +0.19…+0.26**；`P(判定器对 \| LLM 错)` = 0.13–0.17，**低于**其边际 0.294 ⇒ **与共享失效一致**（但 Fisher p = 0.049/0.086/0.163，仅 1/3 次显著）；
  **⚠️ 但 MDE = 0.28–0.30，仍大于预声明 +0.10 门 ⇒ 点估计一致为负，精度仍有限。**
**做法**：
- **在选择「廉价第一层 + 升级」之前，先做配对互补性测量**；
- 判据用 **Δ_catch 的符号**，不要用「仅第一层对」的计数；
- 若第一层**不提供增量覆盖**，它就是**更差的第二层**，应当直接去掉——**延迟优势不足以补偿**（§8.3.1：层级对 Laya 是**净收益**，但端到端仅 **0.200**，远低于 LLM 扁平的 0.750–0.900）。

## 9.7 关于「长线」的一句诚实的话

**本项目的长线证据是「缩减版」，不是完整自主运行。** horizon 斜率按 D2 的裁定**降级为描述性**，且**未执行**。
P24 提供了**同一进程内 3×20 步的累积测量**（窗口侵蚀 23%、最终状态 3.4× 钳位）；P26 证明了**截断会发生**（20 次调用全部 `in_pad=512`、`truncated=true`），但**因选项顺序与答案完全共线，未能证明它改变了答案**（§5.3.2）。
但**没有工具使用、没有跨进程恢复、判定器被当作判断器调用而非自主智能体**。
→ 本节建议**建立在单步判断与缩减版累积之上**，**不得升级为「自主长线运行」的结论**。⬜

1. **单一 LLM 配置**：`deepseek-flash`、非思考模式。**未测** `deepseek-v4-pro`、自洽采样臂、思考模式下的质量差异（因语料触顶，**P21 四档准确率全为 1.00，无法回答「思考是否买来质量」**）。

## 10.3 关于「没有判断能力的组件产生可信结果表」的适用范围

该结论建立在 **Jev 的 mock provider** 上，即一个**刻意设计的合成后端**。
→ **它的价值是方法论警示，不是对 Jev 的评价。** 论文必须避免让读者把它理解为「Jev 不可靠」。
→ 但它**可外推到任何返回概率的判定组件**：mock 与真实判定器在**结果表的形状**上没有可区分的差异——这正是危险所在。

## 10.4 不可外推的清单

| 不能说 | 因为 |
|---|---|
| 「Jev/Laya 普遍不如 LLM」 | 只测了**三个**区制：前两个让 LLM 触顶（**不可测**），第三个上限被打破、**真值修复后重判**（n=68），Δ_catch 在 3/3 次抽样中为负但**精度有限**（MDE = 0.28–0.30） |
